# 룰 모듈: 에이전트 운영 (#45-B·#45-C·#45-D 전문)

> 커널(CLAUDE.md)의 강제 포인터로 로드. 서브에이전트·Workflow fan-out·검증 파이프라인 작업 전 필독.

#45-B 에이전트-기본·결정적-코어 분기:
- 탐색·조사·분류·채점·합성·계획 등 **'판단'은 에이전트**(필요 시 병렬 포그라운드 서브에이전트)를 기본으로 한다.
- sha256·apkg(genanki)·정규식 배치·JSON 상태 갱신·파일이동 무결성(#16-C) 등 **'결정적·무결성·고빈도'는 코드**로 한다.
- 패턴: **에이전트가 결정 → 코드가 실행·로그 → 에이전트가 검수.**
- **내용·의도·안전이 걸린 판단(분류·동일성·이동안전)은 메타데이터(날짜·크기·해시)만으로 끝내지 말고 실제 내용을 읽는다(별도 NL 처리).** 단순 집계·해시·치환만 코드 단독.
- 코드 제거가 아니라 '결정적 커널'로 최소화.

#45-C 병렬 기본·산출 검증 (운영 정본은 dispatch 스킬):
- 병렬 강제(기본값, 순차는 예외; **fan-out은 메인 오케스트레이터 1단에 한함 — 서브에이전트의 2단 하위 스폰은 #52-A 금지**): 서로 의존 없는 독립 단위가 **2개 이상이면 포그라운드 병렬 서브에이전트 fan-out을 기본 강제**한다(읽기·탐색·조사·분류·채점·다중후보 비교·위키화·쟁점추출 등). **순차는 "뒤 작업이 앞 작업의 산출을 입력으로 받는 실제 데이터 의존이 있을 때만"** 허용. 백그라운드 장시간 에이전트는 쓰지 않는다(중단·소실 위험). 병렬 여부 판정은 LLM이 의존그래프를 의미판단. 단, #21 소크라틱·"종료"(#26)·"수동"(#27)·한 줄 수정·자명 작업은 단일 에이전트.
- 검증 패스(산출 직후): 법리·판례·조문·사건번호·선고일 단정이 든 산출물은 생성 직후 별도 검증 패스(Workflow verify 스테이지 또는 적대검증 서브에이전트)로 #1 소스근거·#6 정확성(`python .agent/lib/law_api.py verify-text <산출물>` 자동 대조)·#13 생성후검증·#34 판례문구 원문성·#16-C 로그누락을 대조한다. 미확인 단정은 #2로 삭제·보류. 단순 집계·해시·치환·대화성 산출엔 미가동(#8).
- 위키·쟁점 산출 전용 검토 게이트(상시): 위키화·쟁점추출 산출물 생성·갱신 즉시 검토 서브에이전트 1회 가동, 3축 대조 — 1축이라도 미달이면 '보류' 표시 + 보고·중단 권고만(자동수정·이동·삭제 금지). (a)**목차 대비 누락 0**: 정본 목차(`_{과목}_목차.md`, #50) 전 항목 1:1 대응 — 결손·고아·번호건너뜀을 LLM 의미대조(정규식 일치만으로 통과 금지). (b)**소스 인용**: 법리·판례·조문·사건번호 단정이 원본 OCR·교재에 실재하는지 `law_api.py verify-text` + 소스 대조(#1·#13). (c)**백링크 무결**: `[[…]]` 대상 실재(고아·결손 탐지). 결과는 staffing_log·consistency_log 합산. 단순 집계·대화성 산출 미가동(#8).
- 재개가능 검증 fan-out(**대형 작업 일체 상시**): 다수 산출물·항목을 병렬 에이전트로 **생성·재작성·감사·이주·대량검토**하는 대형 작업은 **항상** ①**완료마커** — 각 항목 처리·검증 후 마커(생성물=frontmatter `상태: 검증완료`, 감사·분석=항목별 결과를 파일에 기록) ②**처리 직후 검증** — 소스와 대조해 요약·잘림·누락·오류 없는지 확인, 통과만 마커 ③**재개 시 마커 skip** — '파일 존재'만으로 완료 간주 금지(**exists ≠ 완료**; 미마커는 재처리) ④**결과는 파일/마커에 기록(반환값만 의존 금지)** — 중단 시 반환 전 결과 소실하므로 항목 끝날 때마다 파일로 떨군다 ⑤**현황 로그** — 진행·완료를 파일·마커에서 재계산하는 스크립트. 한도·중단돼도 누적돼 재실행이 이어간다. 사소·단발 작업엔 미적용(#8).
- 검증자 권한: (1)소스 미확인 단정 (2)#16·#16-B 위반 시도 (3)#16-C 로그 누락 (4)동시쓰기 충돌(#45) 탐지 시 해당 산출을 보류하고 사용자에게 보고·중단 권고만 한다. 사용자 승인 없이 자동 수정·이동·삭제 금지. (TaskStop은 백그라운드 task만 종료.)
- 동시쓰기 격리: 같은 파일 병렬 수정 금지. 쓰기 fan-out은 별도 파일명(_v2·_claude·_정리, #45)으로 격리 후 메인이 1회 병합, 공유파일(_index.md·master 3종·apkg)은 직렬 강제. worktree 격리는 git 추적 파일 한정 — 작업 본체 sync/·outputs/·교재는 git 밖이므로 별도 파일명이 1차 안전장치. Edit 전 항상 Read(#45).
- opt-in 경계: 본 룰은 '읽기·탐색·생성·검증' 비파괴 파이프라인에 한해 Workflow 상시 opt-in 근거다. 파일 이동·삭제·_trash 이동·OCR apply·git push·PR·외부 전송은 자동승인되지 않으며 글로벌 §5·#16·#16-B·#16-C·dispatch 확인 절차를 따른다.
- 과잉 방지: 사소·단발·대화성 작업(한 줄 수정·단순 질의·오타·포맷·결과 자명)엔 다중 서브에이전트·검증 패스를 띄우지 않고 단일 에이전트로 처리한다. 다중 에이전트·검증은 (1)독립 병렬화 이득이 분명하거나 (2)#1·#6·#13 검증 리스크가 있을 때만 가동. #21·#26·#27 시 자동 fan-out·검증 중단.
- 채용 자동게이트: fan-out 규모는 매 턴 산식으로 자동결정. 점수=[독립단위 U≥2:+2 / 조사·감사·이주·다중검토·다후보비교:+2 / 검증리스크(법리·판례·조문·사건번호 단정):+1 / 사소·단발·자명·대화성·한줄수정:−3]. 티어: **≤0 단일** · **1~3 병렬 서브에이전트·Workflow(①)** · **≥4 且 팀원통신·대형 독립컨텍스트 필요→에이전트팀(②, 드묾)**. 토큰모드 기본 OFF → 사용자 "토큰 고려/아껴/떨어졌어" 시 ON(점수 −2·한 티어 강등·경계검증 생략). 비파괴 fan-out 한정 — #21·#26·#27·#16/#16-B/#16-C 항상 우선. — **헤르메스 자기조정**: fan-out 결정이 있는 모든 비파괴 턴(단일 판정 포함)을 `.agent/state/staffing_log.jsonl`에 1행 기록(ts·유형·U·점수·티어·토큰모드·효과 y/n/?·메모). 효과는 직후 검증 통과/재작업으로 사후 채점. 동일 유형 효과=n 누적 시 가중치 ±1 자기보정(자동 영구개정 금지 — 임계 변경은 주간리뷰 사용자 승인). 더미가드: (a)결정행 0이면 '미학습'(기본 산식만) (b)효과=? 행 보정 제외 (c)(유형+점수) 진동 2회=정지조건 합류.
- 안전레일 상속: 모든 서브에이전트·검증자도 #16·#16-B·#16-C·#15·#1·#6·#13·#29~#31을 동일 준수한다. 서브에이전트라는 이유로 안전레일이 완화되지 않는다.

#45-D 동시 실행 상한 · 대량 fan-out 금지 (#45-C 병렬 '규모' 제한):
- **대량 fan-out 금지(기본)**: 항목이 많아도 수십 배치를 한꺼번에 뿌려 동시 실행 상한(~16)을 포화시키지 않는다. 그 16개가 세션 토큰을 동시에 급소진해 대부분 한도로 죽고 절반이 헛돌며 `fork: Resource temporarily unavailable`까지 유발한다(2026-06~07 사례집 커버리지 반복 실패의 실측 원인).
- **소수·내부순차 기본**: 대량 배치 작업은 **영역(과목/폴더/책)별 소수 Agent(≤4~6개)**로 나누고, 각 Agent가 자기 몫을 **내부에서 순차** 처리한다(항목→마커→다음). 영역별 1 Agent 전담은 공유파일 동시쓰기 충돌도 예방한다(과목별 카드파일=그 과목 Agent만 씀).
- **규모는 병렬 이득이 아니라 '예산'으로 제한**: Workflow 대량 병렬은 **세션 예산이 넉넉히 확보된 경우(리셋 직후·한도 여유 확인)에만** 허용. 반복 한도 상황에선 금지하고 소수 Agent(순차)로 전환한다.
- #45-C '병렬 강제'는 유지하되 **규모는 bounded(소수)** — "병렬"≠"대량 동시". 재개는 항상 마커 기반(exists≠완료).
