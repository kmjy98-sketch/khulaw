## 3. 머메이드(mermaid) 제작 규칙 — PDF-safe (강제)

1. **방향 TB(세로) 고정. `flowchart LR` 금지.** 가로형은 A4 세로 PDF 변환 시 축소·글자 깨짐(실측 문제). 부득이 가로 배치가 필요하면 열 ≤2(subgraph `direction TB`로 내부 세로 적층).
2. **엣지 라벨 ≤15자/줄, 최대 2줄**(`<br/>`). 긴 설명(법조 해설·괄호 부연)은 라벨에 넣지 말고 도식 아래 각주·본문으로.
3. **노드 라벨 ≤2줄, 줄당 ≤12자.** 줄바꿈은 `\n`이 아니라 **`<br/>`**(변환기 호환).
4. **한 다이어그램 노드 ≤10, subgraph ≤3.** 초과 시 개요도+상세도로 분할.
5. **주체 컬러 = §2 표 필수 적용**(`style N fill:#...,stroke:#...`). 임의 색 금지. 피심인은 stroke-width:3px.
6. **특수문자**: 이모지 금지, 라벨 내 괄호·콜론은 라벨 전체를 따옴표로 감싸기, 따옴표 중첩 금지. `—`(전각대시)는 `<br/>`나 `·`로 대체 권장.
7. **역방향·순환 엣지 금지(TB 랭크 역전)**: `하위노드 --> 상위노드` 방향의 순환 고리(예: 재원 환류)는 mermaid TB의 랭크 계산을 뒤집어 **전체 배치가 역전**된다(2026-07-03 실측: 배제 대상이 최상단으로 올라감). 순환·피드백 관계는 도식에서 빼고 **각주로 서술**하거나 별도 소도식으로.
8. **인접 엣지 라벨 겹침 주의**: 같은 노드에서 나가는 엣지 2개 이상이면 라벨이 나란히 붙어 한 줄처럼 겹쳐 보일 수 있다(실측). 라벨을 최대한 짧게(번호+핵심어) 하고 렌더로 겹침 확인.
9. **subgraph `direction TB`는 외부 엣지가 있으면 무시**됨(mermaid 사양) — 내부 노드가 가로로 펴진다. 내부 노드 ≤4까지는 허용(A4 수용), 초과 시 subgraph 분할.
10. **생성 후 확인 의무(검증 게이트)** — 확인 전 완료 보고 금지:
   - (a) 문법 자가검증: 노드ID 중복·괄호/따옴표 짝·`<br/>` 닫힘·화살표 문법(`-->`, `-.->`, `==>`, `<-->`)을 코드블록 재독으로 점검.
   - (b) 렌더 검증(로컬): `npx --yes @mermaid-js/mermaid-cli -i x.mmd -o x.png -w 900 -b white` (11.16.0 npx 가용 확인, 2026-07-03) → **PNG를 Read로 눈 검증**(배치 역전·라벨 겹침·컬러). 첫 실행이 일시 오류나면 1회 재시도. npx 불가 시에만 사용자에게 옵시디언 미리보기/mermaid.live 확인 요청.
   - (c) PDF 대상이면 세로폭 시뮬레이션: 최상위 나란한 요소(subgraph 포함)가 2열 이하인지 확인.
   - (d) 도식 아래에 규칙 준수 표기 1줄(`> 도식 규칙: TB 고정 · DESIGN_Fact_PPT 팔레트 · 렌더 검증일`).

## 4. 작업 플로우

1. 도식 요청 감지 → 본 SKILL 로드 → 대상 확인(마크다운 내 mermaid? SVG 위젯? PPT?).

5. 기존 도식 수정 시: LR 발견 → TB 전환 제안(PDF 변환 예정이면 강제).
