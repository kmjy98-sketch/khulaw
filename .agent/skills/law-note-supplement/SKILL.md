## Overview

기존 한국 법학 노트를 유지·보완하는 스킬이다. 원본 소스에서 새 노트를 처음부터 생성하는 것이 아니라, **이미 있는 노트에 누락된 내용을 추가하거나 오류를 수정하거나 구조를 개선**하는 용도다.

새 노트를 처음부터 만들고 싶다면 `study-notes` 스킬을 사용한다.

---

## Workflow

### 1. 대상 파악 먼저

편집 전 다음을 확인한다:

- 과목: 민법 / 형법 / 헌법
- 원본 노트 파일 경로
- 단권화(통합본)가 있다면 그 경로
- 요청 모드: **augment**, **review**, **restructure**

**원본 노트를 먼저 편집하고, 원본이 안정된 후 단권화를 동기화한다.**

---

### 2. 소스 우선순위 확인

편집 전 `references/source-priority.md`를 읽는다.

기본 규칙:
- 교수 소스 > 동료 노트
- 조문·결정 원문 > 요약본
- 소스 충돌 시 충돌 사실을 명시
- 소스가 주장을 뒷받침하지 않으면 `소스에서 확인할 수 없습니다` 또는 `자료 부족—보류`로 표기

---

### 3. 모드 선택

#### augment
전체 노트 정체성을 바꾸지 않고 내용을 추가할 때 사용.

주요 작업:
- 요건 ①②③ 추가
- 원칙 → 예외 구조 추가
- 판례문구 한 줄 추가
- 모답형 또는 선지판단형 문장 추가
- 회상 개선 시에만 도표 추가
- **각주 형식 적용**: 근거 추가 시 `근거 위치`를 `[^id]` 각주로 분리. 기존 인라인 근거 위치도 각주로 변환
- **고아 각주 해소**: 편집 섹션 내 정의 없는 `[^id]` 참조에 각주 정의 추가 (페이지 마커에서 소스 추출)
- **백링크 추가**: 편집 섹션의 쟁점이 같은 과목 다른 노트에도 등장하면 `[[파일명#섹션명]]` 백링크 삽입 (과목 내 한정, 섹션당 최대 3개)

#### review
갭 검토 또는 오류 스캔 요청 시 사용.

출력 순서:
1. 내용 오류
2. 소스 불일치
3. 구조 갭
4. **각주 무결성**: 고아 참조(정의 없음) / 고아 정의(참조 없음) 목록
5. **백링크 커버리지**: 같은 과목 내 교차참조 가능하나 미링크된 쟁점 보고
6. 잔여 리스크

review 모드에서는 사용자가 명시적으로 승인하거나 진행을 요청하지 않는 한 **묵묵히 재작성하지 않는다.**

#### restructure
회상 또는 답안 작성을 위해 노트 순서나 레이아웃 변경 요청 시 사용.

기존 노트의 소스 추적성을 보존한다. 재정렬은 허용, 미인용 압축은 불허.

##### restructure — issue-priority 서브모드

기출/사례집 빈도 데이터 기반으로 노트 목차를 쟁점 중심으로 재배치할 때 사용.

**입력**: `.agent/state/issue_frequency.json` (extract_issues.py로 생성)

**동작**:
1. issue_frequency.json에서 해당 과목 상위 쟁점 목록 로드
2. 기존 노트의 `## N.` 섹션들을 쟁점 빈도 순위에 매핑
3. 빈출 쟁점(상위 10) 섹션을 노트 상단으로 이동
4. 빈출 섹션에 모답형/판례/도표 배분 우선
5. 기존 `## 1. 빈출 쟁점` 표의 ★ 등급을 실제 빈도 데이터로 갱신
6. 빈도 데이터에 매핑되지 않는 섹션은 기존 순서 유지하여 후반부 배치

**제약**:
- 섹션 내용(근거 발췌, 판례, 조문)은 변경하지 않음 — 순서만 변경
- 소스 추적성 보존: 근거 위치, 파일 참조 유지
- 빈도=0인 쟁점 섹션도 삭제하지 않음 (후반부 배치)
- 노트의 `## 0. 소스 범위` / `## 0-1. 독법` 등 메타 섹션은 항상 최상단 유지

---

### 4. 노트 작성 규칙 적용

편집 전 `references/note-structures.md`를 읽는다.

핵심 규칙:
- 모든 법리 단정에 `근거 발췌`와 `근거 위치` 필요
- 페이지 번호, 문단 번호, 사건 식별자 임의 생성 금지
- 동일 내용을 바로 아래 문장 블록이 설명할 때만 도표 유지
- 요건은 ①②③ 형태의 문장으로 작성
- 예외 중심 법리는 `원칙 → 예외` 구조로 작성
- 서브개념도 최소 개념 한 줄 또는 판례요지 한 줄 유지
- 기존 파일 이름과 섹션 번호는 번호 자체가 깨진 경우가 아니면 보존
- **챕터별 페이지 마커**: `##` 섹션에 페이지 마커 주석 필수. augment 시 누락된 마커 보강, review 시 마커 정확성 검증. 상세: `references/note-structures.md` "챕터별 페이지 마커 규칙"

### 4-1. korean-law-mcp 자동 조회

노트 편집 중 다음 상황이면 korean-law-mcp MCP 도구를 **자동 호출**한다:

1. **augment — 조문 보강**: 노트에 조문 번호만 있고 원문이 없으면 `get_law_detail`로 원문 조회 → 요건 ①②③ 변환 소스로 사용
2. **augment — 판례 보강**: 판례명/사건번호가 있지만 판결요지가 없으면 `search_precedent_tool` → `get_precedent_detail`로 판결요지 한 줄 확인
3. **review — 조문 정확성 검증**: 노트의 조문 내용이 원문과 불일치 의심 시 원문 대조
4. **restructure**: 조회 불요 (구조 변경만 수행)

자동 조회 결과는 근거 형식으로 기재: `[《국가법령정보센터》 | "조문 원문"]`

qmd law-notes 검색 결과에 이미 원문이 있으면 중복 조회하지 않는다.

### 5. 과목별 기본값

#### 형법
- 쟁점 집중 블록: `쟁점의 정리 → 학설 → 판례 → 검토 → 모답형`
- 조문 집중 블록: `조문·요건 ①②③ → 원칙·예외 → 판례 → 검토 → 모답형`
- IRAC 레이블 잔존 시: `쟁점`, `기준`, `포섭`, `결론` 선호
- **보강 소스 3종 병행**: `서보학_형법총론_18.pdf`(요건·법리 기준) + `홍형철_쟁점정리_형법_25.pdf`(쟁점 프레임·학설) + `김성돈_형법총론_*_25.pdf`(비교 학설·교차 검증)
- **김성돈 보강 추가 시**: `교수님 저서 보강` 블록과 별도로 `김성돈 보강` 블록을 아래에 추가
  - 형식: `- \`김성돈 보강\`: [요점]. [《김성돈_형법총론_파트명_25.pdf》 p.X | "발췌"]`
- **소스 범위 추가 기준**: 내용에서 인용되는 파일은 반드시 `## 0. 범위 전제` 또는 `## 0. 소스 범위`에 등재

#### 민법
- `청구권/법률효과/요건` 구조 우선, 사례형 포섭문장 부착
- 쟁점노트, 사례교재, 판례 PDF, 교수 교재 교차 확인
- 학설 대립 잔존 시: controlling source 먼저 기재, 보조 source는 자료상 대립으로 분리
- **요건 작성 규칙 (사용자 지시)**: 목차형 나열(명사형) → 쟁점노트 기준 판례 한 문장 변환 최우선
  - 쟁점노트에서 판례 원문 확인 가능: 판례 한 문장으로 요건 대체
  - 판례 원문 확인 불가: 쟁점노트 문장형 → ①②③ 문장형으로 변환
  - 목차형 명사 나열은 augment 시 반드시 변환 대상으로 처리

#### 헌법
- IRAC 강요 없이 객관식 중심 구조 기본값
- `개념 → 비교표 → 판례/결정례 한 줄 → 객관식 함정 포인트` 선호
- PPT, 단권화, OX, 결정례 정리 먼저 확인

---

### 6. 동기화 및 검증

편집 후:

1. 원본 노트에서 단권화(통합본)를 동기화한다
2. 해시 비교로 쌍을 검증한다
3. 최종 응답에서 다음을 보고한다:
   - 변경된 파일
   - 변경 내용
   - 원본/통합본 쌍 일치 여부
   - 미해결 소스 충돌 또는 보류 블록
