# SKILL: Anki Card Generation for Law Study

## 0. 목적

이 스킬은 법학 학습 자료를 Anki 카드로 변환하기 위한 규칙이다.
Codex Web/Pro 환경에서 실행 가능해야 하므로 Claude, Gemini, Antigravity 등 특정 모델 전용 명령에 의존하지 않는다.

## 1. 우선순위

카드 작업 시 다음 순서로 읽는다.

1. 루트 `AGENTS.md`
2. 과목별 `AGENTS.md`
3. `.agent/workflows/card-wiki-pipeline.md`
4. 이 파일
5. `docs/anki/*.md`
6. `docs/legacy/*.md`는 참고만 한다.

충돌 시 최신 Codex 운영 문서와 `AGENTS.md`를 우선한다.

## 2. 입력

허용 입력:

- `sync/wiki/쟁점/*.md`
- 사용자가 직접 제공한 위키 또는 노트 텍스트
- 검증된 카드 소스
- OCR 원문에서 확인한 발췌
- korean-law-mcp 또는 공적 법령 및 판례 원문 확인 결과

주의:

- `outputs/02_cards_v37/*.md`는 대량 산출물이므로 Git에 기본 포함하지 않는다.
- Web/Pro 환경에서 해당 파일이 없으면 Drive 자료 요청으로 처리한다.
- 원문 또는 근거가 없는 법리 단정은 만들지 않는다.

## 3. 출력

기본 출력은 Markdown 카드 초안이다.

Basic 카드:

```text
카드유형: Basic
Front:
Back:
태그:
출처:
검증상태:
```

Cloze 카드:

```text
카드유형: Cloze
Text:
Extra:
태그:
출처:
검증상태:
```

## 4. 카드 유형

### 4.1 Rule 카드

요건, 효과, 법리 일반론을 묻는다.

- 하나의 카드에는 하나의 인출 목표만 둔다.
- 요건이 여러 개면 cloze 분할을 우선한다.
- 조문번호가 있으면 정확히 표시한다.
- 조문 원문이 없으면 `조문 원문 미확인`으로 표시한다.

### 4.2 Case-law 카드

판례 법리를 묻는다.

- 사건번호와 선고일이 확인된 경우에만 판례 anchor를 확정한다.
- 사건번호 또는 선고일이 불명확하면 `[불명확]`으로 표시한다.
- 판례 요지를 임의로 압축해 새로운 법리를 만들지 않는다.

### 4.3 Issue 카드

쟁점 구조, 요건사실, 청구 및 항변 구조를 묻는다.

- 사례형은 청구권, 항변, 재항변 구조를 유지한다.
- 원고와 피고 대립 구조가 있으면 표 또는 단계형으로 분리한다.
- 답안 작성용 암기 포인트와 객관식 판별 포인트를 혼합하지 않는다.

### 4.4 MCQ/OX 카드

객관식 및 OX 판단을 묻는다.

- 정오 근거가 있는 경우만 생성한다.
- `기출` 또는 `빈출` 태그는 소스에 명시된 경우만 붙인다.
- 해설 없는 단순 OX는 검증필요로 둔다.

## 5. 태그 체계

태그는 최소한 다음 축을 유지한다.

```text
과목::
속성::
주제::
출처::
검증::
```

예시:

```text
과목::민법
속성::판례
주제::부당이득
출처::송영곤_쟁점노트
검증::anchor확인
```

금지:

- 출처 없는 `기출`
- 출처 없는 `빈출`
- 근거 없는 난이도 태그
- 모델 추정 태그

## 6. 근거 규칙

모든 법리, 조문, 판례 단정은 근거를 붙인다.

```text
근거 발췌: "..."
근거 위치: 문서명 / 페이지 / 절 / chunk_id
```

위치가 없으면 다음처럼 표시한다.

```text
근거 위치: 확인 불가 - 위치 식별자 부족
```

근거가 없으면 카드를 만들지 말고 다음처럼 출력한다.

```text
자료 부족 - 카드 생성 보류
사유:
필요한 추가 자료:
```

## 7. 검증 상태

카드마다 하나의 검증 상태를 붙인다.

```text
검증::완료
검증::anchor확인
검증::원문확인필요
검증::판례확인필요
검증::조문확인필요
검증::보류
```

## 8. 금지

- 교재 원문 없는 법리 창작
- 조문번호 추측
- 판례 사건번호 추측
- 선고일 추측
- 원문에 없는 예외 창작
- 특정 모델 전용 실행 명령을 필수 경로로 작성
- 대량 `outputs` 자동 커밋
- `.apkg` Git 커밋
- 개인 학습 상태 Git 커밋
- API key 또는 MCP 실설정 커밋

## 9. apkg 빌드

apkg 빌드는 사용자가 명시 요청하거나 카드 파일을 변경한 경우에만 한다.

빌드 전 확인:

```text
- 변경된 카드 파일 목록
- 총 카드 수 예상
- Basic/Cloze 수
- 한자 잔존 여부
- 번호 없는 cloze 여부
- 과목별 분리 여부
```

빌드 후 확인:

```text
- 총 카드 수
- Basic/Cloze 수
- 과목별 apkg 존재 여부
- 한자 잔존 0
- 번호 없는 cloze 0
```

## 10. 접근 실패 대응

카드 생성에 필요한 원문, 기존 카드, 위키 파일을 읽지 못하면 다음 형식으로 보고한다.

```text
읽기 실패:
- 대상:
- 필요한 이유:
- 시도한 경로:
- 실패 결과:
- 후속 요청:
```

추측으로 대체하지 않는다.
