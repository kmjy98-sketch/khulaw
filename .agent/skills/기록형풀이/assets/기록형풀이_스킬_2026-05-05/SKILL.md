# 기록형 풀이 스킬 (Claude Code 전용)

사건기록 폴더의 PDF들을 읽고 3단계로 답안을 생성한다. 모든 단계에서 `기록형풀이_룰_2026-05-05.md`의 R1~R10을 준수한다. 특히:
- **R1** 기록 밖 사실 창작 금지 / **R4** 실재 판례만(korean-law-mcp 검증) / **R6** 순환 인용 금지(인용은 항상 원 기록 문서 기준)

## 입력

1. 사건기록 폴더 경로 (예: `4.저작/대회/ai 대회/예시 기록/[Demo] 2026형제8765 상해/`)
   - 신규 기록 표준 위치: `4.저작/대회/ai 대회/기록/{사건번호 사건명}/` — 사건당 폴더 1개에 PDF 일체. 폴더명에 `[대괄호]` 사용 금지(PowerShell 와일드카드 오인).
2. 문제 지시문: 작성할 서면 유형(소장/답변서/준비서면/참고서면/변호인의견서·변론요지서/검토의견서/의견서/공소장)과 당사자 입장. 없으면 **Phase 0 종료 후 사용자에게 확인**. 대회 과제가 양측 서면 제출을 요구하면 한쪽만 지정돼도 원·피 양측을 모두 작성한다(추첨 전 제출 요건). **사건기록 기반 소송 서면뿐 아니라, 기업 자문·규제 리스크 진단형 과제(예: 핀테크사 대상 EU·외국법+국내 규제 종합 검토의견서)도 포함한다** — 이때는 과제를 분해해 단일 검토의견서로 통합하고, 외국법은 Phase 2의 EU/외국 출처로 검증한다(로스쿨 AI 챌린지 예선 실증, 2026-06-20).

## Phase 0 — 기록 인벤토리

1. Glob으로 폴더 내 PDF·문서 목록 수집.
2. 파일명 규칙 해석:
   - 민사 전자기록: `법원_사건번호_문서번호_날짜_문서유형_(설명)_제출자.pdf` → 파일명만으로 목록표 1차 구성 가능
   - 형사·기타: 파일명 단순(`고소장.pdf` 등) → 표지의 순번·권·쪽수·증거번호(G번호) 확인
3. 기록 목록표 출력: `| 순번 | 문서명 | 작성자 | 작성일 | 증거번호 |`
4. **일괄 추출 선행(표준, 2026-06-11)**: 목록 수집 직후 pdfplumber 스크립트로 폴더 내 전 PDF를 `4.저작/대회/_추출/{사건번호}/`에 마크다운으로 일괄 추출한다(스크립트 처리라 토큰 소비 없음). **기존 추출본이 있으면 재추출 금지(#46).** 파일 크기(MB)는 분량 지표로 쓰지 않는다 — 이미지 첨부로 부풀려짐.
5. **면수 기준 분기**: 추출 결과 합계 약 100면 이하 → 전수 정독. 초과 → 인덱스 작성 후 우선순위 정독 + `[자료 부족—보류]` 단정별 보강 문서 매핑 표적 정독.
6. **스캔 PDF 판별**: 추출 텍스트가 빈약하면 스캔본 — 소형은 Read 도구(pages)로 직접 읽기, 대형은 Colab `ocr_extract_v2.ipynb` 경유를 사용자에게 안내.

## Phase 1 — 사실관계 정리

기록 전체를 읽고 다음 5종 산출. **단 지시문에 '사실관계 다툼 없음'이 명시되면(본선 민사 통상) D·E를 생략하고 B(다툼없는 전제사실)+C(쟁점↔주장 대비표)를 주산출로, A(타임라인)는 선택으로 강등한다:**

- **A. 타임라인**: 시간순 표, 각 행에 출처 문서·쪽 병기, 다툼 있는 사실 ★ 표시
- **B. 다툼 없는 사실 목록**: 양측 진술이 일치하는 사실 (답안의 전제사실부)
- **C. 쟁점↔주장 대비표**: `| 쟁점 | 원고·검사 주장 | 피고·변호인 주장 |` (마스터 H절과 동일 3열), 빈 셀 `—`. ※ 최종 답안의 청구-항변 2열 표(원고|피고)는 CLAUDE.md #32로 별도 적용
- **D. 증거 분류**: ①서증 ②인적 증거 ③객관 증거(CCTV·포렌식·의무기록·통화기록). 객관 증거와 진술의 일치 여부 메모
- **E. 진술 불일치표**: 같은 사실에 대한 문서 간 차이를 발췌 병기로 대비 → 신빙성·반대신문 포인트
- **F. 사실관계도(Mermaid)**: 당사자·주요 객체(부동산·금전·가상자산)를 노드로, 당사자 간 행위(계약·이체·송금·등기·양도·소송)를 화살표로(라벨=날짜·금액·출처). 권리변동 복잡 시 `graph LR`, 점선=다툼 사실, 한글 라벨. ` ```mermaid ` 코드블록으로 산출(Obsidian 렌더). 도식은 검토·이해용 — 서면엔 글로 서술. 다툼없음 모드에서도 권리변동이 복잡하면 권장.

각 항목의 모든 셀에 출처(`《문서명》 p.X`)를 붙인다. 발췌 없이 요약만 적지 않는다.

## Phase 2 — 관련 조문·판례 탐색

1. **쟁점 도출**: Phase 1의 다툼 있는 사실에서 쟁점 번호 매김(최대 6개), 각 쟁점에 잠정 조문 부착.
2. **조문 검증**: 잠정 조문 전부를 korean-law-mcp로 원문 조회 → 원문 발췌 확보. 실패 시 `[검증필요]` + law.go.kr 검색어 제시.
3. **판례 탐색**: 쟁점별로
   - korean-law-mcp 판례 검색 (1차)
   - WebSearch — `site:glaw.scourt.go.kr`, `site:law.go.kr` 한정 (2차)
   - **EU·외국법**: EUR-Lex(CELEX)·gesetze-im-internet.de(회원국법)·gdpr-info.eu·curia.europa.eu(CJEU)·각국 감독당국(BaFin·아일랜드 DPC·CNIL) 직접 인출. 동적 페이지(law.go.kr·infocuria)는 CaseNote/LBOX/위키문헌 미러로 우회 (사이트 매핑은 `기록형풀이_룰` 참조)
   - 사용자 보유 자료: `outputs/02_cards/`(주제:: 태그 grep), `sync/wiki/쟁점/` 아티클, `sync/가인 역대 우수 답안.md`(동일·유사 사건의 판례 구성·정형문구 레퍼런스) (3차 — 단, wiki·우수답안은 참고일 뿐, 판례 원문 재확인 필수 #40)
   - 확인 실패 시 사건번호 단정 금지, `[검증필요]` + 추천 검색어
   - **MCP·검색의 실제 반환 로그가 없으면 사건번호·판시를 "MCP 확인"으로 단정하지 않는다.** `get_precedent_detail` 본문 미반환 시 `[부분검증: 사건명만 일치, 판시 미확인]`, 완전 미확인 시 `[검증필요: 후보 없음]`으로 2단 표기. (Phase 3-5 '본문 미반환 판례 본문 인용 금지'와 정합)
4. **결과 정리표**: `| 쟁점 | 조문(원문 발췌) | 판례(사건번호+판시 발췌) | 출처 |`

## Phase 3 — 답안 작성

1. **서면 유형별 골격**:
   - 민사 소장: 청구취지 → 청구원인(요건사실 순) → 입증방법 → 결론
   - 민사 답변서·참고서면: 청구취지에 대한 답변 → 청구원인에 대한 인부(認否는 '인정/부인'으로 표기) → 항변 → 결론
   - 형사 변호인의견서: 사건 개요(공소사실·혐의사실 요지) → 쟁점별 의견[법리→포섭→소결] → 정상관계(양형 사유) → 결론
   - 검토의견서: 질의 → 쟁점별 검토 → 결론 및 조치 의견
2. **IRAC 변형**: 쟁점→법리(Phase 2 결과만 사용)→포섭(Phase 1 발췌 인용, 단 인용 표기는 원 기록 문서)→소결. **Phase 2에서 `[검증완료]`한 판시 발췌를 본문 법리에 따옴표 직접 인용으로 승격**하고, `[검증필요]` 후보 사건번호는 본문에 쓰지 않는다(쟁점·법리 표에만). 쟁점당 복수 판례로 밀도 확보.
3. **상대방 예상 주장 최소 1개 + 반박** 배치. 불리한 쟁점 회피 금지(R9).
4. **문체·형식**: 법원 제출 서면 문체. 분량·서식은 지시문/대회규정 기준. **가인 제출 기본값**: 제출 파일 HWP/HWPX, A4 **20매 이내**, 여백 상·하·좌·우 20mm, 본문 맑은 고딕·명조 계열 12pt(제목 14pt), 줄간격 160%. 과소작성도 감점. 여백·줄간격·글꼴은 고정값이라 초과 시 자구 압축으로만 해결. **단 양식이 공지되지 않은 대회는 페이지 캡이 구속이므로, 캡을 못 맞추면 글꼴·줄간격을 낮춰 맞춘다(가인 고정값 비적용 — 로스쿨 AI 챌린지 32매→19매 사례).** **IRAC 변형은 내부 구조로만 쓰고 본문엔 '쟁점/법리/포섭/소결' 라벨을 노출하지 않는다 — 변호사 의견서 산문으로 작성(사용자 지시 2026-06-20).**
5. **생성 후 검증(#13)**: 답안 내 모든 조문번호·사건번호를 korean-law-mcp로 재검증. 검증 실패 단정은 삭제 또는 `[검증필요]`로 강등.
6. **논리·포섭 검증**: `기록형_논리포섭검토_2026-06-20.md` A절 5축(①요건-사실 대응 완전성 ②삼단논법 타당성 ③반대논거·구별 ④내부 일관성 ⑤결론 정합)으로 점검. 요건 누락·논리 비약은 최우선 보강. (정확성 검증(5번)과 별도 축)

## 산출물 저장

- 위치: 사용자 지정 > 없으면 `4.저작/대회/{사건번호}/` (예: `4.저작/대회/2026형제8765/`). 기록 원본 폴더 안에는 생성하지 않는다 (워크스페이스 루트 생성 금지 #42)
- 파일: `01_사실관계정리.md`, `02_쟁점조문판례.md`, `03_답안_{서면유형}.md`
- 제출본: **`.agent/scripts/md_to_docx.js`로 docx 생성**(`node md_to_docx.js in.md out.docx [bodyPt] [linePct]`, 가인 서식 자동) → 사용자가 한글에서 HWP/HWPX로 수정·저장. 면수는 Word COM `ComputeStatistics(2)`로 실측, 캡 초과 시 bodyPt/linePct 낮춰 재생성. docx 패키지는 C: 로컬 설치(구글드라이브 경로 깨짐). 상세는 `참고서면작성_룰프롬프트_2026-06-12.md` C·D·F절. (실 Python 없으면 pdftotext·Node docx-js·Word COM 체인)
- 추출 캐시: `4.저작/대회/_추출/{사건번호}/` / 운영 보고서(파일럿·검토류)는 `sync/_meta/` 유지
- 임시 파일은 완료 즉시 `_trash/{YYYY-MM-DD}/`로 이동(#16)
