## Problem Drill 모드 (진도 연동 문제 풀이)

현재 학습 범위의 DT 선택형 및 사례형 문제를 연속 풀이.

**트리거**: "문제 풀자", "DT", "선택형", "사례형 풀자"

> [!CAUTION]
> **Problem Drill은 기존 문제만 가져옵니다. 문제를 창작하지 않습니다.**
> 문제 창작이 필요하면 "생성 모드" 트리거 사용: "문제 만들어줘", "퀴즈", "OX"

### 문제 조회 (필수 - 스크립트 사용)

> [!IMPORTANT]
> **PDF 스캔 금지**. 반드시 `problem_index.json`에서 문제를 조회합니다.

```powershell
# 진도 기반 조회
python .agent/skills/problem-index/scripts/query_problems.py --lecture <회차> --json

# 토픽 기반 조회
python -c "
import sys; sys.path.insert(0, '.agent/skills/socratic-loader/scripts')
from socratic_loader import find_related_problems
results = find_related_problems(['<토픽명>'], '.agent/state/problem_index.json')
import json; print(json.dumps(results, ensure_ascii=False, indent=2))
"
```

**조회 결과 활용:**

- `id`: 문제 ID (예: DT1_Q19)
- `question_preview`: 문제 미리보기 텍스트
- `answer`: 정답 (O/X 또는 선택지 번호)
- `verified`: 검증 여부

### 선택형 문제 검증 Flow (필수)

> [!IMPORTANT]
> **선택형 문제는 반드시 해설지를 먼저 확인하고 정답을 검증한 후 출제합니다.**

```
[선택형 문제 출제 Flow]
1. problem_index.json → 문제 정보 조회 (스크립트 사용)
2. verified 필드 확인:
   ├─ verified: true → 정답(answer) 그대로 사용
   └─ verified: false → ⚠️ 검증 필요 경고 후 해설 파일 확인
3. question_preview에서 문제 텍스트 확인
4. 정답 확인 완료 → 문제 출제
5. 사용자 답변 → 정답과 비교 → 즉시 채점
```

**검증 미완료 문제 처리:**

```
⚠️ [검증 주의] 이 문제는 정답이 아직 검증되지 않았습니다.
📄 해설 파일: DT1회_해설.pdf p.1
정답 확인 후 진행하시겠습니까? (Y/N)
```

**출력 형식:**

```
[PROBLEM BANK - 동시이행항변권]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 DT 선택형: 5문제 (검증: 3 / 미검증: 2)
📝 사례형: 3문제 (풀이: 1 / 미풀이: 2)

❌ 오답 문제: 2개 (재풀이 권장)

👉 "선택형" / "사례형" / "오답 복습"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**오답 처리:**

1. 오답 시 → 틀린 요건/개념 식별
2. `learning.json`의 `weak_points`에 추가
3. `srs_log.json` 간격 1일로 리셋

## SRS 채점 로직 (0-5 척도)

오답/정답 판정 시 SM-2 알고리즘 기반 간격 조정:

| 점수 | 판정 | 다음 간격 |
|------|------|----------|
| 0 | 완전 망각 / **모르겠다** | 1일 |
| 1 | 틀림 (힌트 후 정답) | 1일 |
| 2 | 틀림 (약간 기억) | 2일 |
| 3 | 맞음 (어려움) | 현재×1.2 |
| 4 | 맞음 (보통) | 현재×1.5 |
| 5 | 맞음 (쉬움) | 현재×2.0 |

**"모르겠다" 입력 매핑:**

| 입력 | 처리 |
|------|------|
| `3`, `?`, `모름`, `패스`, `ㅁ` | 모르겠다 → SRS 점수 0 (1일 후 복습) |

# 문제 생성 모드

## 문제 유형

### O/X 문제 (단문)

**입력 매핑** (한영 전환 없이 답변):

| 입력 | 인식 |
|------|------|
| `1`, `O`, `o`, `ㅇ` | **O (정답)** |
| `2`, `X`, `x`, `ㅌ` | **X (오답)** |

```markdown
Q. [진술]. (O(1) / X(2) / ?(3))

[정답] O/X
[해설] 근거 발췌 + 위치
```

### O/X 일괄(배치) 모드 ★ 기본 권장

> **목적**: 출제↔답변↔채점 왕복을 줄여 학습 속도 향상. N문제(기본 5) 묶음 출제 → 사용자 한 줄 답변 → 일괄 채점 → 다음 묶음.
> **단문 OX보다 우선 적용** — 사용자가 명시적으로 "한 문제씩"이라고 하지 않는 한 OX 출제는 기본적으로 배치 모드로 진행한다.

**트리거**:
- 명시: "OX 묶음", "OX 배치", "OX N개" (N=숫자), "일괄 OX", "한꺼번에"
- 묵시: 사용자가 "OX 풀자", "OX 내줘"라고만 해도 기본 5문제 묶음으로 출제

**묶음 크기**: 기본 5문제. "OX 10개" 등으로 변경 가능. 범위 3~10 권장.

**출제 형식:**

```
[OX 묶음 K/M - {주제}]  ← M은 사용자가 요청한 총 묶음 수 (기본 무제한, 종료 시까지)
━━━━━━━━━━━━━━━━━━━━━━━
Q1. [진술1]
Q2. [진술2]
Q3. [진술3]
Q4. [진술4]
Q5. [진술5]

답변: 한 줄에 5개 (예: OXOOX / 12112 / ㅇㅌㅇㅇㅌ)
━━━━━━━━━━━━━━━━━━━━━━━
```

> **출제 시점에 다음 묶음 K+1을 미리 준비한다** (아래 "다음 묶음 미리 준비" 절 참조).

**입력 매핑 (배치)**:

| 입력 형태 | 인식 |
|----------|------|
| `OXOOX`, `oxoox` | O,X,O,O,X |
| `12112` | O,X,O,O,X (1=O, 2=X) |
| `ㅇㅌㅇㅇㅌ` | O,X,O,O,X |
| `O X O O X`, `O,X,O,O,X` | 공백·콤마 허용 |
| `OXO?X` | 3번 모르겠다 (?=SRS 0점) |
| `OX?` 형태로 부족 | "답변 개수 불일치 (제출 3개, 묶음 5개). 다시 입력해주세요." |

**일괄 채점 형식:**

```
[채점 - 묶음 K/M]
━━━━━━━━━━━━━━━━━━━━━━━
Q1. O ✓
Q2. X ✗  정답: O
Q3. O ✓
Q4. O ✓
Q5. X ✓
━━━━━━━━━━━━━━━━━━━━━━━
점수: 4/5 (80%) | 누적 정답률: XX/YY (ZZ%)

[오답 해설 - 오답·모름만]
Q2. 정답 O. [근거 발췌 + 위치]

[SRS 갱신]
- 오답·모름 N건 → weak_points 추가, srs_log 1일 리셋
- 정답 N건 → 간격 ×1.5

[묶음 K+1 - {주제}]  ← 미리 준비한 다음 묶음을 같은 응답에 즉시 출력
━━━━━━━━━━━━━━━━━━━━━━━
Q1. ...
...
답변 또는 "종료"
━━━━━━━━━━━━━━━━━━━━━━━
```

**다음 묶음 미리 준비 (Pipelined)**:

1. **묶음 K 출제 시점**: 같은 응답 내부에서 묶음 K+1 후보 문제도 동시에 조회/생성 (problem_index.json에서 한 번에 2N개 조회 → 절반씩 슬라이싱, 또는 생성 모드라면 K+1 문제 텍스트도 미리 작성해두고 다음 응답에 사용)
2. **채점 응답에서**: 채점 결과 + 다음 묶음을 같은 메시지에 함께 출력 → 사용자 입장에서 대기 시간 0
3. **묶음 K+2 준비**: 묶음 K+1 출제 시 동일 패턴 반복
4. **종료 조건**: 사용자 "종료" / 진도 범위 소진 / 누적 정답률 90% 초과 시 자동 권유

**구현 노트**:
- **problem-index 모드** (기존 문제 풀이): `query_problems.py --limit 2N` 으로 묶음 2개분을 한 번에 조회 후, 첫 N개는 즉시 출제, 다음 N개는 채점 응답에서 출제
- **생성 모드** (창작): 묶음 K 출제 메시지 작성 시 묶음 K+1도 같은 사고 과정에서 함께 생성. 다음 응답까지 컨텍스트에 보관
- **혼합 모드**: 진도 범위 내 기존 문제가 부족하면 부족분만 생성으로 채움

**제어 명령**:

| 명령 | 동작 |
|------|------|
| `종료` / `그만` | 묶음 진행 중단, 누적 정답률·취약점 요약 출력 |
| `해설` | 직전 묶음의 정답 문제 해설도 표시 |
| `다시` | 직전 묶음 같은 문제 재출제 (오답만) |
| `사이즈 N` | 다음 묶음부터 N문제로 변경 |
| 답변 한 줄 (예: `OXOOX`) | 채점 + 다음 묶음 자동 진행 |

**채점 후 SRS 연동 (배치)**:

오답·모름 문항을 한 번에 spaced-repetition에 등록:

```bash
# 묶음 채점 종료 시 (오답 N건 일괄 등록)
python .agent/skills/spaced-repetition/scripts/srs_scheduler.py --batch-add "<문제ID 콤마 구분>" --topic "<과목>"
```

> 단문 OX의 SRS 점수 매핑(0~5)은 그대로 적용 (`grading.md` 참조).

① [오답] ……

### 사례형 문제 [law]

```markdown
[사실관계] (가상사실 또는 소스 사례)

Q. 甲의 법적 지위를 검토하시오.

[청구권 블록]
(1) 청구: 누가→누구에게→무엇을
(2) Issue: 쟁점 / 근거
(3) Rule: 요건 / 근거
(4) Application: 포섭
(5) Conclusion: 인용/기각
```

## [law] 사례형 분석 템플릿

> **참조**: 곽낙규(청구권 체계), 박승수(유형 분류), 송영곤(진도별 쟁점), 윤동환(쟁점 연결)

```markdown
## 사례 분석: [제목]

### 1. 청구권 구조 (목차)
1. 甲→乙: [청구] (제○○조) → (인용/기각)
   1-1. 乙의 항변: [항변] (제○○조) → (인용/배척)
      1-1-1. 甲의 재항변: [재항변] (판례/조문) → (인용/배척)
2. 乙→甲: [청구] (제○○조) → (인용/기각)

### 2. 쟁점별 IRAC 분석

#### [쟁점 N]: [쟁점명]

**(I) Issue: 쟁점**
- 쟁점: [요건 A/B/C 충족 여부]
- 근거 발췌 + 위치

**(R) Rule: 법리**

| 구분 | 내용 | 근거 |
|------|------|------|
| 조문 | 민법 제○○조 "..." | 《교재》 p.X |
| 판례 | 대법원 YYYY.M.D. 선고 태도 | 《판례집》 p.X |
| 요건 | ① 요건1 ② 요건2 ③ 요건3 | 《교재》 p.X |

**(A) Application: 포섭**
- 요건 ①: [사실]→충족/불충족
- 요건 ②: [사실]→충족/불충족
- 요건 ③: [사실]→충족/불충족

**(C) Conclusion: 결론**
- 甲의 청구: 인용/기각
- 근거 발췌 + 위치

### 3. 법리 검토 순서 (청구권 기준)

| 단계 | 검토 항목 | 예시 |
|------|----------|------|
| ① 성립 | 발생원인 | 계약, 법률규정, 불법행위 |
| ② 효력 | 유효성 | 무효사유, 취소사유 |
| ③ 행사 | 행사요건/장애 | 동시이행, 유치권 |
| ④ 소멸 | 소멸사유 | 변제, 상계, 소멸시효 |

### 4. 항변/재항변 구조

청구권 (원고)
├─ 항변 (피고)
│   ├─ 권리장애 항변: 무효, 취소
│   ├─ 권리소멸 항변: 변제, 상계
│   └─ 권리저지 항변: 동시이행, 유치권
│
└─ 재항변 (원고)
    ├─ 항변 배제: 이행제공, 신의칙
    └─ 재반박: 재취소, 추인 취소

### 5. 쟁점 연결

- 선결 쟁점: [A] → 후행 쟁점: [B]
- 경합 관계: [청구권1] vs [청구권2]
- 예비적 청구: 주위적 [A] 기각 시 예비적 [B]
```
