# 카드·사례 설계 확정 (#51 + #50 사례층)

## 1. 저장 구조 (확정)
- **논점노트(쟁점 원문보존)** = `sync/위키/{과목}/{쟁점}.md` — 기존. A atom(룰/요건/판례/조문/표) source.
- **사례노트(신설)** = `sync/위키/사례/{과목}/{사례}.md` — sync(옵시디언 백링크·Bases·열람). 사례↔쟁점 **양방향 백링크**.
- **원문 전문(교재 OCR)** = `outputs/01_ocr_llamaparse/` — 비동기, 기존.
- 주의(용량): 사례집 누적이 sync 1GB 압박하면 모범답안 전문만 outputs 분리(2층) 재고. 현재는 sync 일원.

## 2. 사례노트 형식 (확정)
```
---
type: 사례
과목: 민법
출처: [사례집/변시N회/내신] (p)
유형: 다툼형          # 다툼형 | 검토형 | 기록형
쟁점: ["[[사해행위소송 본안판단]]", "[[채권자취소권 소송요건]]"]   # 논점노트 백링크(닫힌루프)
난이도:
회독: 0  사례: 0  약점: false        # 진도속성(드릴·보드 연동)
풀이순서검증:
---
# [사례 제목]
## 문제 (사실관계 + 설문)        ← 드릴 출제 시 제시. 검토형은 사실관계 전문 필수(결론이 사실에서 도출되므로)
## 풀이순서 (골격)               ← 절차 통목차. 풀이순서 카드 source
## 포섭격자 (요건 ↔ 사실관계)    ← claim-chart 셀: 요건 | 충족 사실(핀사이트) | 평가 (+민사 증명책임). 결론이 어느 사실에서 나오는지 추적
## 모범답안 (채점 전용)          ← 풀이 중 미노출, 채점 때만 read
## 채점포인트·함정
```
본문에서 `[[쟁점]]` 위키링크로 논점노트 연결 → 옵시디언 백링크로 **쟁점노트에서 "이 쟁점이 나온 사례" 역참조**.
**핵심(2026-06-28 교정)**: 사례형의 실력 = **포섭(사실↔요건)**. `## 포섭격자`가 결론을 사실에 묶는다(claim-chart 요건×사실 / 포섭 4슬롯). '야간·공포·경악'식 결론어는 사실(자정·칼협박·급박)의 평가어 — 사실 누락 시 포섭 0. 그래서 사실관계는 전문 보존.

## 3. 카드 모델 #51 (확정 — 3역할 + 메타축)
| 역할 | source | 안키 | 비고 |
|---|---|---|---|
| **A 실질 atom** | 논점노트 | O | 룰/요건/판례/조문/표 전수, 누락0 게이트 |
| **풀이순서 카드** | 사례노트 `## 풀이순서` | O | cloze 골격 암기(통목차) |
| **사례 전문** | 사례노트 문제/모범답안 | **X** | 격리 — 드릴 출제·채점 자산 |

**역할 분담(포섭 교정)**: 풀이순서 카드 = **절차 통목차 암기**(추상 OK). **사실↔요건 포섭 실력 = `## 포섭격자` + 드릴(풀기→채점)** 이 담당 — 카드가 사실을 키워드로 추상화해도 되는 건 포섭격자·사실관계 전문이 드릴/채점을 떠받치기 때문. claim-chart(요건×사실 셀)·포섭 4슬롯이 포섭격자로 구현됨.

**A 카드 메타축**(요건사실론·단계 반영):
- `단계::` 쟁점 / 규범 / 포섭 / 결론 (추론사슬 role).
- 요건사실 카드: `요건사실` 명제 + `증명책임:: 원고/피고`(법률요건분류설) + 대응 `항변` 부속.
- 강조(볼드/밑줄) = **우선순위·핵심 태그**(별도 카드 양산 X, A 선별 + 풀이순서 추출 신호).

**누락0 게이트**: 논점노트 atom 대비만(사례 전문은 면제). `카드검증:완료(누락0)` 마커, #45-C 재개식, #142 파일럿→전체.

## 4. 닫힌루프 (확정)
```
목차 → 쟁점(논점노트) → A카드 ↔ 사례노트(백링크) → 드릴(A=객관식 / 사례=풀기+채점) → 보드·약점 → 목차
```
- 사례↔쟁점 **양방향 백링크**(S4 실현).
- 암기(안키) = A + 풀이순서. 사례 풀이능력 = 드릴 복습트랙(풀기→case-answer-review 채점→약점역류). 사례 전문 = 채점 시에만 모범답안 read.
