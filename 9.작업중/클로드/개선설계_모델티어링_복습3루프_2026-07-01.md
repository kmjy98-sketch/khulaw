# 개선설계 — 모델 티어링·채점관·복습 3루프

## 1. 현행 에이전트 구조 타당성 진단

**타당(유지)**:
- #45-D 소수·내부순차·마커 재개 — 사례확장(96청크·919노트)에서 실측 검증됨. 대량 fan-out은 한도 동반사망, 소수(≤6)·순차가 세션 창당 실질 진척 최대.
- #45-B 판단=에이전트 / 결정적=코드 분리 — dedup(코드)·분류배정(에이전트) 분업이 정확도·비용 모두 우수했음.
- 마커 이원화(카드감사=탐지 / 카드검증=완료) + stem키 멱등.

**결함(이번에 교정)**:
- (a) **모델 티어 무규정**: 모든 에이전트가 세션 모델(Fable) 상속 → 볼륨 작업이 토큰제 예산을 소모. 사례확장에서 sonnet 지정을 임의로 했을 뿐 룰이 없었다.
- (b) **에이전트-스폰-에이전트 금지 미명문**: 하위 스폰이 중복 산출·통제 불능을 낳음(실측). 프롬프트마다 수기로 금지 — 룰로 승격.
- (c) **채점이 단일 모델 경로**: 선택형 진리값 대조까지 LLM이 하거나, 사례형 채점을 무조건 세션 모델이 함. 비용 계층 없음.

## 2. 모델 티어링 (Sonnet 5 = 볼륨 / Fable = 판단·토큰제)

| 티어 | 모델 | 담당 | 근거 |
|------|------|------|------|
| T0 코드 | (모델 없음) | 진리값 대조·집계·dedup·마커·apkg·frontmatter 배치 | #45-B 결정적 커널 |
| T1 볼륨 | **Sonnet 5** | 카드 생성·보충, 사례노트 양산, OCR 교정 1차, 대량 스캔·추출, 초벌 채점(격자 대조) | 비용절감. 산출은 마커+표본게이트로 품질 보증 |
| T2 판단 | **Fable(세션)** | 룰·아키텍처 설계, 누락0 게이트 표본검증, 사례형 종심 채점, 품질 스팟검토, 오류 정합성 검토, 애매판정 에스컬레이션 | 토큰제 — 판단 집약 지점에만 투입 |

- 운용: Workflow/Agent에서 **볼륨 스테이지는 `model: sonnet` 명시**, 판단 스테이지는 미지정(세션 상속). T1 산출에 `판정불가/애매` 플래그가 있으면 그 항목만 T2로 올린다(에스컬레이션).
- 하위 에이전트 스폰 금지(명문화): 에이전트가 자기 하위 에이전트를 만들지 않는다. fan-out은 메인(오케스트레이터)만.

## 3. 채점관 구성 (3단 + 자가채점)

| 단 | 채점자 | 대상 | 토큰 |
|----|--------|------|------|
| G0 자가채점 | **사용자** | "번호만" 모드: 문제 선정·번호·소스위치(책 p./사례노트명)만 브리프 — 풀고 책 해설로 직접 채점, 결과만 보고(`--mc 9/12`·약점명) | ~0 |
| G1 진리값 | 코드/메인 | 선택형: 정답키 선확정 → O/X 진리값 대조(기존 daily-drill Phase 1) | 최소 |
| G2 초벌 | Sonnet 5 | 사례형 초벌: 사례노트 `## 포섭격자` 셀 단위 대조(요건별 O/△/X + 갭목록). 격자가 이미 있어 기계적 대조에 가까움 | 저 |
| G3 종심 | Fable | 사례형 종심: G2가 `애매` 플래그한 요건, 배점 큰 실전답안, 사용자가 "종심/제대로 채점" 요청 시 | 고(선별) |

- 기본 라우팅: 학기중·토큰 부족 시 **G0(번호만)** 기본. 평시 선택형=G1, 사례형=G2, 요청·플래그시 G3.
- G0 인터페이스: 드릴 브리프에 각 문제를 "번호+소스 위치"로만 출력(문제 본문 생성 생략 = 생성토큰도 절약). 사용자 보고를 log_result가 그대로 기록.

## 4. 복습 3루프 (L0 당일 / L1 진도 / L2 장기)

현행 2트랙(진도=회독0 선택형 / 복습심화=회독≥1 사례형+SRS)에 **L0 당일복습**을 추가해 3루프로:

| 루프 | 대상 | 주기 | 출제 | 소스 |
|------|------|------|------|------|
| **L0 당일** | 오늘 배운 것(학기 수업·강의·자습) — 사용자가 논점 지정 | 당일 즉시 + 익일 1회 | 선택형 3~5문(G0/G1) | 논점노트 + 해당 카드 |
| **L1 진도** | 나가고 있는 논점(회독0·진행) | 매일 | 선택형(G1) | 기존 진도 트랙 |
| **L2 장기** | 나간 논점(회독≥1)·약점 | SM-2 due → 안키 FSRS 핸드오프(#20) | 사례형(G2/G3) + SRS 선택형 | 사례노트 포섭격자 + SRS |

- L0 입력: `build_session.py --today "민법/대상청구권,민사소송법/기판력"` 또는 자연어("오늘 수업에서 ~ 배웠어"). 기록: 논점 frontmatter `최근수업: YYYY-MM-DD` → 익일 세션이 자동으로 L0 재출제(1일 경과분), 이후 L2로 흡수(SRS 등록).
- 학기중 기본 = L0+L1, 시험기 = L2 비중 확대(deadline-aware #20). 안키(apkg)가 장기기억 주력, Claude SRS는 중단기 브리지 — 기존 #20 유지.
