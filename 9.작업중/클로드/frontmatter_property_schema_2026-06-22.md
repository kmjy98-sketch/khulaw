# Master Property Schema (frontmatter 표준)

> 문제: Obsidian Bases는 **정식 YAML frontmatter 프로퍼티만** 질의·정렬·필터한다. 현재 메타는 인라인 `과목::`·`주제::`·`속성::`에 흩어져 Bases에 안 보인다.
> 해결: 표준 YAML 키를 **추가**한다. 단 카드 파이프라인이 grep하는 인라인 `주제::`·`속성::`은 **유지(제거 금지)** — YAML과 병기.

## 1. 표준 키 (전 노트 공통)
| 키 | 타입(Bases 전역지정) | 값 예 | 비고 |
|---|---|---|---|
| `과목` | text | 민법/형법/헌법/민소/민집/상법/형소/행정/선택 | 필수 |
| `유형` | text | 정리노트/원문/쟁점/카드/사례/기출 | type |
| `쟁점` | list | [신의칙, 권리남용] | 핵심 논점 |
| `조문` | list | ["§103","§108"] | §10↑만(#35) |
| `판례` | list | ["대판 2013다26746"] | 사건번호(#34) |
| `회독` | number | 0,1,2,3 | 정본=진도_board와 일치(#19) |
| `중요도` | text | A/B/C | 또는 상/중/하 일관 |
| `상태` | text | 위키/작업중/보관/완료 | 상태머신 |
| `source` | text | 논점민법재산법-p31 | 출처 약칭-페이지(#14) |
| `tags` | list | (기존) | 발견용(주 구조 금지) |
| `aliases` | list | (기존) | |

## 2. Bases 전역 타입 지정(필수)
- `회독`=number, `조문`·`판례`·`쟁점`·`tags`=list, (SRS용) `due`=date, 나머지 text.
- 타입 불일치 시 정렬·필터 깨짐 → 과목 파일럿에서 타입 일관성 우선 검증.

## 3. 인라인 ↔ YAML 병기 원칙
- **카드 md**: 인라인 `과목::`·`속성::`·`주제::`·`난이도::`·`출처::` **그대로 유지**(build_v37·daily-drill grep 계약). 필요 시 frontmatter에 `과목/쟁점/source` YAML **추가**(겹쳐도 무해).
- **정리노트·쟁점·원문**: frontmatter YAML을 1차 메타로. 본문 인라인 dataview필드는 Bases 비가시이므로 표시·정렬 대상은 반드시 YAML로.

## 4. 적용 순서 (#17 파일럿 후 전체)
1. **1과목 파일럿** = 민법(1.민사) 정리노트 + sync/위키/원문 일부. YAML 추가(인라인 보존) → 타입 일관성·grep 무파손 확인.
2. **Bases 보드 1개** 파일럿: `sync/위키/원문/_원문논점보드.base`(이미 존재)에 과목/회독 필터 뷰 → 렌더 확인(사용자 GUI: Bases 코어 ON).
3. 통과 시 과목별 **포그라운드 병렬**로 확대(#45-B). 같은 파일 동시편집 금지(#45).

## 5. 안전
- frontmatter 추가는 **비파괴**(기존 인라인·본문 보존). 대량 적용 전 1청크 앞/뒤 직접 확인.
- 카드 파이프라인 grep 계약(`주제::` 등) 절대 제거 금지 — 제거 시 출제·빌드 마비.
