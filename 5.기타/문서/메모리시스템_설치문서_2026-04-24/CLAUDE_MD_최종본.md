## 1. 소스 및 근거 규칙 (#1~#9)

적용 범위: 사용자가 소스 자료를 제공한 모든 법학 학습·LEET·발제 작업

#1 Source Grounding: 모든 단정은 사용자 제공 소스에만 근거한다. 외부 지식·추측으로 답변하지 않는다.

#2 Not-in-Source + Uncertainty: 소스에서 확인할 수 없는 단정은 출력하지 않는다. "소스에서 확인할 수 없습니다" 또는 "자료 부족—보류"로 대체한다. 불확실한 경우에도 동일하게 적용한다. (구 #12 통합)

#3 Evidence Mandatory: 법리/사실 단정 시 근거를 명시한다 (발췌 "……" + 위치 《파일명》 p.X). 소크라틱 모드에서는 최종 답변 시에만 근거를 제공한다.

#4 No Fabricated Location: 위치를 추정하지 않는다. 불명확 시 "(확인 불가—위치 식별자 부족)".

#5 Original-Text Priority: 조문/판례 "원문"을 우선한다. 원문이 없으면 "(원문 미포함)" 명시.

#6 Integrity: 조문번호, 판례명/선고일의 정확성을 최우선한다. 불명확 시 [불명확: 후보1/후보2].

#7 COT Disclosure: 내부 추론 과정은 기본적으로 노출하지 않는다. 사용자 요청 시 간결히 설명한다.

#8 Output Minimalism: 요청 형식만 출력한다. 장문을 지양한다. 모든 답변은 한국어 (코드/인용/전문용어는 원어 병기 가능).

#9 PDF Handling: Claude API의 네이티브 PDF 지원을 사용한다. pypdf 로컬 전처리는 RAG 청킹/인덱싱 용도로만 사용한다.

## 4. 인용 (#14)

적용 범위: 법학 학습, LEET 문제 풀이

## 5. 파일 작업 원칙 (#15~#16)

#15 Verify-Before-Act + Checklist:
- 파일 이동/이름변경 전 해당 파일 내용 또는 메타데이터를 확인한다
- 워크플로우/스킬 수정 전 현재 내용을 읽는다
- 폴더 구조 작업 전 현재 상태를 확인한다
- 파일 2개 이상 변경 시 변경 목록(파일명+1줄 요약+순서)을 사전에 작성한다
- 확인 없이 추측으로 작업하지 않는다

#16 삭제 금지 원칙:
- 파일/폴더를 삭제하지 않는다. Remove-Item, del, rm, rmdir 등 삭제 명령을 사용하지 않는다
- 삭제 대신 `_trash/{YYYY-MM-DD}/` 하위 폴더로 이동한다
- 빈 폴더도 삭제하지 않는다. 정리 필요 시 사용자에게 먼저 확인한다
- 백업 파일은 sync 내부가 아닌 5.기타/ 하위에 저장한다
- 이 규칙은 항상 적용된다

## 11. 노트 정리 형식 (#32~#35)

적용 범위: 민법·형법·헌법 등 모든 과목의 사례형 답안 및 정리노트

#32 청구-항변 구조: 사례형 청구-항변 구조는 2열 표(원고|피고)로 정리한다. 트리거: 사용자가 사례문제를 풀거나 청구-항변 구조를 요청할 때 적용한다. 형식: `| **원고 (甲)** | **피고 (乙)** |` + 행 단위로 청구→항변→재항변 주고받기, 빈 셀은 `—`. 3열 표, 볼드 블록, 줄글형은 사용하지 않는다.

#33 모답형/보강포인트 배치: 사례형 답안 연습(모답형), 보강 포인트, 교차검증 결과 등은 해당 쟁점 섹션 안에 배치한다. 부록 성격(암기 문장, 시험 직전 접근순서, 판례 총정리표 등)은 별도 유지한다.

#34 판례 문구 원칙: 판례의 태도/입장을 기술할 때는 교재·판례 원문에 확인된 표현만 사용한다. 전사본이나 요약에서 온 비공식 표현은 교재 원문 표현으로 대체한다. 판례 사건번호를 함께 표기한다.

#35 백링크 규칙: 노트 내에서 판례, 조문, 핵심 개념에 옵시디언 스타일 백링크를 사용한다.
- 판례: [[대판 YYYY.M.DD, YYdaXXXX]] 또는 [[헌재 YYYY.M.DD, YYYYhunmaXXXX]]
- 조문: [[§XXX]] (§10 이상만. §1~§9는 섹션번호 오탐 방지를 위해 제외)
- 핵심 개념: [[선의취득]], [[물권적청구권]] 등
- 표·각주·코드블록 안에서는 백링크를 걸지 않는다
- 적용 범위: 정리노트, 압축본, 교재 추출본, wiki 아티클

## 12. 교수님 표현 및 외국어 (#36~#37)

#36 교수님 고유 표현 태그: 각 교수님만의 독특한 표현·용어는 [전경운], [서보학], [강혜림] 등 태그로 별도 표시한다. 적용 범위: 전 과목 정리노트 및 압축본.

#37 외국어 금지: 노트 본문에 라틴어·독일어·한자 등 외국어 표현을 사용하지 않는다. 한국어 대역만 기재한다. 교재 인용 시에도 한국어로 번역하여 기재한다.

## 13. Wiki 메모리 시스템 (#38~#41)

적용 범위: 모든 세션, 모든 과목

#38 세션 시작 시 Wiki 참조: 세션 시작 시 .auto-memory/wiki/_index.md를 읽고, 사용자의 질문과 관련된 아티클이 있으면 해당 아티클을 먼저 읽은 후 응답한다.
- _index.md가 없으면 MEMORY.md만 참조 (기존 동작 유지)
- _index.md는 25KB 이하로 유지한다
- 개별 wiki 아티클은 필요할 때만 읽는다 (전부 로드하지 않는다)
- wiki는 이전 세션의 작업 기록이므로 "사실"이 아닌 "참고"로 취급한다
- 교재 소스(#1)보다 wiki가 우선하지 않는다

#39 세션 종료 시 자동 기록: 세션에서 다음에 해당하는 내용이 있었으면 .auto-memory/session_logs/에 기록한다:
- 노트 수정/보강 작업의 결과 요약
- 새로 확인된 판례·학설·교수님 입장
- 사용자가 지적한 오류와 수정 내용
- 작업 중 발견한 교훈
- 기록 형식: session_{YYYY-MM-DD}_{HHMM}.md

#40 Wiki 아티클 원칙:
- wiki 아티클은 교재 소스(#1~#5)를 대체하지 않는다
- wiki에서 확인한 내용도 교재 원문과 대조 후 사용한다
- wiki 아티클 내 판례·조문은 반드시 소스 재확인한다
- wiki 아티클에 [[백링크]]를 사용한다 (#35 준수)
- wiki 아티클은 .auto-memory/wiki/ 폴더에만 저장한다

#41 정기 정비:
- "메모리 정비" 또는 "lint" 요청 시 → .agent/scripts/lint.py 실행
- "메모리 컴파일" 요청 시 → flush.py + compile.py 실행
- 오래된 아티클은 삭제하지 않고 _trash로 이동 (#16 준수)
- flush 완료된 세션 로그는 5.기타/세션로그_아카이브/로 이동 (삭제 아님)
- 증분 컴파일이 기본이고 --rebuild는 필요시에만 사용
- schedule 스킬로 주기적 정비를 자동화할 수 있다 (예: 매주 일요일 컴파일+lint)
