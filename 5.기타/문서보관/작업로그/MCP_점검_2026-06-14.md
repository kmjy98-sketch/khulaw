## §3. 미작동 원인 분석

서버 코드·환경은 **모두 정상**이었음:
- Python 3.13.14 설치됨, 의존성 전부 import 가능, `.env`의 `LAW_API_KEY` 유효(국가법령 API 검색 total=9 정상 응답), stdio 핸드셰이크 정상(stdout 깨끗, 배너는 stderr).

문제는 **MCP 런처의 프로세스 spawn 방식**. 데스크톱 로그에서 두 가지 실패를 확정:

1. **`spawn python ENOENT`** — `command:"python"`(맨 이름)일 때.
   `python`이 Microsoft Store **앱 실행 별칭**(`…\WindowsApps\python.exe`, reparse point)이라, Electron/Node가 이름으로 직접 exec하지 못함. (qmd는 `node`라 정상 → 차이의 근거.)

2. **`No module named 'src'`** — `command`를 python.exe **절대경로**로 바꾸자 spawn은 성공했으나, 런처가 설정의 **`cwd`를 적용하지 않아** `-m src.main`이 `src` 패키지를 못 찾음.
   부수적으로 `src/main.py`의 `load_dotenv()`도 cwd 의존이라, cwd 미적용 시 `.env`(API 키)도 로드 실패할 구조였음.

즉 **(별칭 spawn 불가) + (cwd 미적용)** 이중 원인. `cmd /c python` 래퍼나 `MCP_TIMEOUT` 연장으로는 해결 안 됨(각각 재현 검증).

※ 패키지 미설치·API 키 누락·버전 비호환·타임아웃은 **모두 아님**(개별 배제 검증 완료).

- 신규 헬퍼 `_normalize_text()`: 탭·과잉 공백만 정리. **문자(한자 포함)·의미 보존**(한자→한글 변환은 정확성 위험·anchor 한자 보존 원칙(#34)으로 **미적용**).
