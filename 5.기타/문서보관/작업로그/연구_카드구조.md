# 연구1 — 카드 구조 (전수 카드화를 위한 카드 단위·파싱·SCHEMA)

> 목적: '전수 카드화'(논점노트의 모든 항목을 빠짐없이 카드로)를 제대로 하기 위해 카드 구조·파싱을 어떻게 설계해야 하는가.
> 방법: 논점노트 원문 다양 샘플 + 현행 카드 정본(02_cards_v37) + 현행 카드생성 프롬프트(02-card v3.7) + 카드감사 결과를 읽고 분석. 모든 주장에 파일·인용 근거 부착(#1). 못 본 것은 '미확인'.

## 0. 핵심 진단 — '전수 카드화'는 현재 구조적으로 실패하고 있다

카드감사 전수 결과(`.agent/state/card_audit_summary.json`):
- 461/461 논점 감사 완료, **총 누락 1,867건**(원문에 있으나 카드 없는 항목).
- 민법 960건(논점당 평균 7.3건), 형법각론 399건, 형총 242건, 민소법 151건, 헌법 113건. 행정법은 카드 0(234논점 대량신규 필요).
- "카드없음" 논점만 30건(+행정 234).

즉 frontmatter에 `카드감사: 완료`로 찍힌 노트조차 논점당 평균 수 건~15건이 카드화되지 않았다. 예: 민법 [44] 임차권의 대항력 = 누락 15건, [42] 토지거래허가 = 11건, [43] 임대차계약 = 10건(`.agent/state/cardaudit/민법_41-45.md`).

**누락이 집중되는 위치(분석):**
1. **판례 나열**(`> 관련판례 ①②③…`, `○ …(대판 …)` 줄들) — 각 판례 명제가 별개 holding인데 일부만 카드화.
2. **표의 행/셀** — `<table>` 또는 마크다운 표의 개별 행이 통째로 누락(아래 1.②·2 참조).
3. **조문 원문 카드**(예: §21 조문 자체) — 정당방위 frontmatter `누락 14건` 첫 항목이 "§21 조문 카드"(`정당방위.md` line 8).

이 진단이 SCHEMA·파싱 제안의 출발점이다. **현행 02-card 프롬프트는 "coverage_rule"(line 399-402)·"카드감사" 개념을 갖고 있으나, 강제 메커니즘이 없어 LLM이 '중요해 보이는 것'만 뽑고 끝난다.** 전수 카드화의 핵심은 카드 SCHEMA가 아니라 **'원문 항목 → 카드'의 1:N 추적(누락0 게이트)** 이다.

## 2. 표 처리 (② 행별 카드 vs 통짜, 일부만 만드는 문제 방지)

### 현행 규칙(02-card `표_분해_규칙` line 224-258)
- "분해가능"(3행 미만) → 비교 cloze 1장.
- "행별카드+통합cloze"(3~7행) → 각 행 룰카드 + 통합 회상 cloze 1장.
- "행별카드만"(8행 이상) → 각 행 룰카드만(통합 overload 방지).
- `force_table_card: true` 시만 표 이미지/HTML 카드.

### 문제점(실측)
1. **위 규칙은 위키 입력에 `<!-- 속성: 표, 분해가능/… -->` 메모가 있을 때만 작동.** 그러나 현행 신규 노트는 그 메모를 안 쓴다(예 `매도인의 담보책임.md`·`처분권주의.md`는 `<table>`만 있고 분해메모 없음). → 분기 트리거 미발동 → 표가 통째 누락되거나 일부만.
2. **다차원 매트릭스(학설×효과)는 "행별카드"로 부족.** 위전착 표는 행=학설, 열=4축(법조·효과·악의가담자·정당방위)이라 셀 교차값(예 "법효과제한책임설 + 악의가담자 의사지배 → 간접정범○")이 핵심인데, 행 단위 카드로는 열 축 정보가 뭉개진다.
3. **셀 안 판례 누락.** 매도인담보 표 셀에 판례가 박혀 있음(line 43 대판 73다268, line 53 대판 2002다33557 등) → 행 카드만 만들면 셀 내부 판례 holding 누락.

### 제안(표 → 카드 규칙 개정안)
- **표는 먼저 "셀 단위 명제 목록"으로 파싱한다**(행×열 그리드를 (행키, 열키, 값) 트리플로 평탄화). 누락 방지의 1차 단위는 행이 아니라 **채워진 셀**.
- 표 차원 판정:
  - **1차원 비교표**(구분 1열 + 값 1~2열, ≤3행): 비교 cloze 1장(현행 유지).
  - **2차원 매트릭스**(행키 + 값 + 다열): ① **행별 카드**(행키 → 그 행의 핵심 효과) + ② **열축별 교차 카드**(예 "위전착 + 법효과제한책임설 + 악의가담자에 의사지배 있으면? → 간접정범"). 교차 카드를 만들지 않으면 매트릭스의 학습가치 손실.
  - **셀 내부 판례·조문**: 표 파싱 시 셀 텍스트에서 `[[대판 …]]`·`§\d+`·`제\d+조`를 추출해 **각각 별도 판례/조문 카드 후보로 등록**(셀 카드에 묻어두지 않음).
- **force_table_card 자동화**: enum 시각회상이 핵심인 표(변형결정 6종, 담보책임 유형 8종 등)는 행 카드 + 통합 enum 회상 카드(8행 이상이라도 enum은 통합 1장 허용 — "담보책임 8유형 열거")를 추가.
- **일부만 만드는 문제 방지(핵심)**: 표를 파싱한 (행,열,값) 트리플 전수를 **체크리스트로 출력**하고, 각 트리플이 ≥1 카드로 매핑됐는지 카드생성 직후 자기대조. 미매핑 셀은 `누락:표셀` 마커. (현행 카드감사가 사후에 잡아내는 것을 생성 시점으로 당김.)

## 3. 요건 묶기 (③ 요건 세트=1카드 vs 요건당 1카드, 묶음 기준)

### 현행 규칙
- `rule_schema`(02-card line 148-155): Card1 룰명→요건 전체 열거(**앞면에 개수 명시 필수**), Card2 요건→효과, Card3 overlapping cloze(요건별 원자 빈칸), Card4 룰명→예외.
- `MIP`(line 269)·`overlapping`(line 270): 요건 3개 이상이면 통짜 서술회상 금지, **반드시 개별 원자 카드 또는 overlapping cloze**.
- `anti_fragmentation`(line 271-277): 독립회상 불가·단독무의미·답안에서 항상 결합되는 요소는 분리 금지.
- 실측 카드(`강성민OX1_…_v37.md` line 66-74): 직장선택자유 3요건 = "(3요건)" 앞면 명시 + `①{{c1::}}②{{c2::}}③{{c3::}}` cloze 1장. **세트형 표준 패턴 확인.**

### 묶음 기준(샘플 기반 정리)
- **요건 세트 = 1장(개수명시) + overlapping cloze 1장**을 기본 쌍으로 한다. 정당방위 4요건(`정당방위.md` line 37)·상당성 4요건(line 86-92)이 이 형태.
- **요건당 1카드 분할은 다음일 때만**: 각 요건이 그 자체로 독립 쟁점이고 하위 판례/예외를 갖는 경우(예 정당방위 "침해의 현재성"은 line 43-48에 별도 판례 2건 → 현재성 단독 카드 + 그 판례 카드).
- **분리 금지(anti_fragmentation 적용)**: "방위의사" 같은 단독 무의미 키워드, 답안에서 항상 4개 함께 쓰는 상당성 요소.
- **연구 권고(SKILL 1-B, line 26-31)**: 원자 cloze만 하면 far-transfer 약화 → 요건 세트는 원자 cloze + **상위 종합/IRAC 카드 병행**. 간섭 큰 인접요건(정당방위 vs 긴급피난 vs 자구행위)은 **명시적 대조 단서** 카드 추가.

### 제안(요건 묶음 결정 트리)
1. 요건 N개 추출 → 세트 카드(개수명시) + overlapping cloze 1장 **항상 생성**.
2. 요건 e_i가 독립 판례/예외/학설을 가짐 → e_i 단독 카드 + 그 부속 카드.
3. 인접 유사 룰(같은 장 안 다른 위법성조각사유 등) → 대조표 카드 1장.
→ 전수성 관점: "요건 세트를 1장으로 끝내면" 요건 부속 판례가 누락된다(정당방위 누락 14건 중 다수가 요건 부속 판례). **요건 세트 카드는 요건 부속 항목 카드화의 면죄부가 아니다.**

### 현행 파이프라인
- OCR(LlamaParse) → `outputs/01_ocr_llamaparse/` → 위키화(02-wiki) → 쟁점노트(`sync/위키/{과목}/`) → 02-card → `outputs/02_cards_v37/` → `build_v37_apkg.py` → apkg(`10_v37_apkg_빌드_파이프라인.md`).
- 빌더 파서(빌드 doc line 13): 블록구분 `^#{2,6} ` 헤더 또는 `카드 N`, 필드 = 앞/뒤/빈칸/Text. **빌더는 '이미 카드로 쪼개진 md'를 읽을 뿐, 원문→카드 분해는 LLM(02-card)이 한다.**

### 파싱이 필요한 이유(전수성)
현행은 LLM이 원문을 통독하고 카드를 '생성'한다 — 이 과정이 누락의 원인(LLM이 항목을 빠뜨려도 검출 안 됨). **결정적 1차 분해(파싱) + LLM 카드화 + 누락 대조**의 3단 구조가 필요(#45-B 에이전트-코드 분기: '판단'은 LLM, '전수 분해·대조'는 결정적).

### 제안 파싱 단위(원문 마크다운 → 항목 인벤토리)
쟁점노트 md를 다음 규칙으로 **'카드 후보 항목(atom)'** 으로 평탄화(결정적 추출, 최종 채택은 LLM #50-C):
- **블록 마커별 atom 경계**:
  - `○ …` 줄 = 1 atom(형총·형각 판례/법리 줄. `정당방위.md`·`절도·강도의 죄수관계.md` 표준).
  - `* [라벨] …` / `* …(대판 …)` 줄 = 1 atom(민법 송영곤 노트 표준. `매도인의 담보책임.md`·`침해부당이득.md`).
  - `> 관련판례 ①②③` 안의 각 번호 = 각 atom.
  - 표의 각 채워진 셀(또는 행) = atom(2 참조).
  - 조문 인용 블록(`> §… ` / `제\d+조【…】`) = atom(조문 카드).
  - `[CASE]`/`☞ [CASE]` 블록 = 1 atom(사례형, 비분해).
  - `①②③…`/`㉠㉡㉢…` 열거 = 각 항을 atom 또는 묶어 overlapping(요건이면 3 참조).
- **각 atom에 anchor 추출**: `[[대판 YYYY.M.DD, …]]`·`§\d+`·`제\d+조`·학설명. → 판례/조문 카드 후보로 별도 등록(셀·줄에 묻지 않음).
- **atom 인벤토리를 파일로 출력**(논점별 `atom_id` 목록) → 카드 생성 후 `atom_id ↔ note_key` 매핑표로 **누락0 대조**(#45-C 재개가능 검증 fan-out의 완료마커와 동일 사상).

### 주의(이미 학습된 교훈)
- 정규식 단독 신뢰 금지(#50-C): atom 경계는 정규식으로 1차 후보, **최종 경계·묶음은 LLM 의미판단**.
- 마커 단일성: 빈칸은 `{{cN::}}`만(08 §0, 빌드doc line 29). 전각괄호·대괄호 빈칸 금지(레거시 949장 누락 사고).
- 판권지·색인 페이지 제외(02-card line 69 absolute_prohibitions).
- anchor(사건번호·조문·한자) 임의생성·교정 금지(#6·#34).

## 5. 제안 카드 SCHEMA (⑤ 필드·단위·표/요건 규칙)

> 현행 v3.7 schema(rule/case_law/cloze/mcq/precursor/사례형/학설)를 유지하되, **전수성·추적성·표/요건 규칙을 보강**. 출력 포맷은 v3.7 `output_format_lock`(앞:/뒤:/빈칸: + `### [속성] 소제목`) 그대로 — 빌더 호환 필수.

### 5.1 공통 추가 필드 (모든 카드)
- `atom_id`: 원문 항목 식별자(`{논점}::{블록경로}::{seq}`). 파싱 atom과 1:1 추적용. **전수 카드화의 핵심 필드.**
- `note_key`: 안정 키(`{key}::{card_type}::{seq}`, card-wiki-pipeline §8.1). 내용 바뀌어도 불변.
- `source`/`출처`: `{책약어}-p{N}`(line 164).
- `검증`: 완료/anchor확인/원문확인필요/판례확인필요/조문확인필요/보류(SKILL §7).
- 태그 2축 필수: `과목:: 속성:: 주제::`(+난이도·출처·기출·검증) (tag_schema line 348-397).

### 5.3 표/요건 규칙 요약(생성기 강제 규칙)
- **R1 전수 우선(보존>생성)**: 02-card top_priority(line 46-49) 유지. "좋은 카드보다 누락 없는 카드."
- **R2 atom 인벤토리 의무**: 카드 생성 전 원문→atom 평탄화, 생성 후 atom↔note_key 매핑·미매핑(누락) 보고. coverage_rule(line 399)을 **강제 게이트**로 격상.
- **R3 표 셀 전수**: 채워진 셀 전부 ≥1 카드. 셀내 anchor 별 atom.
- **R4 요건 세트 비면죄**: 세트 카드가 요건 부속 판례·예외 카드화를 면제하지 않음.
- **R5 마커 단일성·anchor 보존**: `{{cN::}}`만, 사건번호·조문·한자→한글 보존(08·#34·#37).
- **R6 검수 게이트(human-in-loop)**: LLM 카드 12결함(SKILL 1-B) → 배포 전 사람 검수. 파일럿 1청크 후 전량(CLAUDE.md #17 주의).

### 5.4 전수 카드화 게이트(통합) — '카드감사'를 생성 루프에 내장
현재는 카드 생성과 카드감사가 분리(사후 1,867건 적발). 제안:
1. 파싱: 논점 md → atom 인벤토리(파일).
2. 카드화: atom별 LLM 카드 생성(병렬, #45-C).
3. 대조: atom_id ↔ note_key 매핑 자동집계 → 미매핑 = 누락. `_cardaudit_agg.py`/`card_audit_*.md` 형식 재사용.
4. frontmatter `카드감사: 완료 (누락 N건: …)` 자동 기입(현행 노트가 이미 이 필드를 가짐 → 사상 일치).
5. 누락>임계면 보류·보고(검증자 권한, #45-C). 자동수정·이동·삭제 금지.
