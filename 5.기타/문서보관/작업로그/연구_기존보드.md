## 2. ① 정보 계층 (과목 > 중분류 > 소단원)

### 2.1 계층 정의 위치
- 전 계층은 HTML 안 `const BOARD={...}` JS 객체에 하드코딩되어 있다(#진도_board.html:94-104). 구조:
```
BOARD = { 과목: { 중분류: [ 소단원, 소단원, ... ], ... }, ... }
```
- 과목 목록 `ALL`은 BOARD 키 순서: 민법 / 민사소송법 / 민사집행법 / 상법 / 형법 / 형사소송법 / 헌법 / 행정법 / 선택법 (총 9과목, #진도_board.html:105).
- 과목별 단원 수(집계 근거 `.agent/state/진도_현황.json`): 민법 39 · 민사소송법 20 · 민사집행법 15 · 상법 34 · 형법 17 · 형사소송법 22 · 헌법 19 · 행정법 35 · 선택법 1 = **전체 202단원**(#진도_현황.json:6-97).

### 2.2 단원 키 구조 (핵심)
- **단원 1개 = `"과목|중분류|소단원"` 형태의 파이프 구분 문자열**이 곧 유일 키다(#진도_board.html:109-110).
  - 예: `"민사소송법|소송주체|법원·관할"` (#진도_state.json:4).
- `VALID` Set이 BOARD에서 전 단원키를 펼쳐 보관하고, import/hydrate 시 이 Set에 없는 키는 모두 버린다(`filter(k=>VALID.has(k))`, #진도_board.html:109, 121, 215, 359-360). → BOARD 목차가 단원 키의 단일 진실원이다.
- 상태 저장(st/sel/cas/rec)·내신/방학 단원 리스트·로그 모두 이 동일 키를 쓴다 → 4축이 같은 단원키 위에 겹쳐 쌓이는 구조(#진도_board.html:95-115).

### 2.3 렌더링 시 계층 표현
- 과목 = `.subj` 헤더(밑줄 강조), 중분류 = 행 좌측 `.axis` 라벨, 소단원 = `.cell` 묶음. 한 중분류 = 한 행(`.mrow`), 행 안에 그 중분류 소단원 셀들이 wrap 그리드로 배치(#진도_board.html:165-186, CSS 27-33).
- 비편집(통계) 모드의 중분류 라벨은 진척 요약을 함께 보여준다: `중분류 [done/총 · 평균회독 · 선S·사C·기G]`(#진도_board.html:173).

## 3. ② 축(회독/선택/사례/기록) 동작

### 3.1 모드 = 4축
- 상단 "기록:" 옆 토글 버튼 4개: `["회독","선택","사례","기록"]`(#진도_board.html:149). 현재 모드만 색으로 칠해지고 클릭이 그 모드를 증감한다.
- 상태 저장소가 축마다 분리됨(#진도_board.html:107, 111-115):
  - 회독 `st` (localStorage 키 `jindo2_state`)
  - 선택 `sel` (`jindo5_sel`)
  - 사례 `cas` (`jindo5_cas`)
  - 기록 `rec` (`jindo5_rec`)
  - `PROB={"선택":sel,"사례":cas,"기록":rec}` 로 문제축 3종을 묶음(#진도_board.html:115).

### 3.2 클릭 증감 규칙
- **셀 좌클릭 = 현재 모드 +1, Shift+클릭 또는 우클릭 = −1**(#진도_board.html:178, 사용법 50행).
- 증감 함수 `bump(k,d)`(#진도_board.html:197):
  - **회독**: `st[k]=((st[k]||0)+d+6)%6` → **0↔5 순환**(5에서 +1 하면 0으로 돌아감). 6단계(0,1,2,3,4,5).
  - **선택/사례/기록**: `o[k]=Math.max(0,(o[k]||0)+d)` → **0 이상 무한 누적**(상한 없음).
- 매 클릭마다 타임스탬프 + 7-튜플 로그를 push: `[시각, 과목, 중분류, 소단원, 종류, 값, 증감]`, 최대 3000개 유지(#진도_board.html:197).

### 3.3 색상 표현 (시각 인코딩)
- 회독 색: `COL` 6단계 녹색 그라데이션(0=카드색, 1~5 점점 진하게)(#진도_board.html:127, 190-191).
- 문제(선/사/기) 색: 값을 `ptier()`로 구간화 후 `COL2` 6단계 주황 그라데이션. 구간: `0 / 1~2 / 3~5 / 6~10 / 11~20 / 21+`(#진도_board.html:132, 192).
- 셀 안 텍스트: 회독 N회 + 문제 배지 `선N 사N 기N`(0인 축은 생략)(#진도_board.html:193-194). → 현재 모드 색으로 칠해지되, 다른 축 누적치도 배지로 항상 보임.

### 3.4 목표 탭 (렌즈)
- 상단 탭 `["전체","방학","내신","변시"]`(#진도_board.html:126, 147). 같은 데이터를 거르는 "렌즈"이며 데이터 자체는 안 바뀐다(사용법 51행).
  - **전체 / 변시**: 전 단원 표시(필터 없음, `viewSet()` null 반환, #진도_board.html:135).
  - **방학**: `banghakU` 단원 집합만 표시. 현재 100단원 담겨 있음(민법·민소법·형법각론·행정법 위주, #진도_state.json:24-125, 방학단원수 100 #진도_현황.json:107).
  - **내신**: 학기(1-1~3-2)별로 따로 담아 누적. `naesinSem` 객체, `[누적]`은 전 학기 합산 보기(편집 불가)(#진도_board.html:106, 133, 157). 현재 전 학기 0단원(#진도_state.json:16-23).

### 3.5 편집(담기) 모드 — "큰 단위 담기"
- 방학·내신 탭에서 `[단원 편집]` 토글 시 셀이 ✓/+ 표시로 바뀌고 클릭이 담기/빼기로 동작(#진도_board.html:177, 195).
- **일괄 담기**: 편집 중 **과목 헤더 클릭 = 그 과목 전체 토글**, **중분류 라벨 클릭 = 그 중분류 전체 토글**(`bulkSel`, 모두 담겨있으면 빼고 아니면 담음, #진도_board.html:142, 172, 183). → "형법은 담되 특별형법만 빼기" 식 빠른 담기 가능(사용법 52행).

## 4. ③ 사용성 장점 (왜 보기 편한가)

조사로 확인된, 사용자가 "더 낫다"고 평가했을 구조적 특성:

1. **한눈 그리드(전 과목 동시)**: 9과목 202단원이 한 페이지에 펼쳐져, 스크롤만으로 전체 진도를 색으로 스캔할 수 있다. 셀 색 = 회독 단계, 배지 = 문제 누적(#진도_board.html:165-194). → 별도 페이지 이동 없이 "어디가 비었나"가 즉시 보인다.

2. **클릭 증가(저마찰 입력)**: 단원 셀을 좌클릭만 하면 +1, 우클릭/Shift로 −1. 폼·저장 버튼 없이 클릭=기록(#진도_board.html:178). 서버 모드에서는 그 클릭이 즉시 디스크에 남는다(#진도_board.html:256).

3. **4축이 한 셀에 겹침**: 회독·선택·사례·기록을 단원 단위로 한 자리에서 본다. 모드 전환만으로 같은 그리드를 다른 축으로 색칠(#진도_board.html:151, 190-194). → 단원별로 "읽었나/문제 풀었나/사례 썼나/기록형 썼나"를 한 곳에서 파악.

4. **상단 통계 바(현재 렌즈 기준 실시간)**: 대상 단원수·평균 회독·완료율·선택/사례/기록 합계·진척 게이지 바·최종 저장시각을 항상 상단에 표시. 탭(렌즈)을 바꾸면 그 범위로 재집계(#진도_board.html:68-77, 198-205).

5. **목표 렌즈(전체/방학/내신/변시)**: 같은 데이터를 시험 목표별로 걸러 본다. 데이터를 복제하지 않고 보기만 바꿈(#진도_board.html:135, 사용법 51행).

6. **큰 단위 일괄 담기**: 과목/중분류 헤더 클릭으로 수십 단원을 한 번에 담고, 예외만 따로 뺀다(#진도_board.html:142, 172, 183). → 방학·내신 범위 설정이 빠르다.

7. **서버 모드 부가 패널(약점·시험일)**: 서버로 열면 보드 신호 기반 약점에 빨간 테두리, 약점/SRS/시험일 패널이 보드 하단에 자동 추가됨(#진도_board.html:259-354). 학습 루프(약점·복습)와 진도보드가 한 화면에서 연결된다.

8. **저장 투명성**: `[저장 환경 보기]`로 저장 방식·경로·단원 카운트·도메인 용량을 표로 확인, file:// 일 때 백업 경고를 띄움(#진도_board.html:218-231).

## 5. ④ 데이터 흐름 (클릭 → state → ingest → drill)

### 5.1 클릭 → JS 상태 → 디스크 (서버 모드)
1. 셀 클릭 → `bump(k,d)` → `st`/`PROB[mode]` 갱신 + 로그 push + `saveAll()`(localStorage) + `render()`(#진도_board.html:197).
2. 서버연동 래퍼가 `bump`를 감싸 클릭 후 `pushLog()`(`/api/log`) + `scheduleSave()` 호출(#진도_board.html:256).
3. `scheduleSave()`는 350ms 디바운스 후 전체 스냅샷을 `/api/save` POST(#진도_board.html:252-254). 스냅샷 형태(#진도_board.html:253):
```
{updated, 회독, 선택, 사례, 기록, 내신_학기별, 방학_단원, 기록로그}
```

### 5.2 서버 쓰기 산출물 (board_server.py `write_state`)
`POST /api/save` → `write_state(state)`가 한 번에 여러 파일을 갱신(#board_server.py:401-403, 137-214):
- `백업/진도_state.json` — 전체 상태 스냅샷(브라우저 캐시 소실 대비)(#board_server.py:39, 139).
- `백업/진도_board_export_latest.json` — `_ingest_jindo.py` 호환 내보내기 형식(#board_server.py:41, 141-146).
- `.agent/state/진도_현황.json` — 기계용 단원별 집계 + 요약 + 최근로그(#board_server.py:42, refresh_hyunhwang 157-191).
- `6.진도관리/진도_현황.md` — 사람용 표(전체/과목별/내신/방학/최근로그)(#board_server.py:43, 194-205).
- `.agent/state/progress.json` 의 `"보드연동"` 블록 — 과목별 평균회독·완료율·선택·사례·기록 요약(기존 구조 보존, #board_server.py:44, 207-214).
- `백업/진도_log.jsonl` — `/api/log` append-only 1클릭=1줄(#board_server.py:40, 150-153, 407-409).

### 5.3 부팅 시 역방향 하이드레이트
- 서버 모드 부팅 시 `GET /api/state`(`read_state()`)로 디스크 상태를 읽어 JS 상태를 덮어쓴 뒤 재렌더(#진도_board.html:357-364, board_server.py:388-389).
- `read_state()`는 `진도_state.json`에 데이터가 없으면 백업 폴더의 다른 export JSON을 mtime 최신으로 시드한다(#board_server.py:97-134).
→ **단일 진실원은 디스크(백업/진도_state.json)**, 브라우저는 그 뷰. localStorage는 file:// 폴백.

### 5.4 오프라인 ingest (서버 없이)
- `_ingest_jindo.py`는 보드 `[JSON 내보내기]` 파일(`6.진도관리/백업/` 또는 `6.진도관리/`)을 자동 탐색(mtime 최신)하여 `진도_현황.json` / `진도_현황.md` / `progress.json` 보드연동 블록을 생성(#_ingest_jindo.py:31-43, 46-115).
- 즉, board_server.refresh_hyunhwang 과 _ingest_jindo.main 은 **동일 집계 로직의 두 경로**(서버 자동 / 수동 export 반영). 산출 파일·키가 같다(#board_server.py:157-214 ↔ #_ingest_jindo.py:46-110).

### 5.5 외부(드릴)→보드 역반영 경로
- 서버에 `POST /api/bump`(또는 CLI `--bump`)가 있어, 드릴 등 외부 활동을 보드 카운트에 +1 반영할 수 있다. 보드 클릭과 동일한 7-튜플 로그를 남기고 디스크 저장(#board_server.py:268-293, 424-431, 483-493).
- 약점 연동: `GET /api/weak`는 `.agent/state/learning.json`의 `weak_points` + SRS 임박을 반환, `POST /api/weak`는 보드 신호(사례≥2&회독≤1 등) 후보를 weak_points에 추가(append-only)(#board_server.py:218-260, 390-391, 413-423; 보드측 신호계산 #진도_board.html:262-267).
- 시험일: `GET/POST /api/exams`로 learning.json의 `exams`(과목·날짜·D-day) 관리, 보드 시험일 패널과 연동(#board_server.py:297-354, 392-393; 보드측 #진도_board.html:321-354).

→ **데이터 흐름 요지**: 클릭 → state.json(정본) → (집계) 진도_현황.json/md·progress.json → drill/약점/SRS는 learning.json을 매개로 보드와 양방향 연결. "drill→보드"는 /api/bump, "약점→보드"는 /api/weak, "보드→약점"은 보드 신호 후보 추가.

## 7. 재설계 시 보존해야 할 핵심 (체크리스트)

이 보드가 "더 낫다"는 평가의 근거가 된 요소 — 재설계 기준선:

- [보존] 단원키 = `"과목|중분류|소단원"` 파이프 문자열, BOARD가 단일 진실원, VALID 필터(#진도_board.html:109-110).
- [보존] 3단 계층의 한눈 그리드(과목 헤더 / 중분류 행 / 소단원 셀)(#진도_board.html:165-186).
- [보존] 4축(회독 0~5순환 / 선택·사례·기록 누적) + 모드 전환 색칠 + 셀 배지(#진도_board.html:190-197).
- [보존] 클릭 증감(좌+1, 우/Shift−1)의 저마찰 입력(#진도_board.html:178, 197).
- [보존] 목표 렌즈(전체/방학/내신/변시), 큰 단위 일괄 담기(과목/중분류 헤더 클릭)(#진도_board.html:135, 142, 172, 183).
- [보존] 상단 실시간 통계 바(렌즈 기준 재집계)(#진도_board.html:68-77, 198-205).
- [보존] 서버 모드의 디스크 자동저장 + 다중 산출(state.json/현황.json/현황.md/progress.json/log.jsonl)(#board_server.py:137-214).
- [보존] 점진적 향상(file://도 동작, http면 부가기능) 구조(#진도_board.html:236-247).
- [보존] 약점·SRS·시험일 패널이 진도보드와 한 화면에서 연결(#진도_board.html:259-365, board_server.py:218-354).

## 8. 미확인 / 한계

- 사용자가 "서버 보드가 더 낫다"고 한 **발언의 원문 출처**는 본 조사 파일들에서는 확인되지 않음(코드/데이터만 조사). 본 문서는 "서버 모드"가 file:// 모드보다 기능이 많다는 코드 사실(#진도_board.html:236-365)에 근거해 그 구조를 정리한 것이며, 사용자 평가 맥락 자체는 미확인.
- `learning.json`(약점·SRS·exams 원본)은 본 조사 대상에 없어 내용 미확인 — board_server가 읽고 쓰는 스키마(weak_points / srs.items / exams)만 코드에서 확인(#board_server.py:218-354).
- file:// 모드에서 localStorage 마이그레이션(구 키 `jindo3/4/5_*` → 신 키)이 있으나(#진도_board.html:113, 120, 124), 실제 잔존 데이터는 브라우저 종속이라 파일로 확인 불가 — 미확인.
