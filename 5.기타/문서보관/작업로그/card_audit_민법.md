## 3. 품질 이슈

### 3-1. 앞/뒤/빈칸 정형성 — 혼재(파일별 상이)

카드 구조 형식이 파일마다 다르며 통일 미흡:

| 파일군 | 형식 |
|---|---|
| 쟁점노트_재산법 p001-030 | `앞:` / `뒤:` / `빈칸:` / `태그:` (구버전 단순형) |
| 쟁점노트_재산법 p241-270 | `**앞면**` / `**뒷면**` / `**빈칸**` (마크다운 볼드형) |
| 쟁점노트_재산법 p271-300 | `- 앞:` / `- 뒤:` / `- 빈칸:` (리스트형) |
| 쟁점노트_재산법 p301-330 | `**앞면**` / `**뒷면**` / `**빈칸**` + 빈칸에 `①체언` 등 이상 기재 |
| 신민사법선택형 전체 | `앞:` / `뒤:` / `빈칸:` 또는 cloze `{{c1::}}` 혼용 |

**이슈 1 — cloze 형식 혼용**: 신민사법선택형 파일에서 `{{c1::}}` 형식(Anki cloze 표준)과 `{{단어}}` 형식(독자 빈칸형)이 혼용됨.
- 예시: `신민사법선택형_가족법_llamaparse_p031-060` 라인 27: `재판상 이혼이 된 경우에는 {{c1::조건 불성취}}로 {{c2::효력이 발생하지 않는다}}`
- vs 쟁점노트 라인 36: `빈칸: ①불법행위에 기한 손해배상청구권 / ②상속능력 / ③유증`
- 이 두 형식은 동일 apkg 빌드 파이프라인에서 처리 방식이 달라야 하므로 변환 오류 위험.

**이슈 2 — p301-330 빈칸 오기**: `outputs/02_cards_v37/쟁점노트_재산법_llamaparse_p301-330_암기장_v37.md` 라인 25:
```
빈칸: ①체언 ②체언 — 조사 미포함
```
빈칸 내용이 실제 답(`①법령 / ②임의`)이 아니라 문법 힌트(`체언`)로 대체됨 → 카드로서 기능 불가.

### 3-2. 내용 원문 일치 — 대체로 양호, 일부 왜곡

**판례번호 정확성**: 확인 샘플 범위에서 오류 미발견. 단 일부 판례번호는 초안 생성 시점 OCR 오류 가능성 있음(실시간 검증 대상).

**이슈 3 — 논점 번호 헤더 비일관**: 논점 60이 `쟁점노트_재산법_llamaparse_p241-270`(H1: `# 논점 60`)과 `p271-300`(H2: `## [논점 60]`) 두 파일에 중복 분산됨.
- 원인: p241-270 마지막에 논점 60 시작 → p271-300에도 이어짐
- 결과: 논점 60 카드가 두 파일에 분산, 논점 번호 중복 집계 가능

**이슈 4 — 헤더 형식 3종**: `## 논점 NN`, `## [논점NN]`, `# 논점 NN` 세 형식 병존. Anki 카드빌더가 논점 단위 분리를 헤더 기준으로 처리할 경우 H1/H2 구분에서 오류 발생 가능.

**이슈 5 — 물권 영역 논점 번호 헤더 전무**: `신민사법선택형_물권`, `신민사법선택형_물적담보`, `신민사법선택형_인적담보` 파일 전체에 MOC 논점 번호([85]~[122])에 해당하는 헤더가 없고 주제별로만 분산. MOC-카드 추적성 없음.

### 3-3. cloze 적절성

- 쟁점노트 파일: `{{단어}}` 형식 — 핵심 법리 단어를 빈칸 처리하여 대체로 적절
- 신민사법선택형 파일: `{{c1::}}` cloze 형식 — 문장 내 핵심 어구를 빈칸 처리, 맥락 충분
- 문제: 일부 카드에서 빈칸이 지나치게 짧은 단어(조사 포함)를 채우는 구조. 예시:
