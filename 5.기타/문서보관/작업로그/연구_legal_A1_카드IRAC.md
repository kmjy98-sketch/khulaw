## 1. 각 스킬의 핵심 기법·구조

### 1.1 `flashcards` (블랙레터 암기 카드 생성·드릴)

- **목적 분리**(line 35): "Outlines are for synthesis; flashcards are for memorization." 아웃라인(종합) ≠ 카드(암기). 카드는 **빠른 룰 회상(fast rule recall)** 전용.
- **명시적 비-SRS 선언**(line 37): "Not a full SRS system." Leitner 4버킷(new→learning→review→mastered)만. "Anki 쓰려면 Anki 써라 — 이건 채팅 중 빠른 드릴용."
- **모드 라우팅**(line 15-20): `--generate / --drill / --review / --stats / --session <n>`.
- **카드 구조**(line 89-98): `Q / A / Source / Bucket / Last reviewed / Next review / Notes`. **모든 카드에 Source 필드 고정**(아웃라인 절·케이스북 페이지·수업노트 날짜).
- **카드 작성 4원칙**(line 100-104): ① 카드당 1개념("Elements of negligence"는 1장이 아니라 4장) ② 앞면은 질문(주제 아님) ③ 뒷면은 룰(문단 아님 — 문단이면 쪼개라) ④ 출처 인용.
- **Leitner 채점 테이블**(line 122-127): right=버킷+1·간격 1d/3d/7d/21d, partial=동일버킷·+1d, wrong/don't know=버킷−1·당일+4h. (SM-2/FSRS 아님 — 고정 간격.)
- **세션 우선순위**(line 110-113): 기한 도래 due > 새 카드 > (없으면) 마스터 카드 decay 방지 복습.
- **session 결과 적재**(line 66-78): `study-plan.yaml`의 `session_history`에 right/partial/wrong/stuck_topics 누적.
- **stats의 stuck 탐지**(line 135): `new`로 2회 초과 강등된 카드 = '막힌 개념' → 구두 드릴(`socratic-drill`)로 라우팅.
- **신뢰 규율(confidence discipline)**(line 39-45, 106): 소스 없이 생성한 카드는 룰마다 `[VERIFY: rule — confirm against source]` 플래그. "8개 좋은 카드 > 20개 중 5개 틀린 카드." **개수 채우기 금지**(line 156).
- **데이터 흐름**: 소스(아웃라인/노트/케이스북) → `--generate` → `flashcards/[subject]/cards.md`(과목당 1파일, 인라인 메타) → `--drill`(버킷·next review 갱신) → `--stats`(stuck → socratic-drill).
- **데이터 한계 자인**(line 151): ">500 카드엔 부적합." 대규모 덱은 비대상.
- **Real-matter check**(line 27-31): 실제 사건(실명·실제 마감·금액)이면 카드/조언 생성 거부 — 미인가 법률조언 차단 가드. (우리에 없는 안전축.)

### 1.2 `irac-practice` (IRAC 에세이 구조 채점)

- **본질 = 구조 채점**(line 32, 34): 학생이 쓴 IRAC 답안을 **채점만** 한다. "Does not rewrite the essay. Ever." 모범답안도 안 보여준다(line 176) — 학생이 머릿속에 모델을 세우게.
- **2모드**(line 53-56): ① 학생제공 hypo+답안 ② 스킬생성 hypo+학생답안.
- **IRAC 4성분 매핑 채점**(line 62-68):
  - **Issue**: 스폿한 쟁점 / 놓친 쟁점 / 오인 쟁점.
  - **Rule**: 쟁점별 룰 (a)존재 (b)정확 (c)완전.
  - **Application**: "룰을 사실에 적용했나, 아니면 룰+사실을 나열만 했나" — **판정 테스트 = 'because/here' 같은 매핑 언어가 있는가**(line 66).
  - **Conclusion**: 도달했나, 질문(call)에 응답하나.
  - **Organization**: IRAC/CRAC 순서·토픽문장·문단.
- **출력 포맷**(line 74-140): 쟁점(spotted/missed/mis-identified) → 룰 정확성(쟁점별 정확/부분/오류/누락 + `[VERIFY]`) → 분석(쟁점별 "적용했나" 판정 + 못했으면 구체 지시) → 조직 → **등급 밴드(Pass/borderline/not yet — 숫자점수 금지, line 177)** → **Top 3 수정** → 인용검증 경고.
- **패턴 추적(장기가치)**(line 142-159): 세션마다 `tracker.md`에 [놓친쟁점·룰정확성·분석갭·조직] 적재 → **3세션+ 누적 시 패턴 표출**("3연속 반론 누락", "Issue+Rule은 강한데 Application이 일관 약점"). "한 번 피드백은 한 에세이를 돕고, 패턴 피드백은 공부법을 바꾼다."
- **노출 통제**(line 130-139, 174): 모범답안·전면 재작성 금지. **라벨된 예시문장 1~2개만** 허용하되 **학생의 실제 쟁점/주제로는 절대 금지**(다른 분야·추상 플레이스홀더로만 — "정답 건네주기" 방지).
- **신뢰 규율 차등**(line 38-42): 구조 채점=확신(structure is structure) / 쟁점콜=명백하면 확신·논쟁적이면 `[UNCERTAIN]` / 룰정확성=`[VERIFY]` / 모르는 관할·분야면 **구조만 채점하고 그렇게 명시**.
- **데이터 흐름**: CLAUDE.md(클래스·시험형식) + hypo + 학생답안 → 4성분 매핑 채점 → `irac-sessions/[student]/tracker.md` → 3세션+ 패턴 → flashcards/socratic-drill/outline-builder로 라우팅.

### 1.3 공통 설계 사상

- **카드 = 암기, IRAC = 구조** — 두 스킬이 학습 단계를 명확히 분업. flashcards는 "이미 공부한 것의 회상", irac-practice는 "구조·적용 능력". (우리 daily-drill 2트랙 = 진도(객관식 정착)/복습(사례IRAC)과 사상 유사.)
- **세 가지 일관 가드**: ① Real-matter check(법률조언 차단) ② Confidence discipline(`[VERIFY]`/`[UNCERTAIN]`, 추측 카드 금지) ③ Citation check(AI 생성 인용은 미검증 — 외부 DB로 확인하라).
- **저장은 평면 마크다운 + 인라인 메타**(과목당 1파일). 빌더·apkg 없음 — 채팅 내 경량 운용 전제.

## 2. 우리보다 나은 점 (구체)

> 우리(법학볼트)에 없거나 약한 것만. 출처는 외부 SKILL 라인.

1. **패턴 추적 = 학습 메타루프의 명문화**(irac line 142-159). 우리는 약점을 learning.json·SRS에 항목으로 모으지만(daily-drill Phase3·case-answer-review 약점연동), **"3연속 같은 갭"을 자동 표출해 공부법을 바꾸라"는 종단(longitudinal) 패턴 진단이 스킬에 명시돼 있지 않다.** 우리 case-answer-review는 "같은 유형 2회 반복 → 카드 후보"(line 194)까지는 있으나, 외부는 더 나아가 **메타-피드백("Application이 구조적 약점이다")을 학생에게 돌려준다.** → 우리 weekly-review/daily-drill에 '종단 약점 패턴 표출' 단계가 약함.

2. **'적용/포섭' 판정의 단순 휴리스틱**(irac line 66): "because/here 같은 매핑 언어가 있는가"라는 **검출 가능한 표지**로 포섭 여부를 1차 판정. 우리 case-answer-review의 포섭은 4슬롯·E1/E2/E3 코드(line 181-182)로 정교하나, 외부의 'because 표지 1차 스캔'은 **빠르고 결정적인 사전필터**로 우리 포섭 채점의 전처리에 그대로 차용 가능(우리 E3=연결고리 단절 탐지에 직결).

3. **모범답안 비노출 + 라벨 예시 1~2개 가드**(irac line 130-139, 174-176). 우리 case-answer-review는 "해설은 절대 기준"(line 102)으로 해설을 채점에 적극 쓰지만, **학습 효과 측면에서 '모델 답안을 보여주지 않고 학생이 스스로 모델을 세우게' 하는 규율과, 예시를 줄 때 학생의 실제 쟁점으로는 절대 안 주는(=정답 누설 차단) 가드**가 우리엔 명시돼 있지 않다. 우리는 채점 정확성에, 외부는 학습 비누설에 가드가 쏠려 있다 — **이 비노출 규율이 우리 사례형 드릴의 학습효과를 높일 여지.**

4. **신뢰 차등(confidence by component)**(irac line 38-42): 구조=확신/쟁점콜=명백시확신·논쟁시 UNCERTAIN/룰정확성=VERIFY/미지관할=구조만. 우리는 #1·#2로 '소스 없으면 보류'는 강하나, **"구조는 확신해도 되지만 룰정확성은 항상 의심"이라는 축별 신뢰 등급**이 채점 산출에 구조화돼 있지 않다.

5. **등급의 밴드화·반-허위정밀**(irac line 113-117, 177): Pass/borderline/not-yet 3밴드, 숫자점수 거부("precision is false precision"). 우리 case-answer-review는 가중 루브릭(0.0~1.0)을 두되 이미 디프리케이트(line 121)하고 LLM 비교로 옮겼는데, **외부의 '밴드만·숫자거부' 선언은 우리가 루브릭 수치화에서 LLM 비교로 옮긴 방향과 일치**하며 더 단호하다 — 우리 잔존 수치(provisional_grade)를 정리할 근거.

6. **stuck 카드 → 구두 드릴 라우팅**(flashcards line 135, 140): "2회+ 강등 카드 = 이해 못한 개념 → 카드로 안 됨, 소크라틱으로." 우리도 약점→SRS는 있으나 **"카드를 아무리 돌려도 안 되는 항목은 카드 문제가 아니라 이해 문제 → 소크라틱"이라는 명시 분기**가 약하다(우리 #21 소크라틱은 있지만 카드-실패→소크라틱 자동 라우팅 규칙은 미정립).

7. **개수 채우기 금지 명문**(flashcards line 45, 156): "8 good > 20 with 5 wrong." 우리도 #1·#2로 추측 금지지만, **'타깃 개수를 맞추려 VERIFY-투성이 카드를 만들지 않는다'는 카드 생성 안티패턴**이 우리 02-card 프롬프트엔 coverage_rule(전수)만 강조돼 역방향 압력(개수 채우기)이 명시 금지돼 있지 않다 — 단, 우리 목표가 '전수 카드화'라 외부의 '소수정예'와는 긴장 관계(§4 참조).

> 우리가 외부보다 강한 점(대조 균형): 전수 카드화·누락0 감사(1867건 전수 적발, cardaudit_집계.md), atom 추적 SCHEMA(연구_카드구조.md §5.1), 표 셀 트리플 평탄화(§2), 2트랙 드릴, 닫힌루프(#50-A), 원문보존 위키, law_api 조문/사건번호 자동검증, 패널 채점·집계(case-answer-review line 106-117), apkg 빌드 파이프라인. **외부는 경량·채팅용(>500 카드 비대상)이라 전수성·빌드·검증 인프라는 우리가 압도.**

## 3. 한국 요건사실론 반영 시사 (IRAC 기본 + 요건사실·주장증명책임·청구원인/항변)

외부는 **IRAC/CRAC 단일 골격**(line 68)으로 영미 에세이를 채점한다. 한국 실무·시험은 IRAC를 쓰되 **요건사실론(요건사실·주장증명책임·청구원인/항변 구조)**이 분석의 뼈대다. 시사:

1. **IRAC의 'R(Rule)·A(Application)'을 요건사실론으로 치환·세분.** 외부 R=룰진술, A=사실적용이지만, 한국형은 **R = 청구원인의 요건사실 열거 + 각 요건의 주장증명책임 분배**, **A = 요건사실별 사실 대입(포섭)**으로 1단계 더 분해해야 한다. 우리 case-answer-review의 **민법 다툼형 = #32 원고|피고 2열 + 청구→항변→재항변**(line 156)이 바로 외부 IRAC를 요건사실론으로 한국화한 골격 — **외부엔 없는 우리 고유 강점이자, irac-practice의 '4성분 매핑'을 우리 2열 요건사실 매핑으로 확장한 형태.**

2. **'적용 판정 휴리스틱(because/here)'을 요건사실 단위로 적용.** 외부의 "룰을 사실에 매핑했는가"를 한국형은 **"각 요건사실마다 구체적 사실이 because로 붙었는가"**로 격상 = 우리 4슬롯 작법([요건적시]→[사안의 경우+사실]→[법적평가]→[소결], case-answer-review line 182)과 정합. → **외부의 단순 표지 검출을 우리 요건사실별 슬롯 검출로 확장**(요건사실 N개 × 4슬롯 매트릭스로 포섭 채점).

3. **주장증명책임 = 외부 IRAC에 없는 한국 고유 축.** 청구원인(원고 입증)/항변(피고 입증)/재항변의 입증책임 분배가 답안 핵심인데, 외부 irac-practice는 이를 다루지 않는다. → **카드/채점에 '입증책임 귀속(원고/피고)' 필드를 신설**해야 한다(우리 침해부당이득 요건사실표 4열 각 셀 증명책임 판례, 연구_카드구조.md line 54가 이미 이 구조 — 카드 SCHEMA에 `입증책임::원고/피고` 속성 추가 여지).

4. **요건사실 카드 SCHEMA(연구_카드구조.md §5.2 rule(요건))에 요건사실론 메타 보강.** 현재 요건 세트 카드는 "①②③④ + 개수명시"(line 168)인데, 한국형은 각 요건에 **(가)요건사실 명제 (나)주장증명책임 귀속 (다)대응 항변**을 부속시켜야 far-transfer(실제 답안 작성)로 연결. 외부 flashcards의 "1개념=1카드"는 **요건사실 1개=1카드**로 한국화하되, 우리 anti_fragmentation(항상 결합되는 요건은 분리금지, 연구_카드구조.md line 109)으로 균형.

5. **채점 구조 기준(case-answer-review line 156)이 이미 요건사실론 반영 — 외부보다 앞섬.** 민법 다툼형=요건사실↔사실/항변사실 누락 점검, 형법=구성요건→위법성→책임, 헌법=적법요건→본안. **외부 irac-practice는 과목 무차별 단일 IRAC라 이 과목별 구조가 없다.** → 우리는 외부의 '패턴 추적·비노출 가드'만 흡수하면 되고, 요건사실 골격은 유지·강화가 정답.

## 4. 사례형(CASE) 전수 카드화 시사 — 이 레포는 사례를 어떻게 다루나

### 4.1 외부 레포의 사례 처리 방식 (사실)

- **flashcards는 사례(hypo)를 카드로 만들지 않는다.** 카드는 **블랙레터 룰 회상 전용**(line 35: outlines=synthesis, flashcards=memorization). 사례 분석 능력은 **별도 스킬(irac-practice)**이 담당. → **명확한 분업: 룰=카드, 사례=IRAC 채점**(카드화 아님).
- **irac-practice는 사례를 '카드'가 아니라 '쓰기 연습 + 채점 + 패턴추적'으로 처리.** hypo를 주거나 생성해 학생이 답안을 쓰고, 스킬은 채점만 한다(line 34, 142). **사례를 카드(Q/A)로 분해해 암기시키지 않는다** — 모범답안조차 안 보여준다(line 176, 학습효과 우선).
- 즉 **외부는 "사례 = 절대 카드화하지 않는다"가 설계 원칙.** 사례는 매번 새로 쓰고 채점받는 생성형 연습이지, 회상형 암기 단위가 아니라는 입장.

### 4.2 우리 시스템과 대조

- 우리 02-card는 **사례형을 '분해하지 말고 원문 보존'**(연구_카드구조.md line 67, 사례형_schema)으로 두되, **far-transfer 위해 종합/IRAC 카드 1장 병행 권장**(line 67, 172). 즉 우리는 "사례를 잘게 쪼개 카드화"는 안 하지만 "사례 1건당 종합 카드 1장"은 만든다.
- 우리 daily-drill은 **사례형을 복습·심화 트랙에서 '쓰고 채점'(case-answer-review)으로 처리**(daily-drill line 99-122) — 이건 외부 irac-practice와 **사상 동일**(쓰기+채점, 암기카드 아님).

### 4.3 결론 — "사례형을 전부 카드로 만들어야 하는가?"

**아니다. 외부 레포의 설계와 우리 현행 설계가 수렴한다 — 사례는 원칙적으로 카드화 대상이 아니다.**

- **근거 1(외부)**: flashcards/irac-practice 모두 사례를 카드로 만들지 않는다(룰=카드, 사례=쓰기채점 분업).
- **근거 2(우리 원칙)**: 사례형은 원문보존·비분해(연구_카드구조.md line 67·172), 학습은 daily-drill 복습트랙의 쓰기+포섭채점으로(daily-drill line 99). 사례를 Q/A 카드로 잘게 쪼개면 '회상'은 되나 far-transfer(실제 답안 작성·포섭)는 안 된다 — 외부가 모범답안 비노출로 막으려는 바로 그 단축학습.
- **근거 3(전수 카드화의 본뜻)**: 우리 '전수 카드화'(누락0)의 대상은 **논점노트의 룰·판례·표·조문·요건·학설(원자 항목)**이지(cardaudit_집계.md의 1867 누락이 모두 이 유형), **사례 문제 자체가 아니다.** 누락 감사는 판례 줄·표 셀·조문 카드를 잡는 것이지 사례를 카드로 강제하는 게 아니다.

**따라서 권고:**
1. **사례형 = 카드화 비대상(원칙).** 단 예외로 **사례당 '종합/IRAC 회상 카드 1장'**(쟁점골격·결론·핵심포섭 단서)은 허용 — 우리 02-card 현행과 외부 far-transfer 우려를 절충. 이 1장은 '답안 암기'가 아니라 '쟁점 트리거' 카드여야 한다(외부 비노출 규율 준수: 모범답안 전문을 카드 뒷면에 박지 않는다).
2. **사례의 학습 정본 = 쓰기+채점 루프**(daily-drill 복습트랙 + case-answer-review 패널채점). 외부 irac-practice의 **패턴추적(3세션+ 종단 약점)**과 **비노출 가드**를 이 루프에 흡수.
3. **사례에서 추출되는 '룰·판례·요건'은 카드화 대상**(전수). 즉 사례 문제는 카드화 안 하되, 그 사례가 묻는 쟁점의 원자 항목(요건·판례 holding)은 논점노트 경로로 들어와 누락0 카드화된다. → 사례와 카드의 연결은 '사례→쟁점논점→원자카드'(닫힌루프 #50-A)이지 '사례→카드' 직접 분해가 아니다.
