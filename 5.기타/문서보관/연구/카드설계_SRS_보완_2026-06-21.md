## Q1. 카드 — 바꿔야 한다(지식 종류별 분화)

- **단일 카드유형은 부적절** [C1·C13, Yeo&Fazio 2019 / KLI(Koedinger 2012), primary]: 최적 학습법은 지식 '종류'(안정 사실 vs 유연 절차)에 따라 다르다 → 유형을 지식 카테고리별로 분화하라.
- **사실층(룰명·조문·판례 holding):** 지연 시 testing>studying [C12] → cloze·원자적 카드. **현 `rule` 장문 카드 = atomic/최소정보 원칙 위반 → 요건별 '1사실 1카드' cloze로 분할.** (설계원칙은 실무 표준=folklore)
- **능동 생성 강제** [C15]: Q+A 수동 읽기 < 실제 인출 → card-wiki-pipeline은 cloze/생성형으로(앞뒤 통독 카드 지양).
- **포섭/적용층 — 조건부:** 인출이 적용·전이로 이어지나 **≥3회 분산+지연일 때만**(1회·8분=효과 0) [C4·C5]. 즉 application 카드는 '분산·반복·변형'일 때만 값을 한다. 절차학습은 즉시시험에선 worked example이 testing보다 나을 수 있고, 장기엔 testing=변형studying>동일studying [C2·C3] → **같은 쟁점도 사실관계를 바꿔 출제(변형/variation)**.
- **★ 쟁점 인식 카드(최고 ROI):** 인출은 전이의 '인식(recognition)' 성분을 키워 'inert knowledge'(알지만 상황을 못 알아봐 적용 실패)를 깬다 [C6] = 변시 **쟁점 spotting 그 자체** → **'사실관계 → 어느 쟁점/요건인가?' 카드를 신설**(현 3유형에 없음).
- **한계:** Anki 효과는 사실층에 집중, 고차 적용엔 약함(Step2 CK 유의차 없음 p=0.44 / Step1 사실형엔 dose-response) [C7·C16] → **카드만으로 사례 실력 안 됨, 백지 사례 병행**(기존 결론 재확인).

**→ card-wiki-pipeline 권고:** ① `rule` 장문 → 요건별 cloze 분할 ② **4번째 유형 '쟁점인식(fact→쟁점/요건)' 추가** ③ application(포섭) 카드는 변형·분산 전제(동일문항 반복 금지).

## Q2. SM-2 → FSRS: 효율은 yes, 시험점수 근거는 no

- FSRS는 사용자 수행 기반 **간격 최적화**이나, 리뷰가 **FSRS가 SM-2보다 시험성적을 올린다는 비교 근거는 제시하지 못함(서술적)** [C8]. 증거 기반 전체가 관찰적·RCT 없음 [C9].
- 즉 FSRS = **복습량 효율**(같은 retention에 복습 횟수↓ — Anki 커뮤니티 실무경험) 도구이지 점수 상승 보장 아님.
- **현 상태(카드 4개·시스템 미가동)에선 무의미.** 카드 수백+ 누적되면 효율 위해 고려. `srs_scheduler.py`는 커스텀 SM-2라 FSRS 이식은 실제 엔지니어링 → **카드량이 정당화할 때까지 보류**.

## Q3. 아직 안 쓴 기법 (이번 run 근거 약함 — 일반 원리)

- **변형연습/대조사례** [C3]: 같은 쟁점을 다른 사실관계로(스키마 형성) — 교차학습과 직결.
- **worked example=풀이경로 전체**(문제+단계+결론, 답만 아님) [C18, C17 CLT]: 모범답안에 포섭 '단계'를 노출(case_index가 이미 그러함).
- (출처 밖·일반 원리, 이번 딥리서치 미검증): **dual coding** — 보유한 '도표노트'를 인출 프롬프트로(도표 빈칸 채우기) / **prequestion** — 배우기 전 추측 / **메타인지 보정** — 채점 전 점수 예측. ROI 있으나 이번 run이 직접 검증 안 함.
