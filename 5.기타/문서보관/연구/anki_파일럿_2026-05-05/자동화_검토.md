# Anki 카드 워크플로우 — 자동화 세밀 검토

대상 입력: 송영곤 쟁점노트 .md (OCR 완료 + 정규화본)
판단 기준: **결정적(deterministic) 구간은 스크립트, 판단(judgment) 구간은 LLM**으로 분리

---

## 0. 파이프라인 분해

```
쟁점노트.md
   │
   ├─[A] 블록 분류 파서 (스크립트)      → blocks.json (조문/판례/표/논점/frontmatter)
   │
   ├─[B] 결정적 카드 생성 (스크립트)     → 조문 카드, 태그 prefix
   │
   ├─[C] 판단 카드 생성 (LLM/02-card)    → 판례 사안카드, cloze, 표 재구성
   │
   └─[D] 검증 게이트 (스크립트+MCP)      → 조문·사건번호 실재 검증, {불명} 마킹
```

핵심: **A·B·D는 사람 개입 없이 반복 가능**. C만 LLM 판단 + 수동검수 필요.

| 조문 블록 → 조문 카드 | **HIGH** | `> [!조문] 제N조 제목` + 인용 | rule/statute TSV | 95%+ | 다항(①②③) 줄바꿈, OCR 누락 |

## 2. HIGH 등급 — 즉시 스크립트화 가능

### 2.1 조문 블록 → 조문 카드
- **입력 정규식**: `^> \[!조문\] (제\d+조(?:의\d+)?)\s*(.*)$` → 다음 `> ` 인용행들을 원문으로 수집
- **출력 매핑** (statute schema):
  - 룰명 = `{조문번호} {제목}`
  - 근거조문원문 = 수집된 원문 (축약 금지 — #34)
  - 태그 = frontmatter에서 자동 (`속성::조문`)
- **다항 처리**: `①②③④` 마커를 만나면 동일 카드 내 `<br>` 또는 항별 분리 옵션
- **검증**: 추출 조문번호를 korean-law-mcp로 대조 → 원문 불일치 시 플래그
- **이번 파일럿 검증**: 제329·334·335·338·345·347·348·349·352·353조 전부 `> [!조문]` 블록에서 결정적으로 추출 가능했음

### 2.2 frontmatter → 태그 prefix
- YAML `과목: 민법` → `과목::민법`
- YAML `쟁점: [동산질권, …]` → 첫 항목을 `주제::` (복수 시 수동 확인 필요 = MEDIUM으로 강등)
- YAML `페이지: 481-510` → `출처::송영곤쟁점노트-p481` (시작 페이지)
- **주의**: 띄어쓰기 제거·한글 원형 정규화 규칙(02-card tag_schema) 적용

### 2.3 검증 게이트 (korean-law-mcp)
- 조문번호 → 법령 원문 대조 (민법/상법/주임법)
- 사건번호 → 판례 실재 확인
- 미수록·불일치 → `{불명}` 또는 `검증필요::` 태그 자동 부착

## 3. LOW 등급 — LLM 판단 필수 (자동화 부적합)

### 3.1 판례 사안 기반 카드 (가장 어려움)
- **이유**: 쟁점노트는 판시(`> [!판례]`)와 사실관계(`> [!사실관계]` 또는 footnote `[^181]` 또는 본문 산재)가 **분리·분산**되어 있음
- 사안 요약은 "갑이 을에게 …" 도식화 = 정보 압축 + 출제의도 판단 → 결정적 규칙 불가
- **권고**: LLM이 사안 초안 생성 → 사람이 출제의도·독립성 검수 (4절)

### 3.2 Cloze 키워드 선정
- `**강조**`를 그대로 빈칸 처리하면:
  - 누설 위험: "신의성실의 원칙(**신의칙**)" 류
  - 과다: 한 문장에 강조 5개 → 카드 붕괴
  - 일반어: "**제339조**" 처럼 식별자만 강조된 경우 회상 가치 낮음
- **권고**: 강조는 후보로만 제시, LLM이 회상가치 판정 + 빈칸 1~3개로 압축

## 4. 수동검수 = "문제 풀고 피드백" 방식 (채택)

자동 생성 카드의 품질은 **passive 읽기가 아니라 실제 풀이**로 검증한다.

**절차**:
1. 카드 앞면(질문/사안)만 제시
2. 검수자(또는 LLM)가 답 시도
3. 뒷면과 대조 → 다음 항목 채점:
   - 답 명확성(앞면만으로 답이 일의적으로 결정되는가)
   - atomic(개념 1개인가)
   - 독립성(다문항 분할 시 단독 이해 가능한가)
   - cloze 누설/과부하
4. 실패 카드는 수정 리스트에 등재

**판정**: O(통과) / △(보완) / X(폐기·재작성) — #23 준수 (배점표 없으므로 O/△/X)

## 5. 자동화 ROI 요약

| 우선순위 | 작업 | 효과 |
|:---:|------|------|
| 1 | 조문 블록 파서 + 검증 게이트 | 조문 카드 100% 자동, 파일당 수십 장 즉시 확보 |
| 2 | frontmatter 태그 파서 | 태그 수작업 제거, 일관성 보장 |
| 3 | 판례 메타(사건번호·선고일) 추출 | LLM 입력 전처리, 환각 차단 |
| — | 사안카드·cloze | LLM + 수동검수 유지 (자동화 보류) |

**결론**: 카드의 약 30~40%(조문·태그)는 스크립트로 결정적 생성, 나머지 60~70%(판례사안·cloze·표재구성)는 LLM 생성 후 "문제 풀이" 방식 수동검수가 적정.
