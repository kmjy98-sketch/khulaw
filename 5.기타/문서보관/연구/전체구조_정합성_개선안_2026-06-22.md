## 2. 미사용 발생의 구조적 원인 (지시1)

1. **은퇴 절차 부재** — 추가는 쉽고 폐기·격리·진입점 제거 표준이 없어 죽은 자산이 누적(레거시 워크플로 12·법무스킬 4·02_cards).
2. **진입점 미연결** — 코드는 있으나 dispatch 라우팅/룰 트리거에 안 물리면 호출경로 단절(flush 동결·레거시 워크플로).
3. **정본 이원화** — 같은 역할이 여러 경로(위키 한/영, 02_cards/v37, 룰 3중)로 갈리면 한쪽이 방치.
4. **트랙 간 상호 미참조** — 메모리 3트랙이 코드상 단절돼 정보가 고립.
5. **룰↔코드 드리프트** — 룰이 노후화해 죽은 자산을 가리킴(#46→폐기예정 02_cards).
6. **직무 무관 자산 일괄 설치** — 마켓플레이스 단위 플러그인이 맥락 없이 상존.
7. **분류가 사후 단계** — 생성시 위치 미결정→루트 적체.

## 4-B. 확정된 결정 (2026-06-22, 사용자 승인) — §4 권고를 갱신·확장

1. **메모리·위키 통합 = 링크만 + MEMORY 색인 확장(확정)**: 38개 .md는 이동하지 않는다(가역). 그 위에 **MEMORY.md를 "클로드용 전체 마스터 색인"으로 확장** — 법학지식은 위키 단방향 링크, 그 외 **구조·스킬·룰·보고서 레이어까지 포인터로 색인**해 클로드가 한 곳에서 전체에 도달. 단 **MEMORY.md는 내용이 아닌 1줄 포인터 색인으로만 유지**(세션마다 자동 로드 → 비대 금지, #38 ≤25KB 정신). 구조 맵은 기존 `sync/_index_master.md`를 클로드뷰 구조 색인으로 활용·연결.
2. **위키 폴더 물리통합 = 목표 확정, 단 실행 보류(확정)**: 최종 목표는 한 폴더 단일화. 그러나 **현재 드라이브 이주(E:) 처리 중** → 지금은 **현황 확인 + 이주 후 실행 계획만** 작성하고 물리 이동은 하지 않는다. 그 전까지는 P1 선언 정합화(정본=`sync/위키/원문` 명시 + lint 정본경로 확장)로 운영.
3. **죽은 사본 트리 = 재확인 후 _trash(확정)**: 하버스 실제 로드경로 1회 확인 → 死사본 확정 시에만 `_trash/{날짜}/` 이동(복구가능·#16-C 로그).
4. **PreToolUse 안전훅 = warn-only 1주 후 enforce(확정)**.
5. **전사 코퍼스 issue_id = 초기 제외(권고대로 확정)**. STT만 은퇴, 코퍼스 보존.
6. **AGENTS.md 자동재생성 = 폐기, 미러 유지(권고대로 확정)**. 상단 1줄(SSOT=CLAUDE.md, 본 파일=미러+고유규정, 번호 별개) 명시로 대체.

> 실행 영향: 위키 물리통합은 별도 **P-defer(드라이브 이주 후)**로 분리. P1~P7 본문은 유효하되 P1의 위키 항목은 "선언 정합화"까지만, 물리이동은 P-defer로 이관.
