## §5. 자동 처리 가능 vs 사용자 결정 필요

### 자동 처리 가능 (스크립트 일괄)

- 공백 → `_` rename (3-B 3건 + 3-A 율촌초안 1건)
- 괄호·대괄호 제거 (3-C Clippings 1건)
- `__pycache__/` → `_trash/2026-04-28/sync_pycache/` 이동
- 루트 운영 메모 2건(`Gemini_*`, `Colab_*`) → `_meta/`로 이동

### 사용자 결정 필요

- `무제.md`·`율촌 초안.md` 최종 rename (자소서 버전 일련번호·날짜 표기)

- `_교재원문/` 폴더 향후 활용 방향(거의 비어있음)

## §6. 점검 한계 및 후속 작업

### 한계

- **bash 마운트 캐시 정체**로 `sync/` 깊이 4 이상 일부 영역(특히 `민법/{각 폴더}/` 깊이 3) 풀 listing은 file-tool 개별 호출로 진행. 대규모 트리는 ripgrep 타임아웃 빈발 → **표본 cover** 수준의 점검으로 한정.
- `5.기타/`, `1.민사/`, `2.형사/`, `3.공법/`, `4.선택법/` 등 **sync 외 메인 폴더는 이번 점검 대상 아님** (사용자 요청 = sync 한정).

### 후속 작업 (별도 task로 처리)

1. **자동 batch 1**: `_meta/` 공백 rename + 루트 운영 메모 2건 `_meta/`로 이동 + `__pycache__` `_trash`로 이동 — 사용자 승인 후 실행
2. **자동 batch 2**: `Clippings/` 1건 rename — 사용자 승인 후 실행
3. **수동 검토 batch**: 자소서 2건(`무제.md`·`율촌 초안.md`), `_md_to_pdf.py`, `민법/총칙/매매·계약법_총칙` — 사용자와 함께 결정
4. **풀 트리 재점검**: bash 캐시 정상화 시 `find sync -type f` 기준 재확인 권고 (특히 `민법/`·`헌법/`·`형법/` 하위 빠진 파일 유무)
