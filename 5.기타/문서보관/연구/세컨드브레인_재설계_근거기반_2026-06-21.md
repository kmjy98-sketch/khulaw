# 세컨드브레인 전체구조 근본 재설계 — 근거기반 설계안

> 전제: 새로 만들지 않고 **검증·재사용·정비**. 모든 변경은 비파괴(이동=_trash 또는 경로변경, 삭제금지 #16) + 승인게이트. `0.공유드라이브/`는 불가침(#16-B).
> 사용자 확정 축: ①기준=Drive 유지하되 「전부 Drive 밖 이주 + Drive 이중백업」 타당성 정면검토 ②모바일=데스크톱 위주·폰 보조(단방향) ③범위=물리구조+지식층+학습워크플로우+거버넌스 전체.

## 0. 한 줄 결론

근거는 **「라이브 볼트를 Google Drive 밖 로컬로 이주 + Drive는 단방향 2차 백업으로 강등」을 지지**한다(Obsidian 공식 다수 + 실제 손실사례 + 우리 Gemini 워처의 silent_drop 실측). 단 48룰·27스킬·스크립트의 H:\ 하드코딩 때문에 **빅뱅 이주는 위험** → ①경로를 단일 config로 디커플 → ②즉시 단방향 백업으로 버전이력 공백부터 메움 → ③방학에 단계적 컷오버, 의 순서가 정답. 지식층은 **Obsidian Bases 도입(단 YAML frontmatter 표준화가 선결)**, 학습층은 **주간리뷰 신설 + 찌라시를 '인출 리허설'로 재정의**, 거버넌스는 **CLAUDE.md 다이어트 + 절대룰(#16/#16-B/#16-C)을 PreToolUse 훅으로 강제**가 핵심.

## 1. 근거 베이스 (검증된 외부 1차 출처)

### A. 동기화·백업 (물리구조)
- **Obsidian 공식: sync ≠ backup.** "they are not designed for backups", "**볼트를 백업 서비스 안에 두지 말 것**". 백업은 작업데이터를 바꾸지 않는 **단방향 복사**. [help.obsidian.md/backup]
- **공식: 더블싱크 = 파일 소실 원인.** "double-syncing … Obsidian Sync runs alongside another syncing service" → 볼트를 third-party 클라우드 폴더 밖으로 이동하라. iCloud/Dropbox/OneDrive/**Google Drive** 병행 비권장. [help.obsidian.md/sync/troubleshoot, /sync/switch]
- **실제 손실사례(포럼):** Google Drive 안 볼트에서 .md 다수가 **무경고로 수시간 편집 소실, Drive 버전이력도 없음**. 원인=노트앱의 잦은 소량 쓰기를 GDrive가 신뢰성 있게 동기화 못함 + 온라인전용 placeholder. [forum.obsidian.md/t/data-loss-with-google-drive]
- **단방향 백업 패턴:** rclone `copy`(단방향 local→remote), **동기화 전 Obsidian 종료**가 안전관행. 양방향 bisync는 충돌해결 플래그 필요(복잡). [rcloneui.com/.../obsidian-sync]
- **마이그레이션 절차(공식):** 백업 먼저 → 새 로컬볼트 생성 → 전 기기 강제종료 → 폴더를 클라우드 밖으로 이동. Windows 권장 위치=비-C 드라이브 또는 전용 `C:\Vaults`. [help.obsidian.md/sync/switch]
- **모바일 제약:** Obsidian 모바일 API는 ≥50MB 파일 동기화 성능문제 → **폰=조회/암기 전용, 대용량 제외**가 합리적. [remotely-save 문서]
- 대안(앱레벨 동기화): remotely-save(충돌감지 有, 단 third-party·"항상 백업하라" 경고). 우리는 우선순위 낮음.

### B. 학습과학 (찌라시·카드 역할분담)
- **Dunlosky 2013(독립 리뷰):** 10개 학습기법 중 **고효용은 단 2개 — 인출연습(practice testing)·분산학습(spacing)**. **요약·하이라이트·재독은 저효용**. Hattie&Donoghue 2021(242연구) 동일 결론(인출 vs 재학습 g≈0.50–0.61). → **우리 카드+SRS가 기억엔진, 위키/링크는 보조**라는 게 정설.
- **Karpicke & Blunt 2011(Science):** 인출연습 > 개념도(concept mapping). **최종시험이 개념도 그리기여도** 인출이 이김. → 위키(MOC/백링크)는 **부호화·조직화** 도구일 뿐, 기억기능은 카드가 소유. **링크층을 카드 규율 희생하며 키우지 말 것.**
- **Deng 2015(USMLE):** **자작 Anki 카드 수**가 면허시험 점수의 독립 예측인자(고유카드 ~1700장당 +1점). **시판카드는 예측력 없음**. → 우리 OCR→위키화→TSV **자작 파이프라인 자체가 인과적 고가치 자산**. 커버리지·볼륨이 중요.
- **인터리빙 메타분석(Brunmair&Richter 2019):** 인터리빙은 **혼동되는 유사범주 변별**에 강함(유사 법리/청구 구분). 단 비유사 자료엔 약함, **선블록→후인터리빙**이 선언지식엔 필요. → daily-drill 2트랙(회독0=블록 학습, 회독1+=혼동 쟁점 인터리빙)이 정합.
- **찌라시/cheat-sheet(Studies in Higher Ed 2024):** **만드는 행위(선별·압축·손글씨 재작성)가 부호화**이고 시험불안 감소. **소지 자체는 학습이득 보장 안 됨**. → 찌라시는 **인출+압축 산출물(만들며 외움)**로 재정의, 수동 벼락치기 요약본이 아님.

### C. 지식층 (Bases/frontmatter/MOC/링크)
- **Bases = 코어(공식) Dataview 후계.** 로컬 .md의 **YAML 프로퍼티만** 질의. .base는 뷰설정만 저장, 데이터는 frontmatter. [help.obsidian.md/bases]
- **결정적 제약:** Bases는 **노트 본문/인라인 Dataview필드(`Rating:: 5`)를 못 읽음** — 정렬·필터·표시할 필드는 **반드시 정식 YAML 프로퍼티**여야. → 우리 카드의 인라인 `주제::`는 Bases에 안 보임. **'Master Property Schema'(중앙 프로퍼티 표준) 선결**, 타입 전역지정(due=date, 회독=number). [chughkabir.com, danholloran.me]
- **Bases vs Dataview:** Bases=GUI·무쿼리·빠름·모바일 부담 적음, 단 (2025.6 기준) **표뷰·프로퍼티질의로 제한·베타**. Dataview=강력하나 대형볼트 느림·모바일 1~2s·정체. **권고: 단순 보드는 Bases, 복잡쿼리만 Dataview 잔존, frontmatter는 공유**(병행 이행). [obsidian.rocks, obsidianstats]
- **MOC/폴더/태그 조합원칙:** 폴더="어디 사는가"(단일·중복불가→교차주제엔 부적합), 태그="무엇에 관한가"(발견·필터 신호일 뿐 **주 구조 금지**), MOC=내비게이션(한 노트가 여러 MOC에 링크, 단일정본 유지). **하이브리드=폴더 최소·MOC 내비·태그 발견**. → 우리 _index.md MOC+원자노트 설계가 이미 정답. 폴더 ≤2단 권장.
- **링크 무결성:** 'Find orphaned files and broken links'(Vinzent03) 플러그인=고아·깨진링크·빈파일 **탐지**(ignore 목록으로 0.공유드라이브 제외 가능). **단 이름변경후 링크복구는 안 함** → Obsidian 코어의 'rename시 링크 자동갱신' 설정 ON + 스크립트 이동(log_file_op.py)엔 별도 fix-renamed-links 헬퍼 필요(코어 자동갱신은 앱 내 rename만 커버).

### D. 주간리뷰·역산 페이싱
- **2357법(역산 스페이싱):** 시험일에서 거꾸로 7-5-3-2-1일 간격 복습. Ebbinghaus 망각곡선 기반. → 우리 SRS를 **시험단위 고정지평 계획**에 묶는 층.
- **GTD 주간리뷰:** 리뷰가 시스템 **신뢰성을 유지**하는 핵심(시스템 방치는 캡처실패가 아니라 리뷰중단에서 옴). 3단계(비우기/현행화/창의). → 확정 갭(주간리뷰 부재) 직격.
- **시험 시간관리(실무):** 시험까지 주수 세고 **마지막 3~4주 복습·모의 선점약**, 2개월당 버퍼 1주, 잔여범위를 **배점×난이도 가중**으로 주별 분배, **일요 5분 리뷰로 미완 롤포워드 + 다음주 과목별 3개 토픽우선순위 사전설정**(추상 'X공부' 금지, 'Ch.5 정의 완성' 식). → §5.2/주간리뷰 자동화 패턴 그대로.
- **Anki 체계리뷰(Springer):** retention 동력은 **적응형 due 스케줄+수행기반 난이도**. → 우리 SRS 엔진은 충분, **빠진 건 주간 집계/리뷰층**이지 엔진이 아님.

### E. AI 거버넌스
- **Anthropic '룰 강제':** CLAUDE.md는 **권고(advisory)**. 절대금지(삭제·공유드라이브 이동)는 **hooks/permissions 결정론 계층**으로. [claude.com/blog/steering-claude-code]
- **Hooks=결정론 통제:** "되돌릴 수 없는 행위 앞에 정중한 지시문만 있으면 통제가 아니라 **희망(hope)**". **PreToolUse 훅**은 실행 직전 deny로 차단(모델의도·프롬프트인젝션 무관). → #16/#16-B/#16-C를 모델재량에서 훅으로 이전. [dotzlaw.com]
- **CLAUDE.md 비대 비판:** 공식 "CLAUDE.md 짧게". 컨텍스트가 빨리 찰수록 성능저하. 48룰은 비대 리스크. 상세는 references/·skills로 분리. [anthropic.com/engineering/claude-code-best-practices, alexop.dev]
- **스킬 과밀:** progressive disclosure로 스킬당 startup ~30~50토큰 → **27스킬 보유 자체는 저비용**. 실질 리스크는 **트리거 신뢰도**(Vercel evals: 스킬 56% 미발화). → 정리 동기는 비용이 아니라 트리거 충돌·유지보수.
- **AGENTS.md(쟁점):** morphllm은 Linux Foundation 표준·Claude Code가 2026봄부터 읽음 주장 / 그러나 Anthropic 공식 memory.md는 "Claude Code reads CLAUDE.md, **not** AGENTS.md, @import 필요" — **상충**. 안전노선=**CLAUDE.md 권위 단일**, 공유는 `@AGENTS.md` import 또는 현 미러 유지+drift 점검.

## 2. 핵심 결정 — Drive 이주 vs 유지

| 기준 | Drive 유지(현행) | 로컬 이주 + Drive 2차백업(검토안) |
|---|---|---|
| 데이터 손실위험 | **높음** — Drive가 잦은 소량쓰기 신뢰성 부족, 버전이력 없음. **우리 Gemini 워처가 이미 silent_drop 5건 실측** | 낮음 — 로컬 정본은 즉시쓰기, Drive는 단방향 복사라 race 없음 |
| 모바일(폰 보조) | Drive 앱 의존(편집충돌·대용량) | Obsidian Sync/rclone 단방향 미러로 마크다운만 |
| 이주비용 | 0 | **높음** — 48룰·27스킬·스크립트 H:\ 하드코딩 전수 |
| 0.공유드라이브 | Drive에 그대로(정상) | **그대로 Drive 유지**(애초에 우리 것 아님·이동금지 #16-B) — 이주 대상 아님 |
| 백업 충실도 | 부분(git add -A 금지로 커버 불완전) | 단방향 백업으로 전체 커버 |

**판정: 이주가 근거상 우월하나, 빅뱅은 금지. 디커플→백업→단계 컷오버 순.**

핵심 통찰: `0.공유드라이브/`는 Google **공유 드라이브**라 본디 Drive에 살아야 하고 우리가 옮길 수도 없다(#16-B). 따라서 「개인 볼트 → 로컬 이주, 공유드라이브 → Drive 잔류·읽기전용」으로 **깔끔히 분리**된다 — 이주가 공유드라이브를 건드리지 않는다.

## 3. 목표 아키텍처 (4축)

### 축 a — 물리구조·동기화·백업
- **정본(라이브)** = 로컬 디스크(예 `D:\법학볼트\` 또는 `C:\Vaults\법학`). 개인 폴더(1.민사~9, sync, outputs, .agent, 6.진도관리 등) 이전.
- **2차 백업** = Google Drive로 **단방향 push**(rclone copy 또는 Obsidian Git+Local Backup). Obsidian 종료 상태에서. 버전이력 확보.
- **3차 백업** = git(khulaw) 유지(텍스트·룰·스킬). add -A 금지 유지.
- **공유드라이브** = `0.공유드라이브/` Drive 잔류, 읽기·복사만(#16-B).
- **모바일** = 로컬볼트 → 폰 **단방향 마크다운 미러**(Obsidian Sync 선택동기화 또는 rclone). 제외: outputs/·PDF·이미지·.agent·_trash(폴더 제외 + 전역 확장자 토글 조합 — 폴더별 확장자 규칙은 미지원).
- **선결 디커플:** 모든 룰·스크립트의 `H:\내 드라이브`를 단일 `VAULT_ROOT` config(`.agent/config/vault.json`)로 치환 → 이주가 1줄 변경이 됨(이주 안 해도 가치 큼).

### 축 b — 지식층
- **frontmatter 표준(Master Property Schema)** 선신설: `과목/쟁점/조문[]/판례[]/회독(number)/중요도/상태/source/type`. 타입 전역지정. **인라인 `주제::`는 유지**(카드 파이프라인 grep 계약 보존), YAML을 **추가**(둘 다).
- **Obsidian Bases 도입**(코어): .base 3~4종 — ①진도 보드(6.진도관리 frontmatter) ②사례답안 GREEN/YELLOW/RED ③SRS due ④위키 쟁점 인덱스(과목/회독). 진도_board.html 정본은 유지하고 Bases는 보조 뷰부터(이중정본 회피).
- **MOC/폴더/태그**: 현 _index.md MOC + 원자 쟁점노트 유지(정설과 일치). 폴더 최소·≤2단, 태그는 발견용.
- **링크 무결성**: ①Obsidian 'rename시 링크 자동갱신' 설정 ON ②'Find orphaned/broken links' 플러그인으로 탐지(0.공유드라이브 ignore) ③log_file_op.py --execute에 fix-renamed-links 헬퍼 추가(스크립트 이동분 복구) ④주간리뷰에 깨진링크·고아 점검 편입.

### 축 c — 학습 워크플로우
- **찌라시 재정의**: 수동 요약본 ❌ → **인출 리허설**(백지에서 재구성하며 압축, 산출물을 카드로 환류). §5.1 '점진압축'을 '회차별 백지인출→압축'으로 구현.
- **카드 규율 보호**: 위키/링크 확장이 카드 시간을 잠식하지 않게. 자작카드 커버리지가 인과 동력(Deng).
- **인터리빙 규칙**: daily-drill에 '혼동 쟁점' 인터리빙 명시(회독1+), 회독0은 블록.
- **주간리뷰 신설(최고 ROI 갭)**: 토요일(일요 skip) 1회. ①주간 drill/SRS/사례 집계 ②시험 역산 페이싱(마지막 3~4주 복습선점, 배점×난이도 주별분배) ③미완 롤포워드 ④다음주 과목별 3개 토픽우선순위(`weekly_subject_prep` 필드 재활용) ⑤약점→SRS 우선순위. 산출 `sync/_meta/` 또는 6.진도관리.
- **진단표**: 누적 데이터 적재 시작(현재 빈 weak.json) + 주간리뷰가 반복약점 surface.
