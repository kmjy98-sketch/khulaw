# 법학 글쓰기 기능 설계

핵심: 이 볼트 글쓰기 자산은 이미 **얇은 로더(기록형풀이) → 정본자산(sync/_meta/*) → 검증패스(#45-C)** 패턴. 발제문·자소서도 같은 단일근원에 얹는다 — 신규 복제가 아니라 **기존 산출물에서 골격 추상화 + 프로세스 문서를 로더로 승격**. **3형제 단일근원 목표**: [[서면종류별_작성가이드_2026-06-20]](기존) + 발제문_작성가이드(①) + 자소서_작성가이드(②). 어법은 전부 글다듬기로 위임(중복 제거).

## ① 발제문 작법 가이드 — 골격 (사용 가능)
정본 위치 제안: `sync/_meta/발제문_작성가이드_{날짜}.md`(서면가이드 형제). 추상화 근거(알고리즘담합 발제본 역설계): 들어가며→개념·유형론→해외동향→국내 현행법·입법→비교표→토론쟁점→결론.

# 발제문 작성 가이드 (학회 발제, 추상화 — 원문 복사 아님)
> 발제문은 '법원 제출 서면'이 아니라 '학술 토론용 논점 제시문'. 조문·판례는 law_api.py 재확인.

## 0. 발제문이 서면과 다른 점 (장르 정의)
   - 목적: 결론 관철(서면)이 아니라 '토론 점화'. 일방 대리가 아닌 양설 균형 제시
   - 평가축: 승소가 아니라 쟁점의 신선도·논의 깊이·균형성
   - 두괄식 유지하되 '주장'이 아니라 '문제제기'를 앞에

## 1. 공통 골격 5단 (쟁점제시 → 학설·판례정리 → 검토의견 → 결론)
   가. 들어가며 — 배경 + 핵심쟁점 1문장("~로 어디까지 포섭되는가")
   나. 개념·유형 정리 — 정의·구별·유형론(표로 스펙트럼화)
   다. 학설·판례·비교법 — 국내 현행법(조문)/학설 대립(긍정·부정+논거+출처)/판례(검증된 사건번호만, 미검증 [검증필요])/해외동향
   라. 검토의견 — 발제자 평가. 지지설+근거 또는 절충
   마. 토론쟁점 — A·B·C 독립 논점 분기(청중이 고를 수 있게)
   바. 결론 — 남는 과제 2~3개로 압축(전부 해결 아닌 '미해결 명시')

## 2. 유형별 변형
   가. 입법론형(개정안) — 현행법 공백→취지→잔존과제
   나. 판례평석형 — 사실관계→판시→법리분석→비판·지지
   다. 비교법형 — 쟁점→국가별 대응→비교표→국내 시사점
   라. 자문연계형(실무발제) — 쟁점→법리→로펌/실무 적용점 (자소서 IV 소재와 교차)

## 3. 검토의견 원칙 (발제문 핵심 차별)
   - 양설 균형 후 입장: "~설이 타당. 다만 ~한계"
   - 단정 회피 아닌 '근거 있는 잠정 결론' + 반론 여지 명시

## 4. 형식·인용·검증
   - 조문 [[§40]]/판례 [[대판 YYYY.M.DD, 사건번호]] 백링크(#35)
   - 직접인용 원문 연속부분만(#34, 독립판 7·8)
   - 산출 직후 law_api.py verify-text 일괄검증(#45-C)
   - 비교표·유형표 적극(법률문장론 도표 효과)

## 5. 어법 최종 패스 — 글다듬기 9원리 1패스(외국어 회피 #37, 단 비교법 고유명사 보존)

## 6. 흔한 누락 체크리스트
   - [ ] 핵심쟁점 1문장 명시 / [ ] 학설 대립구도 / [ ] 검토의견 입장+근거
   - [ ] 판례 사건번호+원문 직접인용(law_api) / [ ] 토론쟁점 독립 분기
   - [ ] 결론이 미해결 과제 정직히 / [ ] 비교가 '칸' 아닌 '스펙트럼'

## ② 자소서 프로세스 → 얇은 로더 SKILL 승격 설계
현 상태: `자소서_작성_검토_프로세스.md`가 5.기타/발제문_백업/ 하위 **4벌 분산**, 트리거 부재로 자동발동 안 됨. 율촌 자소서는 sync/자소서/에서 수작업 운영.

**(A) 정본 1벌 확정 + 나머지 격리(사용자 승인 후)**: 가장 완전한 사본 1벌 → `sync/_meta/자소서_작성가이드_{날짜}.md` 승격(3형제 완성). 나머지는 #49 은퇴 프로토콜로 `.agent/_retired/` 격리(log_file_op.py 로그). **이동은 메인이 사용자 승인 후.**

**(B) 얇은 로더 SKILL.md(기록형풀이 패턴)** — `name: 자소서작성`, 트리거 "자소서/자기소개서/지원동기 써/자소서 검토/로펌 자소서". 실행순서: ①sync/_meta/자소서_작성가이드 읽기 ②모드분기(신규작성/검토) ③어법은 **글다듬기 호출**(가이드 내 어법표 복제 대신) ④검증 단정 식별(로펌정보·법령·통계 미확인 [확인필요], 지어낸 활동 금지 #1·#2). 산출: sync/자소서/{로펌}/.

**(C) 단일근원 핵심**: 자소서 프로세스 문서가 법률문장론 어법표를 자체 복제(V-1~6) → **글다듬기가 이미 동일 9원리 정본**이므로 로더는 글다듬기 호출하고 어법표는 "→ 글다듬기 참조"로 위임.

**(D) #17/#48 레지스트리**: CLAUDE.md #17 표에 "자소서 작성·검토 / 자소서작성 Skill" 1행 추가 대상(룰 편집은 메인 결정).

## ③ gate / [검증필요] 태그 일반화안
분산 진단: [검증필요](법령·판례, 기록형 R3·R4·독립판6) / [확인필요](로펌정보·통계, 자소서 프롬프트6) / [불명확:A/B](#6) / 공백·불명(독립판 3단계) / gate(claude-for-legal attorney-review). 같은 "미검증"을 장르마다 다른 태그 → 검증패스 일관포착 난.

**2축 통일(정본 정의를 sync/_meta/, 전 글쓰기 자산 공유)**:
```
[검증필요]   — 법령·판례 단정인데 law_api.py 미통과/미조회
[확인필요]   — 사실·출처(로펌정보·통계·외부견해·날짜) 1차출처 미확인
[불명확:A/B] — 식별자 후보 복수(조문·사건번호·선고일)
[공백]       — 소스에 해당 사실 자체 없음(지어내기 금지)
[보류]       — 자료부족 판단 유예
```
**제출 전 게이트**(claude-for-legal 이식): 모든 산출물은 위 5태그 1개라도 남으면 "제출 가능" 선언 금지. 검증자(#45-C)가 태그 잔존 스캔→보류·보고만(자동수정·삭제 금지). law_api verify-text의 `unverified`는 자동 [검증필요] 강등. 과잉방지: 단순집계·대화성·한줄수정엔 미가동(#8). 룰 반영(설계만): CLAUDE.md #6에 5태그 정의, #45-C에 "제출 전 게이트" 1줄.
