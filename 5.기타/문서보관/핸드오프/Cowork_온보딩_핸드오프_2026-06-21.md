# Claude Cowork 온보딩 핸드오프 (2026-06-21)

> Claude Code 세션에선 Cowork 온보딩 마법사(역할·플러그인·스킬 도구)를 구동할 수 없음을 확인(이 환경엔 해당 도구 없음, 커넥터 레지스트리 빈 상태). **아래는 Cowork 앱에서 직접 수행할 단계.** OAuth·플러그인 설치는 본인이 클릭.

---

## A. Cowork 앱에서 할 단계 (순서대로)
1. **Cowork 실행** (데스크톱 앱 또는 claude.ai의 Cowork).
2. **역할 선택**: '학생/연구' 또는 'productivity'. 없으면 건너뛰기.
3. **커넥터 — Google Drive 연결**(핵심): 연결하면 `H:\내 드라이브`의 OCR·카드·보고서·`.agent/state`·SKILL.md를 Cowork가 읽음. → 콘텐츠는 이걸로 거의 다 들어감.
4. **플러그인/스킬**:
   - 마켓 플러그인은 사무 지향이라 법학 학습용은 없음 → 무리해서 설치할 것 없음.
   - 당신 로직을 가져가는 2가지 길:
     - (a) **커스텀 스킬 등록**(Cowork가 지원하면): `daily-drill`·`case-answer-review` SKILL.md(+필요 스크립트)를 플러그인/스킬로 추가.
     - (b) **문서 기반 운용**(더 간단): 로직이 SKILL.md 문서에 다 있으니, Cowork에 "이 SKILL.md를 규칙으로 읽고 Drive 파일로 수행"하라고 목표를 주면 됨(LLM 네이티브).
5. **시험 가동(검증)**: Cowork에 목표 1개를 줘본다 —
   > "`.agent/state/진도_현황.json`에서 회독≥1 복습단원을 찾고, 각 단원에 `case_problem_answer_index.json`의 진도매핑으로 연결된 사례 문제를 골라 제시해줘. 답안은 채점 때만 열어."
   → 이게 되면 핵심 흐름(진도→사례 연결)이 Cowork에서 산다는 증거.

## B. 그대로 넘어가는 것 / 안 넘어가는 것
| 자산 | Cowork |
|---|---|
| Drive 콘텐츠(OCR·카드·보고서·state·SKILL.md) | ✅ Drive 연결로 |
| Google Drive MCP | ✅ 네이티브 커넥터 |
| 커스텀 스킬(daily-drill 등) | ◐ 재등록/문서기반 (포맷 공용 가능성) |
| korean-law-mcp(커스텀 MCP) | ⚠ 커스텀 MCP 등록 지원 여부 앱에서 확인 |
| Python 스크립트(build_session 등) | ✗ 임의 셸 실행 불확실 → **LLM 네이티브로 대체 권장** |
| Workflow 다중에이전트 스크립트 | ✗ 비이식 → Cowork 자체 오케스트레이션으로 재표현 |
| Claude Code 메모리 | ✗ 비이식 → 문서로 import하거나 Cowork 메모리 재구성 |

## C. 권고 — 온보딩 전에 Phase A를 먼저 하면 손실 0
지금 그대로 온보딩하면 **안 넘어가는 부분(Workflow·Python·메모리)** 때문에 반쪽이 됨. 순서를 이렇게:
1. **Phase A(여기 Claude Code에서, 내가 함)**: `build_session.py` 등 파이썬 헬퍼를 **LLM 네이티브 스킬 단계**로 전환(진도 join·단원 선정·로깅을 문서 규칙으로). → Python 의존 제거 = Cowork에서 그대로 읽고 실행 가능.
2. **그다음 Cowork 앱에서 A단계** 수행 — Drive 연결 + 위 검증 목표 1개로 동작 확인.
3. 되면 일일 루틴(자율 오케스트레이션)을 Cowork에 맡겨 **수동 부담↓**.

## D. 정직 고지
- Cowork의 커스텀 스킬/커스텀 MCP 등록 가능 범위는 앱에서 실제 확인 필요(추측 아님). 스킬 포맷은 Anthropic 공용일 가능성이 높아 이식 여지 있음.
- 검증 목표(A-5)가 Cowork에서 돌면 "이식 가능", 안 돌면 "Claude Code 유지 + 부분만 Cowork" 하이브리드로.
