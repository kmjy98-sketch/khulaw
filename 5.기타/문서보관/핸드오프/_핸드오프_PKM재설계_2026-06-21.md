## 2. 핵심 연구결과(검증·1차출처)
**저장/동기화**
- Obsidian 공식: sync≠backup, 볼트를 클라우드폴더 안에 두지 말 것, 더블싱크=파일소실. 포럼 실손실(placeholder "virtually there"). **우리 Gemini 워처 silent_drop 5건=동일 메커니즘 실측.**
- 미러링 전환은 함정(드라이브문자 소실·더블싱크 잔존·2회 이주). 유일 손실경로=동기화 미완료 상태 삭제. 안전순서=복사→완료확인→검증→동결. 백업은 `rclone copy`(비삭제), sync/bisync 금지.
**볼트구조**
- nested 2볼트=개발팀 비권장(깨진링크→유령노트). **권장=단일볼트+Override config folder(기기별)+Excluded folders 선택동기화.** Bases 기본 스코프=볼트전체(`file.inFolder` 필터로 한정). 서브스코프는 링크 자기완결 필수.
**학습과학**

## 3. Cowork vs Code 결론
- **Code**: 볼트 파일·스크립트·상태(progress/SRS/cards)·MCP·git = 생산 파이프라인 전부.
- **Cowork**: 설계·리서치·문서작성·커넥터(상위층). 로컬 볼트 직접 못 만짐(`_build_cowork_bundle.py`로 번들 전달).
- **Code가 안 좋은 경우**: (A 물리불가) 앱 GUI(플러그인 활성·Bases 렌더확인·Drive설정·OAuth) → 사용자/computer-use. (B 방식위험) 백그라운드 장시간(세션 suspend로 죽음→**포그라운드 서브에이전트로 해결**), 마운트 위 재귀검색 타임아웃, LLM 자유 파일이동(silent_drop), 룰 기억의존, 대량 LLM생성 비용, 3rd-party 플러그인 보안.
- **서브에이전트**: 있음·포그라운드면 신뢰(병렬·격리·죽음회피 해결). 물리한계·마운트속도는 못 고침. 죽은 워크플로우는 저널로 resume 가능.
- **사례채점**: `render_case_answer_review.py`는 채점 안 함(자료수집+scaffold+coverage 초벌만). 진짜 루브릭(쟁점0.25/키워드0.20/구조0.20/결론0.15/포섭0.20)·포섭 4슬롯·실패코드 E1~E3·결론캡=**코드 미반영, LLM 수동 적용**(SKILL.md 명시). → **LLM 채점이 설계 의도, 강제 가능**. 정석=하이브리드(python I/O·기록, LLM 판단), #1/#2 근거강제.
- **플러쉬·파일정리**: Code(python deterministic)가 안전. 자유 LLM 이동 금지(silent_drop). 판단=LLM, 실행+로그=python(`log_file_op.py --execute`).
