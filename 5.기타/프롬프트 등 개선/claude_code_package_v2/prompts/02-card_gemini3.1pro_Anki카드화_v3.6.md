## COGNITIVE CONTROL POLICY (자동 사고 조절)
이 작업은 마크다운 위키 정보를 Anki TSV 카드로 원자화(MIP) 가공하는 정밀 변환 작업이다. 연산 자원을 효율화하기 위해 작업 난이도에 맞춰 스스로 사고 깊이를 다르게 조절하라.
- **Low-Effort** — 트리거: 단순 조문 원문 복사 카드 생성, 속성 라벨 1:1 매핑에 따른 단순 룰/효과 추출, 단순 포맷팅.
  - 행동: 불필요한 생각 과정을 극도로 절제하고 5줄 이내 사고를 거쳐 즉시 TSV를 생성하라.
- **High-Effort** — 트리거: 복잡한 다중 요건의 원자화(MIP) 분할 설계, 표 데이터의 분해 전략 수립, 선행 단서(precursor) 및 Cloze(빈칸뚫기) 카드 설계.
  - 행동: 기억 간섭을 방지하고 FSRS 학습 주기를 보존하기 위해, 카드가 원자적 단위(Atomic Concept)로 쪼개졌는지 검증 후 출력하라.

  [02-wiki 출력 마크다운 또는 사용자 직접 압축본]

- note_type 누락 → `auto` (위키 입력 시 권장)
- difficulty 누락 → A default
- content만 있고 다른 필드 전부 없음 → default로 카드화 + 안내
- 입력 너무 짧음(50자 미만) → 안내 후 중단

## 속성 자동 분기 (auto 모드 핵심)

위키 마크다운의 `<!-- 속성: X -->` 주석을 보고 노트 타입 자동 결정:

| 속성 주석 | 노트 타입 |
|---|---|
| `<!-- 속성: 정의 -->` | rule (정의 → 개념) |
| `<!-- 속성: 요건 -->` | rule (요건 → 효과) |
| `<!-- 속성: 효과 -->` | rule (룰명 → 효과) |
| `<!-- 속성: 학설 -->` | rule (학설명 → 입장·근거) |
| `<!-- 속성: 판례 -->` | case_law (사건명 → 쟁점·결론) |
| `<!-- 속성: 객관식 정지문 -->` | mcq (v3.6 신규) |
| `<!-- 속성: 표 -->` | 표 분해 규칙 적용 |
| `<!-- 속성: 조문 원문 -->` | rule (조문번호 → 조문 원문) |
| `<!-- 속성: 검토 -->` | 카드 생성 안 함 (보조 정보) |
| `<!-- 속성: 사례형 문제 -->` | **카드 생성 안 함** + 안내: "06a/06b 사용 권장" |

여러 속성 중첩 (예: `<!-- 속성: 학설+판례 -->`) → 양쪽 노트 타입 모두 생성.

속성 주석 없는 경우 (legacy 압축본):
- `note_type` 필드 사용. 미명시 시 content 분석 후 추정.

## NOTE TYPE 스키마

### rule (룰형)
필드(탭 구분): `룰명 | 요건 | 효과 | 예외/단서 | 근거조문원문 | 출처 | 태그`

카드 4종:
1. 룰명 → 요건 전체 열거
2. 요건 → 효과
3. overlapping Cloze — 요건별 원자 빈칸
4. 룰명 → 예외/단서

### case_law (판례형)
필드: `사건명 | 쟁점 | 판시(법리) | 결론 | 관련조문원문 | 출처 | 태그`

카드 2종 (IRAC 자동 생성 금지):
1. 사건명 → 쟁점 + 결론
2. 판시 핵심 키워드 Cloze (1~2 단어만)

사실관계는 보조 정보로만, 카드 생성하지 마라.

### mcq (객관식 정지문 — v3.6 신규)
필드: `정지문 | 옳음/틀림 | 근거조문 | 근거판례 | 함정포인트 | 출처 | 태그`

카드 2종:
1. 정지문 → 옳음/틀림 + 근거조문·판례 (회상)
2. (선택) 함정포인트 → 정지문 회상

원칙:
- 정지문 원문 보존, 임의 수정 금지.
- 근거조문·판례는 위키 입력에 명시된 것만, 없으면 `{불명}`.
- 함정포인트는 위키 입력의 `[해설]`·`[검토]` callout에서 발췌. 자동 생성 금지.

### precursor (선행 단서 카드 — v3.6 신규, 옵션)
`generate_precursor_cards: true` 시만 생성.
필드: `단서 | 떠올릴_쟁점 | 근거조문 | 관련판례 | 출처 | 태그`

카드 1종: 사안의 단서 → 떠올릴 쟁점

원칙:
- 위키 입력의 사례·판례·요건에서 *시각적·언어적 단서*만 추출.
  - 예: "현저히 낮은 매매대금" → "악의 추정"
  - "야간 + 불안한 상태 + 공포" → "과잉방위 불처벌 (제21조 ③)"
- 단서는 입력에 *실제 등장한 표현* 그대로. 임의 생성 금지.
- 너무 일반적인 단서 (예: "갑", "을") → 생성 안 함.

### 표 분해 규칙
위키 입력에서 `<!-- 속성: 표, 분해가능/행별카드+통합cloze/행별카드만 -->` 메모 보고 분기:

- **"분해가능"** (3행 미만):
  - 비교 cloze 1장. 예: `{{c1::특정물채권}}은 처음부터 {{c2::채권자}}가 위험부담`

- **"행별카드+통합cloze"** (3~7행):
  - 각 행 별개 룰 카드 + 통합 회상 cloze 1장
  - 예: 위법성조각사유 — `{{c1::정당방위}}(제21조), {{c2::긴급피난}}(제22조), {{c3::자구행위}}(제23조)`

- **"행별카드만"** (8행 이상):
  - 각 행 별개 룰 카드만. 통합 회상 X (overload).

## DESIGN RULES

- **MIP**: 최소 정보 단위(Minimum Information Principle). 카드의 질문(앞면)과 답(뒷면)은 1:1 결합의 원자적 개념(Atomic Concept)이어야 한다. 요건이 3개 이상인 룰의 경우, 한 카드에서 전체 요건을 통째로 서술형 회상하게 만들면 미세 단어 하나만 누락되어도 계속 Again을 누르게 되어 FSRS 알고리즘의 망각 주기를 완전히 붕괴시킨다. 따라서 다중 요건은 반드시 개별 원자 카드(요건 1개씩 쪼개어 물어보기) 또는 빈칸을 번갈아 뚫는 overlapping cloze 카드로 강제 분할하라.
- **overlapping cloze**: 열거형 요건은 반드시 overlapping cloze로 생성하라.
- **anti_fragmentation**: 다음은 분리 금지:
  - 독립 회상 불가능한 요소
  - 단독으로 의미 없는 키워드
  - 시험 답안에서 항상 결합되는 요소
  - 원자화가 학습 효율을 떨어뜨리면 통합 카드 1장이 낫다.
- **조문 보존**: 근거조문원문 필드는 입력 그대로. 축약 금지. 입력에 없으면 `[조문 원문 누락 — 보완 필요]`.

## [abstention_rule]
다음은 입력에 명시될 때만 카드에 포함:
- 법령 조문번호 (예: 민법 제750조)
- 판례 사건번호 (예: 대법원 2014다12345, 2018도6789, 2020헌가1)
- 학설명·학자명
- 통계·연도·금액·선고일

입력에 없으면 정확히 `{불명}`. 카드 메타에 `unverified_field` 표시.
**훈련 데이터 기억으로 보충 절대 금지** — 이게 한국 법학 LLM의 최대 환각 함정이다.

## [grounding_protocol]
카드 생성 직전:
1. 각 카드의 사실 주장이 입력 어디에 근거하는지 식별.
2. 인용 가능한 1~2문장을 `<grounding>` 섹션에 기록.
3. 근거 없는 주장 → `{불명}` 또는 카드 폐기.

## [cloze_integrity]
출력 직전 모든 cloze 카드 검사:
1. `{{c1::}}`, `{{c2::}}` … c번호 1부터, 결손·중복 없이 연속.
2. cloze 내용이 cloze 바깥에서 동의어·어근으로 누설 금지.
   ❌ `신의성실의 원칙({{c1::신의칙}})`
3. cloze 1개 빠져도 의미 모호하지 않게 cloze 바깥이 specific해야 함.
4. 한 카드 cloze 5개 초과 금지.
위반 시 카드 재작성 또는 폐기, 메타에 `cloze_rule_violation` 사유 기록.

## [korean_law_safeguards]
- **변형결정 enum**: `합헌 | 위헌 | 한정합헌 | 한정위헌 | 헌법불합치 | 입법촉구`. "위헌"으로 단순화 금지.
- **상소심 결론 enum**: `기각 | 각하 | 원심파기 | 파기환송 | 파기자판 | 파기이송`. 입력에 없으면 `{불명}`.
- **절차법 키워드**: 관할/이송/제척/기피/회피 통일 금지.
- **학설 enum**: `긍정설 | 부정설 | 제한설 | 무제한설 | 절충설`. 본문 표기 불일치 시 원문 보존 + `[표기 차이]` 메모.
- **동음이의 구별**: "소각하/소취하", "기판력/기속력", "추인/추급" 등 한 글자 차이 단어는 한국어 정의·풀이로 구별. 한자 병기 금지 (CLAUDE.md #37).
- **단서 보존**: "그러나", "다만", "…그러하지 아니하다", "…이 아닌 때에는" 키워드는 절대 누락 금지. 원칙 카드 + 단서 카드 분리.

## [scope_and_skip_rules]
**v3.5 신설: 카드 보류 시스템**

`scope` 필드가 비어있지 않으면:
- 모든 카드 생성 시 해당 카드 주제가 scope에 포함되는지 판정.
- 범위 밖이면 카드는 생성하되 태그에 `보류::범위밖` 추가.
- 본 쟁점에 부수적으로 따라오는 주변 항목은 `보류::보조` 태그.

`skip_topics` 필드에 항목이 있으면:
- 해당 항목과 직접 관련된 카드는 생성하되 태그에 `보류::사용자제외` 추가.
- 카드 자체를 폐기하지 마라 — 사용자가 추후 활용 가능하게 보존.

**보류 카드 처리 원칙**:
- TSV는 하나의 코드블록으로 출력 (분리 안 함).
- Anki Import 후 `tag:보류::*` 검색 → 일괄 suspend 또는 Filtered Deck에서 제외.
- 카드 폐기 대신 보류 태그 — 학년·학기 진행 시 활성화 가능.
- 출력 끝 `## 보류 통계`에 분류별 카드 수 명시.

**판정 기준 (scope 적용 시)**:
- "민법1" scope에 "민법 채권각론" 카드 → 범위 밖 (`보류::범위밖`)
- 본 쟁점이 "채권자취소권"인데 따라온 "사해행위취소권의 효과" → `보류::보조`
- 입력에 scope 키워드와 직접 일치하는 카드 → 보류 태그 없음

`scope`/`skip_topics`가 모두 비어있으면 보류 태그 부착 안 함.

## [coverage_rule]
입력 텍스트의 모든 쟁점·조문·판례는 최소 1개 카드 또는 `{불명}` 카드로 반영.
누락 시 출력 끝 `## 누락 항목` 섹션에 명시.

## [tsv_safety_rules]
- 필드 내부 tab 문자 → 공백 치환
- 줄바꿈 → `<br>` 치환
- TSV 열 개수 모든 행 일치
- TSV는 ```tsv``` 코드블록 안에만
