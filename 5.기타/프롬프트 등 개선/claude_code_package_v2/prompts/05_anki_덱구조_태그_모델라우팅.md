## 3. 안티그래비티 앱 vs AI Studio vs Gem (01·02-wiki 실행 인프라)

**Phase 2 권장 = 안티그래비티 앱(데스크톱)**. 01 OCR·02-wiki를 한 앱에서 연속 처리하며 원문 PDF를 직접 첨부.
아래 표는 안티그래비티 앱을 쓰지 않을 때의 대안 인프라(AI Studio/Gem) 비교 참고자료.

| 항목 | AI Studio | Gem | 일반 Gemini 채팅 |
|------|-----------|-----|----------------|
| URL | ai.google.dev | gemini.google.com/gems | gemini.google.com |
| Prompt 잠금 | system_instruction (강함) | Gem instructions (강함) | 채팅 컨텍스트만 (약함) |
| 모델 선택 | 명시 (gemini-3.1-pro) | picker에서 "Pro" 수동 선택 필수 | picker 수동 선택 |
| temperature 제어 | ✓ (1.0 권장) | ✗ (기본값) | ✗ |
| thinking_level 제어 | ✓ (high 권장) | ✗ (기본값) | ✗ |
| media_resolution 제어 | ✓ (PDF는 high 필수) | ✗ | ✗ |
| max_output_tokens | ✓ (64000 설정) | ✗ (기본 cap) | ✗ |
| 모바일 사용 | ✗ (불가) | ✓ | ✓ |
| 비용 | API 종량 | Pro 구독 ($20/월) | Pro 구독 |
| 재사용성 | 매번 prompt 등록 또는 저장 | Gem 한 번 만들면 재사용 | 매 채팅마다 재입력 |

### 매칭 가이드 (v3.6 Phase 2 — 2모델 역할분담)
- **01번 (OCR)**: 방대한 원문 PDF 저비용 처리 → **안티그래비티 앱(데스크톱, Gemini 3.5 Flash)**. 마킹 인식 정밀도 필요 시 AI Studio(media_resolution: high) 대안
- **02-wiki (위키화)**: 방대한 원문 → 본문 보존 위키로 구조화 → **안티그래비티 앱(데스크톱, Gemini 3.5 Flash)**. 구조 추론 품질 우선 시 Claude Opus 4.8 대안
- **02-card (단권화)·06a·06b**: 위키(구조화 텍스트)만 입력받아 정교한 카드 빌드 → **Claude Opus 4.8** (최상급 추론·지시 준수)
- **04번 (NotebookLM)**: v3.6에서 보조용으로 강등 (Anki 카드가 메인)
- **비용 논리**: Opus가 PDF 재OCR 없이 구조화 위키만 입력 → 입력 비용↓ + 카드 퀄리티 최상

### 안티그래비티 앱(데스크톱, Gemini 3.5 Flash) 설정 절차 (01·02-wiki)
1. **안티그래비티 앱**(데스크톱)에 단계별 프롬프트(`01_claude_*`, `02-wiki_claude_*`)를 system instruction으로 등록
2. 모델은 **Gemini 3.5 Flash** (대용량·저비용 위키화 목적). 원문 PDF/OCR을 앱에 직접 첨부
3. 출력 위키 마크다운을 02-card(Opus 4.8) 입력으로 전달
   - 앱 사용: 01 OCR → 02-wiki를 같은 안티그래비티 앱에서 연속 처리 (단계마다 system instruction 교체)

### Claude Opus 4.8 설정 절차 (02-card·06a·06b)
1. Claude.ai Project 또는 Claude Code에 프롬프트(`02-card_claude_*`, `06a/06b_claude_*`) 등록
2. 입력은 02-wiki가 만든 위키 마크다운 (원문 직접 입력 지양 — 비용 논리 유지)
3. Project 이름: `02-card_단권화_카드화`, `06a_사례집_manual`, `06b_사례집_extract`
4. 저장 후 매 작업 시 같은 Project 선택

## 5. 02-wiki 위키화 운영 (v3.6 신규)

### 5.1 워크플로우
```
1. 01번 출력 OCR 마크다운을 outputs/01_ocr/책이름_chunk_NNN.md에 모음
        ↓
2. 청크별로 02-wiki 호출 (안티그래비티/Gemini 3.5 Flash — 품질 우선 시 Opus 4.8)
   입력: source, book_type_hint (선택), chunk_anchor, content_source
   출력: outputs/02_wiki/책이름_chunk_NNN.md
        ↓
3. (선택) Obsidian vault의 책이름/ 폴더에 복사 → wiki link 자동 활성화
        ↓
4. 위키 마크다운을 02-card·06a·06b의 입력으로 전달
```

### 5.2 책 유형 자동 식별 검증
첫 청크 처리 후 출력 첫 줄에 다음과 같은 추정 결과:
```
책 유형 추정: 단권화 (신뢰도 95%, 시그널 분포: 정의 8%, 요건 18%, 학설 12%, 판례 41%, 표 6%, 사례 0%, 객관식 0%)
hint 일치 여부: 확인됨 (또는 충돌 — hint 우선 적용)
```

- 신뢰도 80% 이상 → 다음 청크 자동 진행
- 신뢰도 60~80% → 사용자 검토 후 진행
- 신뢰도 60% 미만 → 사용자 hint 명시 권장

### 5.3 마크다운 충돌 회피 확인 (Obsidian 호환)
v3.6 위키화는 책 원본의 박스 라벨을 Obsidian callout으로 변환:

| 원본 | 변환 |
|---|---|
| `[논점정리]` | `> [!summary] 논점정리` |
| `[관련판례]` | `> [!example] 관련판례` |
| `[해설]` / `[모범답안]` | `> [!note] 해설` |
| `[주의]` | `> [!warning] 주의` |
| `[중요]` | `> [!important] 중요` |
| `[개념]` / `[사안]` / `[설문]` 등 인라인 라벨 | `**[개념]**` 굵게 |
| `[불명]` | `{불명}` (link 시도 회피) |
| `[[backlink]]` | 유지 (Obsidian wiki link) |

확인 방법: 위키 마크다운을 Obsidian에 열고 callout이 박스로, backlink가 활성 link로 렌더링되는지 확인.

### 5.4 속성 라벨 검증
모든 소목차에 `<!-- 속성: X -->` 주석 부착 확인. 누락 시 02-card 자동 분기가 작동 안 함.

### 5.5 Obsidian vault 동기화 (선택)
- vault 구조: `Obsidian_vault/단권화/{과목}/{책이름}/`
- 청크 파일을 그대로 복사 → backlink가 자동 활성화
- frontmatter의 `book_type`, `attribute_distribution` 메타로 Dataview 대시보드 구성 가능

## 4. 06a vs 06b 분리 운영

### 사용 시기 가이드

| 상황 | 권장 |
|------|------|
| 변시 직전 정밀 학습, 사례집 직접 풀고 모범답안 비교 완료 | **06a (manual)** |
| 학기 중반, 풀이 포함 사례집 빠르게 훑기 | **06b (extract)** |
| 풀이 없는 사안만 있는 사례집 | **06a (manual) — 직접 풀어서 user_issue_list 작성 필수** |
| 변시 6개월 전, 사례집 새 책 입수 후 1차 카드화 | **06b → 사후 검증 → 06a로 재정리** |

### 학습 효과 vs 환각 위험 trade-off

| 모드 | 학습 효과 | 환각 위험 | 검증 부담 |
|------|---------|----------|---------|
| 06a (manual) | 매우 높음 (active retrieval) | 매우 낮음 | 없음 |
| 06b (extract) | 중간 (수동 인지) | 낮음 (출처 grounding 강제) | **사후 검증 필수** |

### 06b 카드 사후 검증 워크플로우

1. **Anki Import 직후**: 06b 카드는 모두 `검증필요::AI추출` 태그 자동 부착됨.
2. **검증 학습 별도 운영**: Filtered Deck 생성
   ```
   tag:검증필요::AI추출 -is:suspended
   ```
3. **검증 절차** (카드 한 장씩):
   - 카드 표시 → 사례집 원본 풀이 부분 펴고 대조
   - 쟁점·조문·판례 키워드가 풀이와 일치 → 검증 OK → 태그 제거
   - 일치 안 함 또는 누락 → 손으로 수정 → 검증 OK → 태그 제거
   - 풀이 영역 식별 자체가 잘못됨 → 카드 폐기 → 06a로 재작성
4. **태그 일괄 제거**: Anki Browse에서 `tag:검증필요::AI추출 마크검토완료` 검색 후 우클릭 → 태그 제거.

### 06b 운영 권장
- 1주에 한 번 정도 `검증필요::AI추출` 태그 카드 일괄 검증 (50-100장 단위).
- 검증 안 된 카드가 200장 이상 누적되면 새 06b 생성 일단 중단.
- 검증 완료된 카드만 본 학습 덱 (암기장-사례형::{과목})에서 활성화.

### Anki 운영 — 보류 태그 일괄 처리

Import 후:
```
tag:보류::*
```
검색 → 일괄 suspend (Ctrl+J).

또는 Filtered Deck 조건:
```
-tag:보류::* -tag:검증필요::*
```
보류·검증 안 된 카드 제외 학습.

### 보류 카드 활성화 (학기 진행 시)

예: 1학년 2학기 → 2학년 1학기 진입 시 민소법 활성화:
```
tag:보류::범위밖 tag:과목::민소
```
검색 → unsuspend (Ctrl+J).

## 3. PDF 분할 워크플로우

### Step 1: 사용자 로컬 분할
```bash
pip install pypdf
python pdf_split_100p.py 형법총론.pdf
# → 형법총론_chunks/ 디렉토리에 100p 단위 파일들 + split_log.txt
```

### Step 2: 청크 단위 AI Studio 처리
각 청크 업로드 시 사용자 메시지 첫 줄:
```
CHUNK: pages 001-100 | total 100 pages | source: 형법총론 | mode: full extraction
모드: A
[PDF 첨부]
```

01번 system_instruction의 [FIDELITY_CONTRACT]가 임의 압축을 차단한다.

### Step 3: 청크 간 일관성
- 같은 책 다음 청크는 **새 안티그래비티 세션**에서 시작 (Gemini 다중턴 PDF 회귀 버그 회피)
- 카드 ID 누적 카운트는 사용자가 수동 관리 (예: 청크1=C0001-C0099, 청크2=C0100-...)

## 4. Anki 덱 구조

```
기본서 (부모 덱 — 주력 회독서)
├── 민사법    (논점민법)
└── 형법      (김형총)

암기장-객관식 (부모 덱 — 쟁점 암기 + OX·MCQ 정지문)
├── 헌법      (핵정300 / 강성민1·2·3 / 유니온헌 — 헌법은 기본서 없이 핵정300만)
├── 민사법    (쟁점노트 / 논민소 / 신민사 선택형)
└── 형법      (compact형총 / 반반형법)

암기장-사례형 (부모 덱 — 사안→쟁점 포착·목차 구성)
├── 헌법      (해커스헌)
├── 민사법    (민사례1 / 송영곤 사례연습)
└── 형법      (작은변사기)

교수저 (부모 덱 — 참고용, 완전 무시: 신규 0·임포트 시 전체 suspend 권장)
└── 민사법    (김준호민총·물권·채총·채각)

(과목 확장 시 각 부모 아래 서브덱 추가. 민소는 민사법에 통합(논민소).
 책 단위 세션이 필요하면 서브덱이 아니라 `출처::약어` 태그 필터덱 사용 — 전 카드 부착됨)
```

**라우팅 (Anki Import 시 — 책 약어 기준 배정, 위 트리 괄호 참조):**
- 논점민법·김형총 → `기본서::{과목}` / 쟁점·OX·MCQ책 → `암기장-객관식::{과목}` / 사례집(`*_사례형_*`, 06a·06b 포함) → `암기장-사례형::{과목}` / 김준호 4종 → `교수저::민사법`(전체 suspend)
- 덱이 실제로 좌우하는 것은 ①세션 묶음 ②preset(retention·신규/일) ③신규 도입 흐름 — 스케줄은 FSRS가 카드 단위로 처리하므로 회독이 쌓이면 분류와 무관하게 수렴한다. 덱은 이 4부모 × 과목에서 더 세분하지 않는다
- 주제·난이도·빈출·출처·세부 속성은 전부 **태그** (책 단위 운용 = `출처::약어` 필터덱)
- 중복: 교수저(김준호) suspend로 기본서↔교수저 중복 부담 해소. 잔여 중복(논점민법↔쟁점노트 등)은 Phase 3 클러스터링 시 암기장 우선

**복습 운영:**
- 평일 진도: 기본서·암기장 과목 서브덱에서 신규 카드 도입 (교수저는 신규 0)
- 매일 복습: 기본서(부모) + 암기장-객관식(부모) 회독 — 각각 Random gather 과목 인터리빙
- 사례 세션: 암기장-사례형 덱을 별도 블록으로 학습 (시험 전 집중 드릴)
- 시험 직전: Filtered Deck 약점·기출 집중
- 교수저(김준호): 평소 suspend — 필요한 쟁점만 `주제::` 태그로 검색해 개별 unsuspend
- rule Card 1(요건 전체 열거) 채점 운용: 목차 복원 여부만 판정 — 요소 1개 누락 시 Again 대신 Hard (요소별 진단은 Card 3 overlapping cloze 담당, MIP)
