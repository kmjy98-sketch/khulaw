## 0. 안티그래비티가 맡는 범위 (요약)

| 단계 | 작업 | 소스별 필요 여부 |
|---|---|---|
| **01 OCR** | PDF → 마킹·헤더·조문 마크다운 | 핵심정리헌법 + 사례연습26 (쟁점노트·반반형법·민사법사례연습2는 md 보유 → 생략) |
| **02-wiki** | 마크다운 → 위키(속성 라벨·callout·backlink·보존율 ≥0.90) | 단권화 3종 전부 (+ 사례집은 선택) |

> 산출물(위키 md)을 Claude Opus 4.8(02-card)에 넘기면 카드 빌드. 안티그래비티는 카드(TSV)를 만들지 않는다.

## 1. 앱 세팅 (1회)

### 1-1. 프롬프트 등록 (system instruction)
- 01 OCR용: `prompts/01_gemini3.1pro_마킹_구조_조문_추출_v3.6.md` 전문
- 02-wiki용: `prompts/02-wiki_gemini3.1pro_위키화_v3.6.md` 전문
- 단계 전환 시 system instruction 교체(같은 앱에서 연속 처리).

### 1-2. 모델·파라미터
| 항목 | 값 |
|---|---|
| 모델 | Gemini 3.5 Flash (대용량·저비용 위키화) |
| temperature | 1.0 (낮추면 looping — 변경 금지) |
| thinking_level | high |
| media_resolution | **high** (01 OCR PDF에서 마킹 인식에 결정적) |
| max_output_tokens | 64000 |

> 앱에서 파라미터 제어가 안 되면 01 OCR만 AI Studio(`ai.google.dev`, system_instruction + media_resolution high)로 대체. 02-wiki는 앱에서 가능.

### 1-3. 운영 패턴
- **01 OCR**: 청크마다 새 세션(Gemini 다중턴 PDF 회귀 버그 회피).
- **02-wiki**: 한 책당 한 세션 가능(출력 일관성).
- 30p 청크 권장. 100p 초과 PDF는 `scripts/pdf_split_100p.py`로 사전 분할.

## 2. 소스별 실행 프롬프트 (붙여넣기용)

### 2-A. 핵심정리헌법 — ① 01 OCR

> system instruction = `01_gemini3.1pro_...md`. 아래 메시지 + PDF 첨부.

**분할 01 (헌법재판):**
```
CHUNK: pages 001-NNN | total NNN pages | source: 헌법 핵심정리 300 (헌법재판편) | mode: full extraction
모드: B
[첨부] 3.공법/_분할/핵심정리300_01_헌법재판.pdf
```

**분할 03 (기본권 + 헌법총론):**
```
CHUNK: pages 001-NNN | total NNN pages | source: 헌법 핵심정리 300 (기본권·헌법총론편) | mode: full extraction
모드: B
[첨부] 3.공법/_분할/핵심정리300_03_기본권_나머지_헌법총론.pdf
```

- 산출 회수 → `outputs/01_ocr/헌법핵심정리300_01_chunk_NNN.md` / `_03_chunk_NNN.md`
- 확인: 첫 줄 `CHUNK:` anchor + `TOTAL_CHARS:`, 페이지별 글자수 표, `{누락의심}` 사유.

### 2-A. 핵심정리헌법 — ② 02-wiki

> system instruction = `02-wiki_gemini3.1pro_...md`. 01 산출 마크다운을 content_source로.

```
source: 헌법 핵심정리 300 (제3전정4판)
book_type_hint: 단권화          ← OX·정지문 비중 높으면 "혼합"으로 재시도
chunk_anchor: CHUNK: pages 001-030 | total NNN pages | source: 헌법 핵심정리 300
content_source: |
  [여기에 01 OCR 산출 md 청크 본문 붙여넣기]
scope:                    ← 비움(전권 일괄). 보류 주석 없음
```
- 산출 → `outputs/02_wiki/헌법핵심정리300_chunk_NNN_wiki.md`

---

### 2-B. 반반형법 — 02-wiki (01 생략, 기존 md 입력)

> 입력 md: `.agent/data/ocr_chunks_reviewed/형법/반반형법/반반형법_pXXXX-XXXX__chunk_00N.md` (p1~480 검수완료).
> chunk_000/001로 30p가 2분할 → 한 청크(30p)로 합쳐 입력 권장.

```
source: 반반형법 25
book_type_hint: 단권화
chunk_anchor: CHUNK: pages 0001-0030 | total 495 pages | source: 반반형법 25
content_source: |
  [반반형법_p0001-0030__chunk_000.md + chunk_001.md 본문 이어붙여 붙여넣기]
scope:                    ← 비움(전권 일괄: 총론+각론)
```
- 산출 → `outputs/02_wiki/반반형법_chunk_NNN_wiki.md`
- 주의: **p0481-0495는 미검수**(`5.기타/교재원문_백업/형법/반반형법/_backup_phase1/반반형법_p0481-0495.md`) → 위키화 전 본문 1회 육안 확인.

---

### 2-C. 쟁점노트 — 02-wiki (01 생략, 기존 md 입력)

> 입력 md: `sync/_백업/교재원문_문서_백업_2026-05-22/1.민사/33.송영곤_쟁노/교재_추출/민사법쟁점노트_재산법_26_pXXX-XXX.md` (30p 청크 전권).

```
source: 송영곤 민사법쟁점노트 26 (재산법)
book_type_hint: 단권화
chunk_anchor: CHUNK: pages 001-030 | total 616 pages | source: 송영곤 민사법쟁점노트 재산법
content_source: |
  [민사법쟁점노트_재산법_26_p001-030.md 본문 붙여넣기]
scope:                  ← 비움(전권 일괄: 재산법+가족법+소송집행)
```
- 산출 → `outputs/02_wiki/쟁점노트_재산법_chunk_NNN_wiki.md`
- 순서: 재산법 → 가족법 → 소송집행 전권 일괄.

### 2-D. 사례집 — 송영곤 2종 (카드화는 Claude 06b/06a 담당)

> 사례집 카드화 자체는 Claude. 안티그래비티 역할은 **② 사례연습26의 md 추출(01 OCR)** 뿐.

**① 민사법사례연습2 — 안티그래비티 불필요**
- `교재_추출` md(p001-930) 보유 + 정식해설본(풀이) → Claude에 06b로 바로 투입.

**② 사례연습 26 — 안티그래비티 01 OCR 필요 (md 부재)**
> system instruction = `01_gemini3.1pro_...md`. 과목별 분할 PDF 첨부.
```
CHUNK: pages 001-NNN | total NNN pages | source: 송영곤 사례연습 26 (채권편) | mode: full extraction
모드: B
[첨부] 1.민사/31.송영곤_사례/교재/_분할/송영곤_사례연습_채권_26_01.pdf
```
- 산출 → `outputs/01_ocr/사례연습26_채권_chunk_NNN.md` → 이후 Claude 06b.
- 정식해설본(`송영곤_사례연습_민법_정식해설본_15회변시_260406.pdf`)도 풀이 회수용으로 별도 OCR.

**(선택) 원문 보존 위키가 필요할 때만 02-wiki** — `book_type_hint: 사례집`:
```
source: 송영곤 [사례집명]
book_type_hint: 사례집
chunk_anchor: CHUNK: pages 001-030 | total NNN pages | source: [사례집명]
content_source: |
  [사례집 md/텍스트 붙여넣기]
```

## 3. 산출물 회수 → Claude 전달 규칙

1. 안티그래비티 출력(위키 md)을 그대로 복사 → `outputs/02_wiki/{책약칭}_chunk_NNN_wiki.md`로 저장(임의 수정 금지).
2. Claude Code에 명령:
   - `outputs/02_wiki/쟁점노트_재산법_chunk_001_wiki.md 02-card로 변환` (단권화 3종)
   - 사례집은 `inputs/cases/...` + `06a`/`06b` 명령.
3. 한 청크 = 한 위키 파일. 청크 간 카드 ID는 사용자 수동 누적 관리.

## 4. 안티그래비티 출력 검증 체크리스트

### 01 OCR 출력
- [ ] 첫 줄 `CHUNK: pages NNN-MMM` anchor + 다음 줄 `TOTAL_CHARS:`
- [ ] Mode B(전체 추출) 적용
- [ ] 모든 페이지 처리 또는 `{불명: page X}` 명시
- [ ] 인쇄 박스(파란 헤더·노란 조문·회색 [관련판례])를 마킹으로 오인 안 함
- [ ] 조문 원문 보존 또는 `[조문 원문 누락]` 표시
- [ ] 판례번호 문장 중간 인용까지 포착
- [ ] 페이지별 글자수 표, `{누락의심}` 사유 명시
- [ ] 한자 병기 없음 (#37)

### 02-wiki 출력
- [ ] frontmatter(source·book_type·book_type_confidence·attribute_distribution)
- [ ] `INTEGRITY: INPUT_CHARS=… | OUTPUT_BODY_CHARS=… | 보존율=NN%` (≥ 90%)
- [ ] 책유형 추정 신뢰도 ≥ 90% (낮으면 hint 명시 재시도)
- [ ] 모든 소목차 `<!-- 속성: X -->` 라벨
- [ ] callout 변환(`[논점정리]`→`> [!summary]`), 인라인 라벨 굵게, `[불명]`→`{불명}`
- [ ] `[[backlink]]` 보수적 부착(남발 X)
- [ ] 한국법학 가드 4축(변형결정·상소심·절차법·학설 enum) 보존
- [ ] scope 적용 시 범위밖 `<!-- 보류: 범위밖 -->` 주석
- [ ] `END_OF_CHUNK` 메시지

> 보존율 90% 미만 또는 신뢰도 60% 미만 → 재처리. 100장당 환각 3장 초과 → 중단·보고.

## 5. 진행 순서 (안티그래비티 측)

1. 앱에 `02-wiki_gemini3.1pro_...md` 등록 (가장 많이 씀).
2. **반반형법 또는 쟁점노트 1청크(30p) 시범** → 4장 02-wiki 체크리스트 통과 확인.
3. 통과 시 같은 책 나머지 청크 진행, 미달 시 hint·scope 조정 후 재시도.
4. 핵심정리헌법 + 사례연습26은 `01_gemini3.1pro_...md`로 OCR 먼저 (핵심정리 → 02-wiki, 사례연습26 → Claude 06b).
5. 위키 산출물을 `outputs/02_wiki/`에 모아 Claude Code에 02-card 명령.
