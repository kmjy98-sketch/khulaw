# 작업 계획서 — 안티그래비티 글자수 무결성 검증 (v1)

작성일: 2026-06-01 / 대상 파이프라인: claude_code_package_v2 (v3.6 Phase 2)

---

## 1. 배경

- 파이프라인: `[PDF] → 01 OCR → 02-wiki 위키화 → (Opus) 02-card·06 → Anki`
- `01 OCR`·`02-wiki`는 **안티그래비티(Gemini 3.5 Flash)** 가 담당한다.
- 문제: Gemini 계열은 **silent drop(예외 없이 본문 누락)** 전력이 있다(메모리 `feedback_gemini_explore_only.md`, transcript-split 파일럿 사례). 위키화 단계에서 본문을 임의로 요약·누락할 위험이 상존한다.
- 기존 프롬프트에 보존 규칙(`FIDELITY_CONTRACT`, "원문 그대로", `{불명}`)은 있으나 **정량 검증 장치가 없다.** 누락이 일어나도 자동으로 잡히지 않는다.

## 2. 목표

안티그래비티가 본문을 함부로 줄이거나 누락하지 못하도록, **글자수 자가계측·자가보고 + 임계 밴드 이탈 시 출력 중단**을 프롬프트 규칙으로 강제한다.

## 3. 핵심 모순 — 확인 필요 (중요)

| 출처 | 진술 | 함의 |
|---|---|---|
| SKILL.md / 02-wiki 헤더 | "원문 10:1 압축", "Gist 위키" | **압축(요약)** |
| 02-wiki ABSOLUTE RULES 2·4, TOP PRIORITY | "원문 그대로, 요약·재구성 금지" | **보존(무손실 변환)** |

두 진술이 충돌한다. 본 계획은 사용자 요청("함부로 못 바꾸게")과 ABSOLUTE RULES를 근거로 **보존(무손실 변환)** 으로 해석하고, `02-wiki` 본문 **보존율 ≥ 90%** 를 기준으로 삼는다.

- "10:1 압축"은 **책 전체 → 위키** 비율(01 OCR의 Mode 필터·선별 청크 포함)을 가리키는 것으로 보이며, `01-OCR → 02-wiki` **변환 자체는 보존**이 맞다고 판단함.
- → **확정(2026-06-01): (A) 보존 변환.** 보존율 ≥ 0.90 적용. 이에 따라 프롬프트·SKILL의 "10:1 압축/Gist" 문구를 "본문 보존 구조화"로 정정함.

## 4. 메커니즘 설계

원리: 모델이 글자수를 **세어서 출력에 명시**하게 하고, 기준 밴드를 벗어나면 **침묵 진행 대신 중단·플래그**한다. 자가보고 수치는 사후 외부 재계측으로 검증 가능하므로 허위·과압축을 억제한다.

| 단계 | 입력 | 기준 글자수 | 가드 |
|---|---|---|---|
| 01 OCR | PDF(페이지) | 입력 정답값 없음 | 페이지별 추출 글자수 표 + 본문 페이지 80자 미만 → `{누락의심}` + `TOTAL_CHARS` anchor |
| 02-wiki | 01 OCR md(텍스트) | `INPUT_CHARS` 계측 가능 | 보존율 = `OUTPUT_BODY_CHARS / INPUT_CHARS`, **≥ 0.90 강제**. 미달 → 출력 중단 + `{누락경고}`. 1.10 초과 → 본문 증식 의심 |
| 02-wiki (입력이 PDF) | PDF | 입력 정답값 없음 | 01 방식(페이지별 글자수)으로 폴백 |

- 글자수는 **공백 제외**, 마크업(`YAML` · `<!-- 속성 -->` · callout 라벨 · `[[backlink]]`)을 제외한 **본문만** 계측.
- 소목차별 `<!-- chars: NNN -->` 주석으로 누락 위치를 추적.

## 6. 검증의 한계와 향후 (Phase 2)

- **LLM은 글자수를 정확히 못 센다.** Flash가 보고하는 수치는 근사값이며, 모델이 임의로 `보존율 ~1.0`을 적어버릴 수도 있다. 따라서 프롬프트 자가보고만으로는 강제력이 약하다(soft enforcement).
- 현재(Phase 1)의 실효: (a) 모델의 보존 인식 강화로 과압축 경향 억제 (b) 사용자 육안 점검용 앵커 제공 (c) 향후 자동 검증의 훅.
- **Phase 2 (완료 2026-06-01)**: `scripts/integrity_check.py` — `outputs/` 파일에서 **한글 글자수 기반 보존율을 독립 재계측**하여 자가보고치·01 원본과 대조 → 누락(< 0.90)·자가보고 괴리 자동 검출(FAIL 시 exit 1). 이것이 실제 teeth(강제력)다.
  - 02-wiki: 입력(01 출력 md) vs 출력(wiki md) 본문 글자수 diff → 보존율 자동 산출.
  - 01: 페이지별 글자수 분포 이상치 탐지.
