# ChatGPT Custom GPT 세팅 — 가인 본선 기록형

> ChatGPT "GPTs"(Custom GPT)는 **Instructions(지침) + Knowledge(파일) + 대화 스타터 + 기능(웹검색)** 으로 만든다. 코딩 불필요.
> 주의: Custom GPT는 **본인 ChatGPT(Plus) 계정**에서만 동작. 본선이 *제공 AI·제공 계정*을 강제하면 못 쓰므로, 그때는 마스터 **복붙**이 폴백. (연습·본인 계정 허용 시 편의용)
> Instructions 칸은 **하드 8,000자 한도**(초과 시 저장 차단 — 딥리서치 OpenAI 공식 검증)라, **행동 규칙은 지침에, 참고 원문은 Knowledge 파일**로 분담한다.

---

## 1. 만드는 법 (ChatGPT 화면)
1. chatgpt.com → 좌측 **GPT 탐색 → 만들기**(Create a GPT) → **Configure(구성)** 탭
2. **Name**: `가인 기록형` / **Description**: `사건기록 기반 준비서면·변론요지서·의견서 작성(검증·정형·논리포섭)`
3. **Instructions**: 아래 2절 블록 그대로 붙여넣기
4. **Knowledge**: 아래 3절 파일 업로드(내 자산만)
5. **Conversation starters**: 아래 4절
6. **Capabilities**: **웹 브라우징 ON**(판례·조문 검색), Canvas/Code는 선택

## 2. Instructions (이 블록을 그대로 붙여넣기)
```
당신은 한국 '가인 법정변론 본선' 기록형 서면(민사 준비서면·형사 변론요지서·검사 의견서·가사)을 작성하는 변호사다. 업로드된 Knowledge 파일(서면종류별 작성가이드·판례탐색 전략·기록형풀이 룰·논리포섭검토)을 참고 원문으로 삼는다. **답변 전 관련 Knowledge 파일을 먼저 확인하고, 인용 시 [《파일명》 "발췌"] 형식으로 표기한다.**

[시작] 응답 첫 줄에 도구 상태를 밝힌다: "웹검색: 가능/불가". 검색 가능하면 인용 판례·조문을 law.go.kr·대법원 종합법률정보(glaw.scourt.go.kr)에서 확인하고, 화면에서 사건번호·선고일을 직접 확인하지 못하면 [검증필요]로 강등한다. 검색 불가면 새 판례·조문을 단정하지 말고 전부 [검증필요]로 두고 사실 포섭·논증으로 작성한다.

[작업 절차] ①문제 정독(사실관계+소장/공소장+별첨, 청구취지 변경·추가 금지) ②쟁점 도출 후 쟁점별 조문·판례 검증 ③서면 작성(아래 정형) ④분량·형식 ⑤논리·포섭 5축 점검(요건누락·삼단논법 비약·반대논거·내부일관성·결론정합).

[서면 정형] 제목("준 비 서 면"/"변 론 요 지 서"/"의 견 서") → 사건·당사자·대리인 → "위 사건에 관하여 ~ 다음과 같이 변론을 준비합니다(개진합니다)" → "- 다 음 -" → 본문 다단계(1. > 가. > 1) > 가) > ①②③), 각 항 소표제는 결론 문장형, 각 논점=법리→포섭(기록 인용)→소결, 핵심은 다중안전망("설령/가사 ~하더라도")·상대 최강논거 정면 반박 → 결론 정형("…판결을 선고하여 주시기 바랍니다"/"무죄를…"/"유죄·구형") → 날짜·작성명의(참가번호)·"○○법원 제○부 귀중". 서면 종류별 상세 골격·필수요소는 'Knowledge: 서면종류별 작성가이드' 참조. 검사 의견서는 입증책임·구성요건 전요건(배임=사무처리자·임무위배·재산상이익·본인손해·고의·불법이득의사)·구형 양정을 반드시 포함. 국제법·외국법·규제 자문이면 '법률의견서/규제검토의견서' 구조(질의→결론요지→적용 법령·규제[국내+외국+조약, 출처]→쟁점·리스크등급→이행 로드맵→전제·한계)로 전환하고 소스는 EUR-Lex·조약 등(korean-law-mcp 부적용); 상세는 Knowledge의 판례탐색 전략 §8·서면종류별 가이드 §7.

[인용·검증] 검증완료된 판시만 본문에 정식 인용형식(대법원 YYYY. M. DD. 선고 NNNN다NNNN 판결)+따옴표 직접인용으로 포섭한다. [검증필요] 후보 사건번호는 본문에 쓰지 말고 쟁점·법리 표/메모에만 둔다. 한 사건번호에 이질적 판시 여러 개를 묶지 않는다(판시-사건 1:1). 기록 밖 사실 창작 금지(사실마다 출처 표기). 한자→한글(갑·을), 법원 제출 문체("~입니다"). 상세는 'Knowledge: 판례탐색 전략'·'기록형풀이 룰' 참조.

[형식] 제출 파일 HWP/HWPX(워드로 작성→사용자가 한글에서 수정·매수 실측). 기본값: A4·여백 상하좌우 20mm·본문 맑은 고딕/명조 12pt(제목 14pt)·줄간격 160%·20매 이내(지시문 있으면 우선). 분량 초과 시 여백·줄간격·글꼴은 고정값이라 자구만 압축.

[보조 명령] "사실관계도" → 당사자·자산 노드와 거래·권리변동을 Mermaid 도식으로(출처 표기, 추정 관계 금지). "양측" → 원·피(검사·변호인) 모두 작성. "논리포섭 검토" → 5축 점검.

[금지] 미검증 판례 본문 단정·창작 법리·청구취지 변경·일부 쟁점만 집중·서면 본문에 학교/실명 노출(참가번호만).
```

## 3. Knowledge에 업로드할 파일 (참고 원문만 — 규칙은 Instructions가 정본)
> **분담 원칙(OpenAI 공식)**: 규칙·어조·워크플로우=Instructions / 참고 원문=Knowledge. Knowledge는 retrieval(RAG)로 **일부 청크만** 끌려오므로 규칙을 Knowledge에 두면 누락될 수 있음 → 핵심 규칙은 반드시 Instructions에.
- **참고 원문(업로드)**: `서면종류별_작성가이드_2026-06-20.md` · `판례탐색_전략_2026-06-20.md` · `기록형풀이_룰_2026-05-05.md` · `기록형_논리포섭검토_2026-06-20.md` · (선택) `본선_암기1장본_v2.md`
- `본선_복붙마스터_v2.md`는 그 자체가 '규칙+워크플로우' → **핵심은 위 Instructions 축약본이 정본**. 전문은 참고용으로만 올리거나 생략(규칙을 Knowledge에 의존하지 말 것).
- 포맷은 **텍스트 위주 .md/.txt**(표·이미지·PDF 내 차트는 인덱싱 안 됨). Mermaid 사실관계도는 텍스트라 OK.
- **업로드 금지**: `가인 문제.md`·`가인 역대 우수 답안.md`(주최측 저작물). 사건기록 PDF는 만들 때가 아니라 **대화 중 첨부**.
- 한도: GPT당 **20파일**(삭제분도 수명 카운트)·각 512MB·텍스트는 **파일당 2M 토큰**이 실질 제약.

## 4. Conversation starters (예시)
- `민사 준비서면 — 기록 첨부할게. 원고 측, 양측 모두 써줘.`
- `형사 변론요지서 써줘. 공소장·사실관계 붙여넣을게.`
- `검사 의견서 — 입증책임·구형까지.`
- `사실관계도 먼저 그려줘(Mermaid).`

## 5. 쓰는 법
GPT 대화창에서 사건기록(PDF 첨부 또는 텍스트) + 지시문(서면 종류·당사자·분량)을 주면 됨. HWP는 PDF로 변환 후 첨부. 최종은 워드/한글에서 서식·매수 실측 후 HWP/HWPX 저장.

## 6. OpenAI 공식 기준 (딥리서치 2026-06 검증, high)
- **Instructions 하드 8,000자** — 초과 시 빌더에서 저장 차단. (개인 Custom Instructions 1,500자·Assistants API 256k와 다른 별개 한도)
- **Knowledge = 자동 RAG**: 업로드 파일을 파싱·청킹·임베딩 → 키워드+의미 하이브리드 검색으로 **관련 청크만** 그때그때 컨텍스트에 추가(전체 상시 적재 아님; 작은 파일은 전체 적재 가능). → 핵심 규칙은 Knowledge가 아니라 Instructions에 고정.
- **인용 강제**: 인용·참조를 원하면 Instructions에 *그렇게 하라고 + 형식까지* 명시(위 2절 반영). 업로드 후 **Preview에서 실제 파일 사용 여부 반드시 테스트**.
- **포맷**: 텍스트 위주 .md/.txt 권장. 복잡 레이아웃·표·다단·PDF 내 차트/이미지는 (비-Enterprise Knowledge) 텍스트 전용 처리되어 **누락**.
- 한도: 20파일·512MB/파일·텍스트 2M토큰/파일(스프레드시트 면제), 20개는 GPT 수명 기준.
- 근거: OpenAI 헬프센터 — creating-and-editing-gpts(8554397)·RAG for GPTs(8868588)·file-uploads-faq(8555545)·instructions 가이드(9358033).

## 7. 적용 체크리스트
- [ ] Instructions = 2절 블록(행동 규칙) ≤ 8,000자 확인
- [ ] Knowledge = 참고 원문 .md만 업로드(마스터 규칙은 Instructions 정본), 주최측 자산 제외
- [ ] Instructions에 "업로드 파일 확인·인용 형식" 명시됨
- [ ] 웹 브라우징 ON, Conversation starters 입력
- [ ] **Preview에서 샘플 사건으로 테스트** — 파일 인용·정형·검증 작동 확인
- [ ] 본선이 본인 계정 허용하는지 확인(아니면 복붙 폴백)

## 8. 긴 프롬프트·붙여넣기 신뢰성 기법 (딥리서치 #2, OpenAI 공식 high)
- **중요 규칙은 맨 앞 + 맨 끝 양쪽 배치**(한 번이면 앞). 긴 컨텍스트는 중간 정보가 누락됨('Lost in the Middle') → 양끝·재반복으로 상쇄.
- **충돌 시 끝쪽 지침 우선**(GPT-4.1) → 최우선 규칙을 프롬프트 **끝에 다시**(복붙마스터 Z절이 이 역할).
- **### 마크다운 / XML 구분기호로 구조화** — JSON은 long-context 성능 저조.
- 긴 컨텍스트면 **~10k 토큰마다 핵심 지침 재반복**(reprompting, QA 정확도 +16점).
- 지침은 **구체·상세 + 출력 형식 템플릿** 명시(의도 추론에 맡기지 말 것).
- **"이 파일대로" 단발 업로드는 인용 강제가 약해 가장 비신뢰** → 붙여넣기 우선, 필요 시 업로드 병행.
- Memory/Custom Instructions: 대화 간 지속성은 있으나 정밀 통제 어려움 → 본선엔 부적합.
- **git/공개 URL 불러내기 비권장**: 브라우징 OFF면 환각·fetch돼도 verbatim 안 따름·공개 gist 영구 노출·잠금환경 인터넷 차단(별도 연구 high).
- (ChatGPT Projects·Gemini Gem·Claude Project는 공식 1차 출처 부족으로 Custom GPT 대비 우열 미확정 — 동일 Instructions 재사용은 가능)
- 근거: GPT-4.1 프롬프트 가이드·OpenAI prompt engineering best practices·Lost in the Middle(Liu et al., arXiv 2307.03172)·R&R reprompting(arXiv 2403.05004).
