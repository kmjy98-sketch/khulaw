## §3. Gemini 위임 권고 영역 (Top 1·확장 후보 1)

채택 영역이 적은 이유: 파일럿 silent-drop 사례 + 룰 #1·#13·#15와의 마찰이 큼. 신중하게 1+1건만 권고.

### 위임-1 (정식 채택 중) — 의미불명 파일명 1차 콘텐츠 분류
- **현 상태**: 정식 채택, 운영 중
- **근거**: 《classification-rules_v2.md》 핵심원칙 15 — "신뢰도 ≥0.85면 자동 라우팅, 미만이면 `_inbox/` 격리"
- **위험**: silent drop 가능성. 완화책으로 **0.85 미만 자동 격리**가 이미 작동 중.
- **모니터링**: `_inbox/` 누적량과 오분류율을 주 1회 점검 (현재 자동 점검 스크립트 미확인—추가 검토 필요).

### 위임-2 (신규 후보) — 공개 1차 자료 1차 수집·요약
- **대상**: KCI 논문, 법조신문/리걸타임즈 칼럼, 국가법령정보센터 부속 자료, 헌재·대법원 보도자료
- **장점**: Google 검색 통합 + 1M 토큰 컨텍스트로 다수 PDF 1회 처리. Claude가 같은 작업 시 web_fetch 다중 호출.
- **위험 1**: 인용 위조 (Gemini가 존재하지 않는 판례·조문을 조작). 룰 #2·#6 위반 가능성.
- **위험 2**: 사용자 개인 자료를 함께 입력하면 외부 송출. **공개 자료만 입력** 원칙 필수.
- **완화책**:
  1. Gemini는 **수집·요약·발췌 후보 추출**까지만. 인용·확언은 Claude가 korean-law-mcp로 재검증.
  2. 입력 데이터 필터링: 자소서·발제 본문은 절대 첨부 금지.
  3. 출력 후 Claude의 reverse-RAG(#13)로 단정 검증.

## §4. 병행 권고 영역 (Top 2)

### 병행-1 — 발제·정리노트의 1차 자료 보강
- **분담**: Claude = 9대 원리 적용·각주 작성·룰 #34 판례 표현 검증 / Gemini = 동일 쟁점 관련 KCI 논문·판례평석 1차 수집
- **핸드오프**: Gemini 출력 → `_gemini_review/{topic}/raw.md`에 dump → Claude가 read 후 인용 검증
- **운영 모델**:
  - 사용자가 `/병행 {쟁점}` 명령 시 (현재 미구현) Claude가 Gemini 호출 프롬프트를 생성
  - Claude는 Gemini 결과를 **참고 후보**로만 취급, 확정 인용 시 원문 확인
- **위험**: Gemini 결과를 검증 없이 수용 시 룰 #1 위반 → 검증 단계 누락 방지 체크리스트 필수

### 병행-2 — 강의 전사문 의미 단위 분할 후보 탐색 (구조화 워크플로우)
- **근거**: 《REPORT.md》 §5 "의미 단위 분할(목차 변경 지점, 화제 전환점 등 *semantic boundary*)이 필요한 경우 Gemini Flash가 유리할 수 있음"
- **분담**: Claude = 메타헤더·anchor 보존 + 결정론적 N등분 / Gemini = 화제 전환점 후보 markup만 (본문은 건드리지 않음)
- **운영 모델**: Gemini는 `[BREAK]` 마커만 출력하는 read-only 모드. Claude가 마커 위치를 읽어 split 결정.
- **위험**: 동일 silent-drop 위험. **본문 echo 금지 + 마커 출력만** 프롬프트 강제.
- **상태**: 미구현. 도입 전 별도 파일럿 필요.

### 병행 후보로 검토했으나 **부적합** 결론
- **자소서 윤문 — 영문 표현 점검**: 자소서가 한국어 한정이고, 외부 송출 위험이 보상보다 큼. **부적합**.
- **Colab 에러 로그 분석**: Claude가 이미 충분히 처리. Gemini 추가 시 핸드오프 비용이 더 큼. **부적합**.

## §6. 즉시 시작 가능한 파일럿 (1개)

### 파일럿 제안: "Gemini 1차 자료 수집 → Claude 검증" (위임-2 검증)

- **목표**: §3 위임-2 후보의 실제 ROI 측정
- **대상 쟁점**: 직전 발제·정리노트에서 다룬 1개 쟁점 1건 (예: [[등기청구권]] 또는 [[선의취득]] 등 wiki 보유 쟁점)
- **절차**:
  1. Claude가 쟁점 명세서 작성 (`_gemini_review/topic-search-pilot/spec.md`) — 검색 키워드·기간·출처 화이트리스트(KCI·로앤비·국가법령정보센터·헌재·대법원)
  2. Gemini CLI로 spec.md를 입력해 1차 자료 수집 → `raw.md` 출력
  3. Claude가 raw.md의 단정·인용을 reverse-RAG(#13)로 검증
     - korean-law-mcp로 사건번호·조문 검증
     - 출처 URL 실재성 확인 (web_fetch)
     - 룰 #1 위반 단정 표시 후 삭제
  4. 산출: `_gemini_review/topic-search-pilot/REPORT.md` (Claude 단독 시 vs 병행 시 시간/정확도/비용 비교)
- **성공 기준**:
  - 인용 위조율 ≤ 5%
  - Claude 단독 대비 시간 단축 ≥ 30%
  - 사용자 개인 자료 외부 송출 0건
- **실패 기준 (즉시 중단)**:
  - 인용 위조율 > 5%
  - 사용자 개인 자료가 Gemini 입력에 포함된 흔적 1건 이상
- **소요 추정**: 1쟁점 당 30~45분 (spec 10분 + Gemini 호출 5분 + Claude 검증 20분)
