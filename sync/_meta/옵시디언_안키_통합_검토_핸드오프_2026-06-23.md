## 1. 타당성 조사 (방법론 자체)

- **능동 인출·분산 반복**은 확립된 학습과학(Roediger & Karpicke 2006: 지연시험 61% vs 40%). **FSRS**는 약 1만 사용자·7.27억 리뷰 학습으로 SM-2보다 회상 예측 정확(공식 벤치마크). "리뷰 20~30% 절감"류 수치는 **블로그성·미검증** — 방향성만.
- **원자화의 전제**: SuperMemo Wozniak도 "이해 못 하면 외우지 마라, 전체 그림 먼저"로 **맥락 선행**을 요구. 무비판적 원자화는 법학 사례형(요소 상호작용 높은 자료)에 위험.
- **법학 시험의 본질**: 점수의 대부분이 룰의 **"적용(application)"**에서 나옴(Themis, CEB). 단순 암송 카드로는 부족 → 사실관계 변형 드릴·기출이 위상 높음.
- 결론: **골격은 타당하나 효과 인과성은 약하게 입증, 법학 사례형엔 조건부.** 현 볼트 설계가 이미 이 조건을 반영.

## 2. 카드화 vs "문제화" — 세 개의 다른 행위

| 행위 | 정체 | 판정 |
|---|---|---|
| 노트 통째 빈칸화로 복습 | in-note cloze 통암기 | ❌ 퇴보 — 인접 텍스트가 단서(가짜 회상 / pattern completion), 채점 해상도 붕괴. 옵시디언 SR 플러그인 공식 문서도 "순수 사실은 잘게 쪼개라"고 명시 |
| **원문 옵시디언에 클로즈 직접 표기** | in-note cloze 단일소스 | △ 별개 옵션 — 맥락 보존엔 좋으나 현 `02-card`의 구조화 노트타입(요건/효과/예외 필드·overlapping·누설차단)을 **평면 클로즈로 다운그레이드**. 단 AnkiConnect ID 매핑과는 천생연분 |
| 노트→**쟁점 생성·기출형 문제**로 변환 | 능동 드릴(generation effect) | ✅ 옳음, **사례형 한정** — 생성효과 + 적용 훈련. 단 atomic 암기(조문·요건·판례)는 카드로 유지 |

**법학 특수성**: 사례형 IRAC는 "맥락이 곧 지식". 현 `case_problem_card`(06a/06b)는 [사안+설문]을 통째 보존 + 키워드만 회상 + IRAC 자동생성 금지 → **이미 과도한 원자화를 통제**. 설계 변경 불요.

## 4. apkg / GUID — 핵심 발견과 파일럿

- **apkg 루트가 본선**: `build_v37_apkg.py`가 genanki로 과목별 .apkg 생성. genanki guid로 재임포트 시 **중복 없이 업데이트 + 복습이력(due/interval/FSRS) 보존**(genanki README·Anki 매뉴얼 확인). TSV(`md2anki.py`, guid 없음)는 구버전, AnkiConnect 신규 도입 불요.
- **결함**: 현 코드 guid = `genanki.guid_for(src, blk[:30], 정규화본문)` = **내용 해시**. 카드 한 글자 수정 → guid 변경 → 새 카드 생성·기존 고아화(회독 유실). genanki README도 "정체성 필드만 해시하라"고 권고.
- **코드-문서 불일치(⚠️ 확인 필요)**: `card-wiki-pipeline §8.1`·`anki-card-generation §171`은 빌더가 이미 `{stem}::{basic|cloze}::{seq:04d}` 안정 guid로 "2026-06-16 전환·검증 완료"라 기술. **repo 코드는 미반영.** → 실사용본(로컬 H:\)이 이미 패치됐는지 확인 필요. 미반영이면 PR #1 적용, 이미 반영이면 repo 동기화.
- **PR #1 파일럿**(통과): `.agent/scripts/_guid_stable.py`(§8.1 포맷 `note_key`/`guid_seed`/`extract_uid`) + `_test_guid_stable.py`(7 tests). `build_v37_apkg.py`는 #17·#45 따라 미수정.
- **태그 주의**: native TSV 임포트는 태그를 **교체(replace)** → 안키 수기 태그(오답/검증/보류) 유실. apkg 재임포트 태그 동작은 매뉴얼 불명확 → 1노트 파일럿 확인. (apkg+genanki 경로 권장 이유 중 하나)
- **마이그레이션**: 현재 복습이력 없음(사용자 확인) → v37 apkg 신규 임포트, 마이그레이션 0.

## 5. 사례형 "문제화 드릴" 트랙 (조사 결과)

**그린필드 아님 — 골격이 이미 있음:**

**갭(미구현):**
1. 루브릭·약점연동·SRS review_type 매핑이 **"스펙 문서화 단계"로 코드 미반영**(`render_case_answer_review.py`는 coverage 기반 초벌, `srs_scheduler.py`는 초기 interval=1 고정). 출처: `codex이관_claude환원_검토_2026-06-16.md §5`.

**권고 설계**: 안키=atomic 암기, **옵시디언/스크립트=사례형 문제화 드릴**(사실관계 → 쟁점·목차 생성, incremental review). 반복 오답만 카드로 승격(card-wiki-pipeline §8 note_key 준수). 통째 빈칸화·라이브 양방향 플러그인은 채택 안 함.
