## §3 단일 진실 원천 (SSoT) + 갱신 흐름

### 3.1 권위 우선순위

CLAUDE.md #1·#5·#25 결합 적용 시:

| 순위 | 영역 | 사유 |
|:-:|---|---|
| **1차** | **L1 교재 원문** (단, 사용자 보유 정본 PDF) | #1 Source Grounding. 정리노트·위키는 L1을 대체할 수 없음. |
| **1차 보조** | korean-law-mcp 조문·판례 원문 | OCR·인용 검증용 (CLAUDE.md #13). 조문번호·사건번호 ground truth. |
| **2차** | L2 정리노트 | 학습 진입점. 사용자 학습 본체. |
| **3차 (참고)** | L3 wiki 메모리 | 세션 로그. "사실"이 아닌 "참고" (#40). |
| **보조** | L4 색인 (신설) | 자동 생성. L1·L2에서 추출. |

> **결론**: SSoT는 **L1 교재 원문 + korean-law-mcp**. L2 정리노트는 정리·인용본이며 L1을 인용·발췌해야 한다. L3 wiki는 메모리 레이어로 권위가 아니다.

### 3.2 갱신 흐름 (정상 방향)

```
①  교재 PDF 갱신 (사용자)
        │
        ▼
②  L1 교재 노트 OCR 추출/교정 (Colab + Claude 파이프라인)
        │
        ▼
③  L1 yaml 표준화 (송영곤_B형 등)
        │
        ▼ 영향 평가 (yaml hash diff)
④  L2 정리노트 yaml `주요출처` + 본문 인용 갱신
        │
        ▼ 영향 평가
⑤  L4 색인 자동 재생성 (조문·판례·빈출)
        │
        ▼ (세션 종료 시)
⑥  L3 wiki `세션로그` 누적 (#39)
```

### 3.3 충돌 시 우선순위

| 충돌 시나리오 | 처리 |
|---|---|
| L2 인용 ≠ L1 원문 | **L1 우선**. L2 수정. (#1·#13) |
| L1 OCR ≠ korean-law-mcp 원문 | **mcp 우선**. L1 교정 큐 등록. (#13 OCR 파이프라인) |
| L3 wiki 기록 ≠ L1 교재 | **L1 우선**. wiki는 참고만. (#40) |
| L2 ≠ L2 (같은 쟁점 다른 노드) | 사용자 결정 (1쟁점=1노드 원칙). 통합 또는 분기 명시. |
| L2 백링크 형식 ≠ L1 | 표준 형식으로 양쪽 동기화 (§4.2). |

## §4 백링크 매트릭스 + 표준

### 4.1 백링크 흐름 (현재 상태)

| 출발 → 도착 | 형식 (현재) | 활성도 |
|---|---|:-:|
| L2 → L1 | `주요출처:` yaml + 본문 표 안 `[[저자_교재명_청크ID]]` | ★★★ (시범5·추가18 적용) |
| L2 → L2 (인접 쟁점) | `> 관련: [[다른노트]]` 또는 본문 [[..]] | ★★ |
| L2 → 판례 | `[[대판 YYYY.M.DD, YYda...]]` (yaml `관련판례` + 본문) | ★★★ |
| L2 → 조문 | `[[§XXX]]` (yaml `관련조문` + 본문) | ★★★ |
| L1 → L1 | 본문 [[다른청크]] | ★★ |
| L1 → 판례 | `[[YYda...]]` (단축형) | ★★ |
| L1 → 조문 | `[[§XXX]]` 또는 `[[**제XXX조**]]` (혼재) | ★ |
| L3 → L2 | `[[과목/단원/노드]]` (`_index.md`에서) | ★★ (인덱스 한정) |
| L3 → L1 | 거의 없음 | — |
| **L1·L2 → L3** | **거의 없음** (메모리는 단방향 누적) | — |

### 4.2 표준 형식 제안
