### 2.2 front matter 깨짐 양상 (5/5 모두 발생)

A형 비표준 형태:
```
--- tags: [교재원문, 민법, 송영곤_논점민법_본책, ...]
교재: 송영곤 《논점민법강의 본책》 판: 12 과목: 민법 원본_chunk: ... 페이지: ... 포함_페이지: [...]
서브책자: ... 쟁점: [...]
---
```

**문제점**:
- yaml 파서로 파싱 불가 (한 줄에 여러 키-값 압축, 따옴표 누락)
- 샘플 3 (매매계약): tags 배열 안에 `교재: 송영곤 《논점민법강의 본책》`이 토큰으로 잘못 들어감 — **가장 심각** (yaml 구조 자체 깨짐)
- 모든 파일에 `정리일`, `정리_버전` 필드 부재

**적용 가능성**: front matter 표준화는 **5개 모두 안전**. 패턴이 명확하고 본문과 분리되어 있어 위험 낮음. 단, 파일별 메타 값 (페이지 범위·쟁점) 보존 필수.

### 2.3 본문 OCR 노이즈 — §6 자동 batch 적용 가능 패턴

| 패턴 | 5개 샘플 출현 (추정) | 안전도 | 비고 |
|---|---|---|---|
| `(\d+다\d+)\[\^\d+\]` (사건번호 끝 각주 마커) | 0~2건/파일 | **안전** | 직접 매칭, 의미 변경 없음 |
| 페이지 헤더 `^제\d+관 .+\s+\d+\s*$` 단독 라인 | 1~3건/파일 | **불완전** | callout 안 등장하면 매칭 실패 (`> 제2관 [[신의칙]] 5`) — § 추가 정규식 필요 |
| 페이지 헤더 `^\d{2,3}\s+제[O@©0]?부.+$` 단독 라인 | 1~5건/파일 (본문 多) | **안전** | 명확한 패턴 |
| 페이지 헤더 `^제\d+장.+\s+\d+\s*$` 단독 라인 | 0~2건/파일 | **안전** | 명확한 패턴 |
| 페이지 번호 단독 (`^- \d+ -$`) | 0건 | — | 본 파일군은 다른 형식 |
| 페이지 번호 단독 (`^\s*\d{1,3}\s*$`) | 0~1건/파일 | **불완전** | 본문 안 단독 숫자(예: 표 셀)와 혼동 위험 — 보류 |

**핵심 결론**: B형 표준 §6 자동 batch 적용 가능 패턴 중 5개 샘플에 실제 매칭되는 것은:
1. 사건번호 끝 각주 마커 — 적은 양이지만 안전
2. 페이지 헤더 본문 단독 라인 (제N부 포함) — 안전
3. front matter 표준화 — 안전

**그 외 위험 요소**:
- callout 안 페이지 헤더 (`> 제N관 ... 숫자`) → 정규식 추가 필요, 위험도 중
- callout 안 헤더 깨짐 (`> 1 .의 의`) → 의미 변경 위험, **자동화 부적합** (#1 위반 위험)
- 한자 깨짐 (`仲판`, `傑里`, `祭主`, `紀적`, `美貨` 등) → CLAUDE.md #34 anchor 보호, **자동 교정 금지**
- OCR 마커 깨짐 (`IW日!`, `I@E1`, `I갓=1`, `t과=1`, `■`, `丰`, `仲판`) → 의미 추정 위험, **자동화 부적합**
- 줄바꿈 깨짐 (`민` 한 글자가 다음 줄로) → 의미 판단 필요, **자동화 부적합**
