# 운영기준 — 룰(CLAUDE.md) vs 지식(wiki·메모리) 분리

작성: 2026-06-15 / 계기: claude-md-management 플러그인 설치 후 기존 메모리 체계와의 중복 정리

---

## 원칙 한 줄

**"Claude가 어떻게 행동할지" = 룰(CLAUDE.md) / "법이 어떤지" = 지식(wiki·memory).**
법학 내용을 CLAUDE.md에 부가 룰로 넣지 않는다. 분산이 더 효율적이다.

## 이유 — 로딩 비용

| 파일 | 로딩 시점 | 함의 |
|------|----------|------|
| CLAUDE.md, MEMORY.md | 매 세션·매 턴 상주 | 내용 늘수록 전 대화가 비싸지고 룰이 희석됨 |
| sync/wiki/ | `_index.md`만 보고 관련 아티클만 온디맨드 (#38) | 필요할 때만 토큰 소모 |
| .auto-memory/session_logs/ | 종료 시 기록 → compile 압축 (#39·#41) | 상시 로딩 아님 |

법학 지식은 계속 늘어나는 내용 → 상시 로딩 파일에 넣으면 역효율.

## 무엇을 어디에

| 내용 유형 | 저장 위치 | 근거 |
|----------|----------|------|
| 행동 규칙 (파일 안전·인용 형식·출력 스타일, "항상 적용") | CLAUDE.md | 적고 안정적, 상시 적용 |
| 법학 지식·쟁점 (요건·판례문구·학설) | sync/wiki/ | 양 많고 "참고"용, 온디맨드 (#38·#40) |
| 세션 작업 결과·발견 | .auto-memory/session_logs/ → compile | #39·#41 |
| 사용자·프로젝트 사실 (교수님 소스 지시 등) | MEMORY.md (한 줄 색인) | 교차 세션 참조, 단 최소화 |

## claude-md-management 플러그인 사용 범위

- 충돌 조사 결과: 훅·MCP·에이전트 추가 없음, 이름 충돌 없음 → 기술적 충돌 없음. 기능적 중복(메모리 관리)만 주의.
- `claude-md-improver` → CLAUDE.md **행동 룰 품질 점검용으로만**. "내용 추가"·"간결화(룰 축약)" 제안은 법학 워크스페이스엔 부적합 → 무시.
- `/revise-claude-md` → **진짜 새 행동 규칙**이 생겼을 때만. 법학 학습 내용은 여기로 보내지 않고 wiki/세션로그로.
- 마켓플레이스 `autoUpdate=true` (공식). 버전 고정 원하면 settings.json에서 false.
