# 위키 LLM화 작업 검토 + 계획

## §0 작업 정의

**위키 LLM화** = 사용자의 17개 항목 마스터 플랜(《수정 및 진행》)을 구체화하여, 교재원문·정리노트를 **LLM(Claude·Gemini)이 검색·인용 가능한 위키 구조**로 재구성.

> 사용자 명시 목표 [《수정 및 진행》 #14·#15·#16]:
> - "문서 구조는 현재 정노트 내지는 나무위키에 가깝게 만드는 게 목표"
> - "사실상 온라인 주석 만들기"
> - "책원문 살려도 최대한 주제 단위"

| 위치 | 성격 | 노드 수 | 상태 |
|---|---|---:|---|
| `sync/wiki/` | Karpathy 메모리 (#38~#41) — 세션 로그 누적 | 8 | 거의 비어있음. "최근 세션 기록"만 존재 |
| `sync/<과목>/` | 쟁점별 정리노트 — 사용자 학습 본체 | ~147 | 사실상 위키. 본문·청구항변·근거·백링크 일부 적용 |
| `sync/_교재원문/` | 교재 원문 (저자별 폴더) | ~400+ | 정규화 진행 중. 별도 6순위 통합계획으로 처리 중 |

### 1.3 핵심 진단

1. **위키의 실체는 `sync/<과목>/`에 이미 존재** — 별도 wiki 폴더보다 기존 정리노트가 사실상 위키 노드 역할.
2. **`sync/wiki/`는 Karpathy 메모리 시스템**(#38) — 세션 간 누적 로그용. 17개 항목의 "정노트/나무위키"와는 **다른 레이어**.
3. **17개 항목 = D 위키 구조화 + A 교재원문 정규화 결합** — 두 작업이 분리되어 있어 통합 필요.
4. **빈출 Top 12 쟁점 중 절반 이상 노드 이미 존재** — 신규 작성보다 **기존 노드 강화**가 효율적.

## §2 위키 LLM화 구조 설계

### 2.1 두 레이어 분리 유지

| 레이어 | 폴더 | 역할 | 변경 방향 |
|---|---|---|---|
| **L1: 교재원문** | `sync/_교재원문/<과목>/<저자>/` | 1차 출처. 청크 단위. yaml 메타데이터. | 별도 6순위 통합계획 + OCR 교정 파이프라인 |
| **L2: 정리노트(=위키 노드)** | `sync/<과목>/<단원>/<쟁점>.md` | 2차 정리. 1쟁점=1파일. 백링크. | **본 계획 주 작업 영역** |
| **L3: 메모리** | `sync/wiki/` | Karpathy 세션 로그 누적 | 기존 #38~#41 정책 유지 |
| **L4: 색인** | `sync/_index/` (신설) | 조문·판례·태그 자동 색인 | **본 계획 신설** |

> 결론: **L2 강화 + L4 신설**이 위키 LLM화의 핵심. L1·L3은 기존 정책 유지.

|---|---|---|
| yaml 표준화 batch | Python (file tool only 환경에서 사용자 실행) | 단계 2~4 |
| 백링크 [[..]] 일괄 삽입 | 정규식 batch | 이미 1,897개 적용 완료 (#16 보완 시) |
| 조문 색인 추출 | Python yaml 파서 | 단계 3 |
| 판례 색인 추출 | 정규식 (`\d+다\d+`, `\d+도\d+`, `헌재\s*\d{4}\.`) | 단계 3 |
| OCR 교정 (Haiku+Sonnet) | 기존 파이프라인 | L1 교재원문 (별도) |
| LLM 본문 검토 | Claude/Gemini 직접 | 단계 1 시범 후 |

> CLAUDE.md #1·#16: 자동화도 본문 의미 변경 금지. 백업 → 적용 → 검증 3단계 강제.
